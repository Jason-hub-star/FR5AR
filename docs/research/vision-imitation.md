# 모방학습 — 시연을 보고 재현하기 (Vision 폴더 구체화의 근거)

분류: **조사**. SSOT 가 아니다. 여기 값을 근거로 코드를 바꾸지 않는다 — `docs/ref/` 로
승격된 뒤에 짠다. 2026-08-03 팀 회의 요구("뎁스카메라를 그리퍼에 달고 사람 작업을 관찰해
로봇이 그대로 실행")를 받아 조사했다. **`Vision/` 폴더를 구체화할 때 이 문서를 먼저 읽는다.**

## 0. 범위 (D47 — 이건 조사가 아니라 결정이다)

> **시연 수집 → 정책 학습 → 정책으로 작업 수행까지가 범위다.**
> 학습은 데모의 **목적 그 자체**이자 작업을 하는 **수단**이다 (2026-08-03 확인).
> 배운 적 없는 작업을 로봇이 **스스로 계획**하는 것은 여전히 범위 밖이다 (PRD).

D45 는 이보다 좁게("시연 1건 → 궤적 1건 재생") 그었다가 D47 에서 넓혔다. 넓어지면서
**기술 관문이 하나 열렸다 — `MoveJ` 로는 정책을 실행할 수 없다** (아래 §3.5).

## 1. 접근법 넷

| 접근 | 방식 | 장비 | 시연량 | 우리 적합성 |
|---|---|---|---|---|
| **직접교시** (Kinesthetic Teaching) | 사람이 로봇 팔을 **직접 잡고 끌어** 보여준다. 관절값은 엔코더가 읽는다 | **추가 장비 0** — 벤더링 SDK에 이미 있다 | 20~50회 | **1순위 후보** — 새 하드웨어 없이 아래 텔레오퍼레이션 블로커를 지운다. **단 실기 미검증** (§6) |
| **텔레오퍼레이션** | 사람이 로봇을 조종하며 녹화 | 기존 브리지 + 게임패드 | 30~300회 | 2순위 — 코드엔 바로 붙지만 **입력 장치가 없다**. 나사 체결 같은 정밀 작업은 조이스틱으로 시연 품질이 안 나온다 |
| **UMI 류 핸드헬드** | 그리퍼 모양 도구를 사람이 들고 시연, 손목 카메라가 관찰 | 3D 프린트 핸드헬드 + 카메라 | 20~100회 | 데이터 품질 최상. 하드웨어 제작이 선행 |
| **사람 손 영상 → 리타게팅** | 맨손 작업을 추적해 로봇 자세로 변환 | 카메라만 | 50~500회 | 장비는 제일 싸지만 손↔평행 그리퍼 변환 오차가 핵심 위험 |

회의에서 나온 "사용자가 작업하는 모습을 관찰" 은 문면상 넷째지만, **손가락 2개 평행
그리퍼(PGE A-100-40)와 사람 손은 자유도가 달라** 리타게팅이 곧 연구 주제가 된다.

**첫째가 왜 1순위 후보인가** — 벤더링 SDK에 `DragTeachSwitch(state)`(`Robot.py:943`)와
`IsInDragTeach()`(`:965`)가 실재하고, 후자는 실기에서 이미 값을 읽었다
(`evidence/2026-07-31/fr5-first-motion.md` — `dragTeach: 0`). 관절값은 20004 상태 스트림에
33ms로 이미 흐르므로 **녹화만 붙이면 된다.** 엔코더가 곧 정답이라 정밀도도 조이스틱보다 낫다.

**대신 안전 자세가 뒤집힌다.** 지금 게이트는 "나가는 명령"을 검사하는데, 직접교시는 나가는
모션 명령이 0이고 **사람이 작업영역 안에서 로봇을 만지고 있다.** 위험은 "그 사이 원격에서
누가 `arm`·조그를 누르는 것"으로 옮겨간다. 그래서 **`inDragTeach` 중 stop 외 전부 거부**를
게이트 조건으로 먼저 넣는다 — `SAFETY-RULES.md` **조건 25**. 화면 힌트가 아니라 서버 판정이다.

## 3.5 `MoveJ` 로는 정책을 실행할 수 없다 (2026-08-03 발견)

학습된 정책은 초당 10~50회 목표를 뱉는다. `MoveJ` 는 **점 대 점** 명령이라 매 호출마다
가감속이 새로 걸려 뚝뚝 끊기거나 큐가 밀린다. 벤더링된 SDK 에 필요한 것이 있다 —
`ServoMoveStart` → `ServoJ`(기본 주기 8ms) → `ServoMoveEnd` (소스 확인, 실기 미검증).

그래서 **브리지에 서보 스트리밍 경로를 새로 만드는 것이 모방학습의 선행 조건**이고,
안전 게이트도 "명령당 5°" 가 아니라 **각속도(°/s)** 로 다시 써야 한다.
정본은 `docs/ref/contract/SAFETY-RULES.md` §서보 스트리밍 상한 · `docs/ref/arch/STACK.md` §서보 스트리밍.

## 4. 사다리 (학습 없는 것부터)

1. **카메라 장착·스트림** — 마운트 제작, `/api/camera/*` 계약 먼저 (하드 룰 1). 학습 없음
1.5 **직접교시 녹화** — `DragTeachSwitch(1)` → 20004 관절값 시간축 기록 → `(0)`.
   **선행은 `SAFETY-RULES` 조건 25**(드래그 중 명령 차단). 학습 없이 되고 장비도 안 든다
2. **시연 녹화 → 키프레임 재생** — 궤적을 기록하고 되돌려 실행. 학습 없이 되는 구간이고
   Teach·Program 확장으로 끝난다. **여기서 후처리를 한다** — 사람이 끈 궤적은 손떨림과
   느린 속도를 그대로 담고 있다. 스플라인 평활화 + 관절 한계 안에서 시간축 압축
   (재생 경로에만 쓴다 — 학습 데이터에 대한 주의는 §5)
2.5 **서보 스트리밍 경로** — 위 §3.5. 여기부터가 정책 실행의 전제다
3. **시연 수집** — 같은 작업 20~50회. LeRobot 데이터셋 포맷으로.
   **물체 위치·각도를 매번 바꿔가며 찍는다** — 작업영역 안에서 ±5~10cm, 기울기도 조금씩.
   한 자리에 고정해 50회를 찍으면 정책은 시각 서보가 아니라 **고정 궤적을 외운다**
4. **정책 학습(ACT 먼저)** — GPU 필요. 판정은 "5회 중 3회 성공" 같은 실측 기준으로
5. Diffusion Policy·UMI 식 상대궤적 — 4가 되고 나서

**브리지·서보 경로·시연 수집은 우리 몫이고, 정책 학습은 분담이 가능하다.** 어느 쪽이
학습을 맡든 **실행은 브리지의 승인·안전 게이트를 그대로 통과**한다 — 예외를 만들면
xmlrpc 단일 연결에서 컨트롤러가 넘어간다.

**선행 준비물** — 서보 경로 · 텔레오퍼레이션 입력(±1° 버튼으로 30~50회 시연은 불가능하다) ·
손목 카메라와 hand-eye · 학습용 GPU. 전부 `GAP-MATRIX` 에 OPEN 으로 있다.

## 5. 함정

- **관절 좌표만 옮겨 학습 데이터를 불리지 않는다** — "시연 1회를 평행이동·회전시켜 수백 개를
  자동 생성" 은 궤적 재생에는 통해도 **정책 학습에는 못 쓴다.** ACT·Diffusion Policy 는
  픽셀로 판단하는데 옮긴 관절값에 맞는 카메라 영상이 없다. 짝이 틀린 데이터를 먹인 꼴이라
  현물에서 조용히 실패한다. 늘리려면 **실제로 물체를 옮겨 다시 찍는다** (§4 사다리 3)
- **hand-eye 캘리브레이션** — 손목 카메라 좌표계를 로봇에 묶지 않으면 물체 위치가 틀린다.
  UMI 식 상대궤적을 쓰면 부담이 준다
- **손목에는 카메라 모듈만 단다** — 파이 본체·허브는 베이스나 중간 마운트에 고정하고
  손목엔 케이블만 간다. 말단 하중은 J5·J6 지터로 나타나고, 그 지터가 그대로 시연 데이터가 된다
- **케이블 감김** — 뚜껑 풀기·조이기는 J6 가 같은 방향으로 계속 도는 작업이다. 손목 USB 를
  여유 없이 묶으면 몇 바퀴 만에 감겨 당겨진다. 스파이럴 튜브로 관절을 따라 여유를 준다.
  회전 누적 상한을 브리지가 세는 것도 검토한다 (미결)
- **시연↔실행 도메인 차이** — 조명·배경·물체 위치가 달라지면 정책이 실패한다
- **한 번 재고 그리로 가는 경로(open-loop)는 물체가 움직이면 사고다** — 위치를 저장한 뒤
  로봇이 이동하는 동안 누가 병을 건드리면 허공을 잡거나 병을 받아친다. 정책이 매 프레임
  보고 판단하면(closed-loop) 안 생기는 문제지만, **학습 전 사다리 1~2 는 open-loop 다.**
  그 구간에서는 `/proposal` 에 `anchorPose`(잰 시점 자세)와 `validUntil` 을 실어 **실행 직전
  재확인**하고, 허용 반경을 벗어나면 제안을 무효로 만든다. AR 은 그 반경을 안전 링으로 그리고
  이탈 시 경고한다 — 겹쳐 보기가 안전 기능이 되는 지점이다 (`Vision/AGENTS.md`)
- **정책 출력의 안전** — 학습된 궤적은 사람이 검토한 적이 없다. 스트리밍 게이트(각속도·
  결손 종료)를 그대로 태우고, 상한 안의 명령을 연속으로 쏟아 큰 동작을 만드는 우회로를
  열지 않는다 (D47 · `SAFETY-RULES.md` §서보 스트리밍 상한)
- **xmlrpc 는 연결 하나** — 학습 루프가 브리지 밖에서 20003 에 붙으면 컨트롤러가 넘어간다
  (2026-07-31 실측). LeRobot 어댑터도 **브리지를 통해** 말해야 한다
- **그리퍼 지령↔읽기 방향 반대** (실측) — 학습 데이터에 들어가기 전에 변환을 확정할 것
- **체결은 힘이 걸리는 작업이다** — 뚜껑을 끝까지 조이면 모터 과부하나 작업물 변형이 난다.
  `MoveGripper` 에 `force`·`rotTorque` 인자가 이미 있다 (`STACK.md` §그리퍼) — 상한 없이
  부르지 않는다. 토크 서보(`ServoJT`)도 SDK 에 있으나 우리 범위 밖이다 (미검토)
- **개인정보** — 시연 영상에 사람이 찍힌다. 로봇 상태와 같은 공개 수준으로 두지 않는다.
  저장은 `~/fr5-data/demos/`, 보존기간·열람 범위를 촬영 전에 정한다

## 6. 확신 낮은 것 (박기 전 재확인)

- **드래그티칭이 실기에서 실제로 되는지** — `DragTeachSwitch` 를 걸었을 때 팔이 사람 힘으로
  밀리는지, 그 동안 20004 관절값이 따라오는지. 30분짜리 킬실험이고 §1 1순위가 여기 달렸다
- **무선 카메라의 정책 입력 지연 예산** — D48 은 압축 컬러만 흘려 무선을 정당화했지만
  정책이 10~50Hz 로 관측을 요구할 때의 지터를 **아직 안 쟀다**. 학습 짝짓기는 촬영 시각으로
  풀리나(D48), 추론 루프의 늦음은 별개다
- D405 실제 최소거리·무게·시야각 (데이터시트)
- ACT/Diffusion Policy 가 **6축 산업용 로봇**에 얼마나 전이되는지 — 논문 사례는 대부분
  저가 양팔·Franka 다. `ServoJ` 주기·필터·gain 을 어떻게 잡아야 하는지도 실측 대상이다
- 학습에 필요한 GPU 메모리·시간, 시연 1회당 데이터 용량
- LeRobot 관측 루프와 우리 20004 상태 스트림(백그라운드 스레드 캐시)의 타임스탬프 정합
