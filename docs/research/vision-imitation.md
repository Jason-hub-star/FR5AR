# 모방학습 — 시연을 보고 재현하기 (Vision 폴더 구체화의 근거)

분류: **조사**. SSOT 가 아니다. 여기 값을 근거로 코드를 바꾸지 않는다 — `docs/ref/` 로
승격된 뒤에 짠다. 2026-08-03 팀 회의 요구("뎁스카메라를 그리퍼에 달고 사람 작업을 관찰해
로봇이 그대로 실행")를 받아 조사했다. **`Vision/` 폴더를 구체화할 때 이 문서를 먼저 읽는다.**

## 0. 범위 (D47 — 이건 조사가 아니라 결정이다)

> **시연 수집 → 정책 학습 → 정책으로 작업 수행까지가 범위다.**
> 학습은 데모의 **목적 그 자체**이자 작업을 하는 **수단**이다 (2026-08-03 확인).
> 배운 적 없는 작업을 로봇이 **스스로 계획**하는 것은 여전히 범위 밖이다 (PRD).

D45 는 이보다 좁게("시연 1건 → 궤적 1건 재생") 그었다가 D47 에서 넓혔다. 넓어지면서
**기술 관문이 하나 열렸다 — `MoveJ` 로는 정책을 실행할 수 없다** (아래 §3.5).

## 1. 접근법 셋

| 접근 | 방식 | 장비 | 시연량 | 우리 적합성 |
|---|---|---|---|---|
| **텔레오퍼레이션** | 사람이 로봇을 조종하며 녹화 | 기존 브리지 + 게임패드 | 30~300회 | **1순위** — 지금 코드에 바로 붙는다. 로봇 동작 범위 안에서만 기록돼 캘리브레이션·안전이 간단 |
| **UMI 류 핸드헬드** | 그리퍼 모양 도구를 사람이 들고 시연, 손목 카메라가 관찰 | 3D 프린트 핸드헬드 + 카메라 | 20~100회 | 데이터 품질 최상. 하드웨어 제작이 선행 |
| **사람 손 영상 → 리타게팅** | 맨손 작업을 추적해 로봇 자세로 변환 | 카메라만 | 50~500회 | 장비는 제일 싸지만 손↔평행 그리퍼 변환 오차가 핵심 위험 |

회의에서 나온 "사용자가 작업하는 모습을 관찰" 은 문면상 셋째지만, **손가락 2개 평행
그리퍼(PGE A-100-40)와 사람 손은 자유도가 달라** 리타게팅이 곧 연구 주제가 된다.
같은 결과를 가장 싸게 얻는 길은 첫째다.

## 3.5 `MoveJ` 로는 정책을 실행할 수 없다 (2026-08-03 발견)

학습된 정책은 초당 10~50회 목표를 뱉는다. `MoveJ` 는 **점 대 점** 명령이라 매 호출마다
가감속이 새로 걸려 뚝뚝 끊기거나 큐가 밀린다. 벤더링된 SDK 에 필요한 것이 있다 —
`ServoMoveStart` → `ServoJ`(기본 주기 8ms) → `ServoMoveEnd` (소스 확인, 실기 미검증).

그래서 **브리지에 서보 스트리밍 경로를 새로 만드는 것이 모방학습의 선행 조건**이고,
안전 게이트도 "명령당 5°" 가 아니라 **각속도(°/s)** 로 다시 써야 한다.
정본은 `docs/ref/SAFETY-RULES.md` §서보 스트리밍 상한 · `docs/ref/STACK.md` §서보 스트리밍.

## 4. 사다리 (학습 없는 것부터)

1. **카메라 장착·스트림** — 마운트 제작, `/api/camera/*` 계약 먼저 (하드 룰 1). 학습 없음
2. **시연 녹화 → 키프레임 재생** — 조그·지점으로 만든 궤적을 시간축으로 기록하고 되돌려
   실행. 학습 없이 되는 구간이고 Teach·Program 확장으로 끝난다
2.5 **서보 스트리밍 경로** — 위 §3.5. 여기부터가 정책 실행의 전제다
3. **텔레오퍼레이션 시연 수집** — 같은 작업 30~50회. LeRobot 데이터셋 포맷으로
4. **정책 학습(ACT 먼저)** — GPU 필요. 판정은 "5회 중 3회 성공" 같은 실측 기준으로
5. Diffusion Policy·UMI 식 상대궤적 — 4가 되고 나서

**브리지·서보 경로·시연 수집은 우리 몫이고, 정책 학습은 분담이 가능하다.** 어느 쪽이
학습을 맡든 **실행은 브리지의 승인·안전 게이트를 그대로 통과**한다 — 예외를 만들면
xmlrpc 단일 연결에서 컨트롤러가 넘어간다.

**선행 준비물** — 서보 경로 · 텔레오퍼레이션 입력(±1° 버튼으로 30~50회 시연은 불가능하다) ·
손목 카메라와 hand-eye · 학습용 GPU. 전부 `GAP-MATRIX` 에 OPEN 으로 있다.

## 5. 함정

- **hand-eye 캘리브레이션** — 손목 카메라 좌표계를 로봇에 묶지 않으면 물체 위치가 틀린다.
  UMI 식 상대궤적을 쓰면 부담이 준다
- **시연↔실행 도메인 차이** — 조명·배경·물체 위치가 달라지면 정책이 실패한다
- **정책 출력의 안전** — 학습된 궤적은 사람이 검토한 적이 없다. 스트리밍 게이트(각속도·
  결손 종료)를 그대로 태우고, 상한 안의 명령을 연속으로 쏟아 큰 동작을 만드는 우회로를
  열지 않는다 (D47 · `SAFETY-RULES.md` §서보 스트리밍 상한)
- **xmlrpc 는 연결 하나** — 학습 루프가 브리지 밖에서 20003 에 붙으면 컨트롤러가 넘어간다
  (2026-07-31 실측). LeRobot 어댑터도 **브리지를 통해** 말해야 한다
- **그리퍼 지령↔읽기 방향 반대** (실측) — 학습 데이터에 들어가기 전에 변환을 확정할 것
- **개인정보** — 시연 영상에 사람이 찍힌다. 로봇 상태와 같은 공개 수준으로 두지 않는다.
  저장은 `~/fr5-data/demos/`, 보존기간·열람 범위를 촬영 전에 정한다

## 6. 확신 낮은 것 (박기 전 재확인)
