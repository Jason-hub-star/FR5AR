# 모방학습 — 시연을 보고 재현하기 (Vision 폴더 구체화의 근거)

분류: **조사**. SSOT 가 아니다. 여기 값을 근거로 코드를 바꾸지 않는다 — `docs/ref/` 로
승격된 뒤에 짠다. 2026-08-03 팀 회의 요구("뎁스카메라를 그리퍼에 달고 사람 작업을 관찰해
로봇이 그대로 실행")를 받아 조사했다. **`Vision/` 폴더를 구체화할 때 이 문서를 먼저 읽는다.**

## 0. 먼저 그은 선 (D45 — 이건 조사가 아니라 결정이다)

> **시연 1건 → 궤적 1건 재생. 새 물체·새 배치로 일반화하지 않는다.**

PRD 의 "자율 작업 계획은 범위 밖 — 사람이 가르친 것만 재생한다" 와 충돌하지 않게 그은
선이다. 팀이 일반화(물체 위치가 바뀌어도 알아서 잡기)까지 원하면 **범위 재결정이 먼저**다 —
시연 수십~수백 회 수집과 GPU 학습이 붙어 일정이 달라진다.

## 1. 접근법 셋

| 접근 | 방식 | 장비 | 시연량 | 우리 적합성 |
|---|---|---|---|---|
| **텔레오퍼레이션** | 사람이 로봇을 조종하며 녹화 | 기존 브리지 + 게임패드 | 30~300회 | **1순위** — 지금 코드에 바로 붙는다. 로봇 동작 범위 안에서만 기록돼 캘리브레이션·안전이 간단 |
| **UMI 류 핸드헬드** | 그리퍼 모양 도구를 사람이 들고 시연, 손목 카메라가 관찰 | 3D 프린트 핸드헬드 + 카메라 | 20~100회 | 데이터 품질 최상. 하드웨어 제작이 선행 |
| **사람 손 영상 → 리타게팅** | 맨손 작업을 추적해 로봇 자세로 변환 | 카메라만 | 50~500회 | 장비는 제일 싸지만 손↔평행 그리퍼 변환 오차가 핵심 위험 |

회의에서 나온 "사용자가 작업하는 모습을 관찰" 은 문면상 셋째지만, **손가락 2개 평행
그리퍼(PGE A-100-40)와 사람 손은 자유도가 달라** 리타게팅이 곧 연구 주제가 된다.
같은 결과를 가장 싸게 얻는 길은 첫째다.

## 2. 오픈소스 스택 (2026-08-03 주소 응답 확인)

| 무엇 | 주소 | 역할 |
|---|---|---|
| **LeRobot** | `github.com/huggingface/lerobot` | 중심축 — 데이터셋 포맷·기록·학습·추론을 한 묶음. `Robot` 어댑터만 구현하면 우리 FR5 가 붙는다 |
| ACT | `github.com/tonyzhaozh/act` (arXiv:2304.13705) | 정책 1안. 시연 적은 양으로 학습, 추론 빠름 |
| Diffusion Policy | `github.com/real-stanford/diffusion_policy` (arXiv:2303.04137) | 정책 2안. 다중 모드에 강하고 추론이 느림 |
| UMI | `github.com/real-stanford/universal_manipulation_interface` | 핸드헬드 시연 수집 방식의 원본 |
| RealSense SDK | `github.com/realsenseai/librealsense` | 카메라 드라이버 (옛 `IntelRealSense/` 주소는 이리로 넘어간다) |
| HaMeR · MediaPipe · dex-retargeting | `geopavlakos/hamer` · `google-ai-edge/mediapipe` · `dexsuite/dex-retargeting` | 손 영상 경로를 갈 때만 |

## 3. 손목 뎁스카메라

| 후보 | 최소거리 | 무게 | 판정 |
|---|---|---|---|
| **RealSense D405** | ~7cm | ~60g | **1순위** — 근거리 전용이라 손목에 맞다 |
| D435i | ~30cm | ~72g | 물체와 30cm 를 못 띄우면 손목엔 부적합 |
| OAK-D Lite / Azure Kinect | 13cm / 25cm | 214g / 440g | 무겁다 |

⚠ **미검증** — 위 수치는 조사 단계 값이다. **구매 전 제조사 데이터시트로 재확인한다**
(스택가드 규칙 — 값을 박기 전 등재).

## 4. 사다리 (학습 없는 것부터)

1. **카메라 장착·스트림** — 마운트 제작, `/api/camera/*` 계약 먼저 (하드 룰 1). 학습 없음
2. **시연 녹화 → 키프레임 재생** — 조그·지점으로 만든 궤적을 시간축으로 기록하고 되돌려
   실행. **여기까지가 데모의 최소 성립선**이고 Teach·Program 확장으로 끝난다
3. **텔레오퍼레이션 시연 수집** — 같은 작업 30~50회. LeRobot 데이터셋 포맷으로
4. **정책 학습(ACT 먼저)** — GPU 필요. 판정은 "5회 중 3회 성공" 같은 실측 기준으로
5. Diffusion Policy·UMI 식 상대궤적 — 4가 되고 나서

**2까지는 우리 몫, 3~4는 팀 분담이 자연스럽다** — 생산성 알고리즘·AMR 주행을 나눈 것과
같은 선이다. 어느 쪽이 학습을 맡든 **실행은 브리지의 승인·안전 게이트를 그대로 통과**한다.

## 5. 함정

- **hand-eye 캘리브레이션** — 손목 카메라 좌표계를 로봇에 묶지 않으면 물체 위치가 틀린다.
  UMI 식 상대궤적을 쓰면 부담이 준다
- **시연↔실행 도메인 차이** — 조명·배경·물체 위치가 달라지면 정책이 실패한다
- **정책 출력의 안전** — 학습된 궤적은 사람이 검토한 적이 없다. 브리지의 10%·5° 상한을
  그대로 태우고, 5° 안의 명령을 연속으로 쏟아 큰 동작을 만드는 우회로를 열지 않는다 (D45)
- **xmlrpc 는 연결 하나** — 학습 루프가 브리지 밖에서 20003 에 붙으면 컨트롤러가 넘어간다
  (2026-07-31 실측). LeRobot 어댑터도 **브리지를 통해** 말해야 한다
- **그리퍼 지령↔읽기 방향 반대** (실측) — 학습 데이터에 들어가기 전에 변환을 확정할 것
- **개인정보** — 시연 영상에 사람이 찍힌다. 로봇 상태와 같은 공개 수준으로 두지 않는다.
  저장은 `~/fr5-data/demos/`, 보존기간·열람 범위를 촬영 전에 정한다
