# 파이5 기록 노드 브링업 — 랜선 없이 자립해 브리지에 붙는다

날짜 2026-08-07 · 실기 · 계정 `pi` / WiFi `192.168.30.45` · 호스트 `fr5-log`

## 판정 — 파이5로 확정

D81 이 "호스트는 실측 후 정한다"로 열어 둔 파이4/5 선택을, **파이5로 닫는다.**

| 실험 | 결과 | 판정 |
|---|---|---|
| ① 전원 | `vcgencmd get_throttled` = **`0x0`** · 47.7→51.0°C · core 0.81V | 저전압 0 — **D61 전원 보류 해제** |
| ② FR5 브리지 접속 | `curl …:5055/robots` → **HTTP 200 (0.057s)** | 기록 노드 성립 실증 |
| ③ 시계·RTC | NTP 동기됨 · **`/dev/rtc0` 존재** | 파이5 **내장 RTC** — 배터리 시 정전에도 시각 유지 |
| ④ 저장 | microSD 14.9G (rootfs 14.4G · 여유 12G) | 부팅·기록 둘 다 SD 로 충분(⑥). SSD 는 수명 대비용 |
| ⑤ 사양 | 파이5 Model B Rev 1.1 · 4코어 · RAM **3.9GB** | 기록 노드 충분 · LLM 은 1~3B 까지 |
| ⑥ 기록 왕복 | 실기 궤적 스트림 **29.7Hz** 구독 → SD SQLite 기록: INSERT+commit **p50 60µs·p99 105µs**, 최대 쓰기율 **9.5kHz** | 유입의 **354배 여유** — 기록 노드 역할 실증. 1시간 연속 32MB |

**핵심은 ②③.** ② 는 D81 의 "랩 안 상주 기계가 브리지 데이터를 받는다"를 실기로 세운 것이고,
③ 의 내장 RTC 가 파이5 를 파이4 보다 앞세우는 결정타다 — 파이4 는 D81 조건③(시계 유지)을
외부 모듈로 받쳐야 하는데 파이5 는 배터리 커넥터만 꽂으면 된다.

## 자립성 — 사람 개입 0으로 재부팅·재접속

전원을 껐다(안전 종료) 켜고 **랜선을 뽑은** 상태에서:
- WiFi(`codelab_robot_team_3_5G`)에 자동 접속 → `192.168.30.45`
- FR5 브리지에 **HTTP 200** 재확인
- 이더넷 DOWN 인데도 정상 — 상주 노드의 무인 복구가 성립

## 어떻게 세웠나 (재현 경로)

1. **Ubuntu Server 24.04.3 (arm64+raspi)** 이미지를 맥에서 `xz -dc | dd of=/dev/rdisk` 로 굽는다
2. 부팅 파티션(FAT · macOS 안전)의 `user-data` 를 계정 `pi`+`ssh_pwauth:true`+`chpasswd` 로,
   `network-config` 로 WiFi 를 넣는다
3. **갓 구운 이미지여야 한다** — 쓰던 카드는 cloud-init 이 `nocloud` 캐시로 계정 생성을 건너뛴다
   (상세는 `/진단` §쓰던 SD 에서 cloud-init 이 계정을 안 만든다)

## 확인하지 않은 것 (다음 세션)

- **기록 DB 매체** — 속도는 SD 로 충분함이 실측됐다(⑥, 354배 여유). SSD 는 **수명 목적**으로만
  검토한다 (몇 달 잦은 쓰기의 SD 셀 마모). 지금 당장은 SD 로 진행 가능 — 미확보여도 블로커 아니다
- **내구성 설정** — ⑥ 은 `synchronous=NORMAL`+WAL 로 쟀다. 정전 시 마지막 몇 프레임 손실 가능.
  여유가 354배라 `synchronous=FULL`(매 커밋 flush)로 올려도 27Hz 는 문제없을 것 — 미검증
- **RTC 배터리** — `/dev/rtc0` 는 있으나 배터리 없이 정전 후 시각 유지는 미확인
- **LLM 실측** — RAM 3.9GB 에서 1~3B 모델 tok/s 미측정 (얹을지 미정)
- **기록 노드 코드** — SQLite 스키마·브리지 WS 구독은 아직 0줄. D81 은 결정만, 구현 미착수

## 딸린 사고 — 되짚어 둔다

macOS `debugfs -w` 로 SD 의 ext4 를 편집하다 **카드 두 장의 shadow 를 손상**시켰다
(로봇 kim · team1). ext4 쓰기는 리눅스에서 한다 — 랩 우분투 PC 에 USB-A 리더로 꽂아 복구 예정.
로봇 kim 원본 해시는 확보돼 있다. 교훈은 `/진단` §macOS 로 SD 의 리눅스 파티션을 고치려다 깨진다.
