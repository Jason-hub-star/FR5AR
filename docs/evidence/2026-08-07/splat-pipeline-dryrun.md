# 폰 영상 → 가우시안 스플랫 → three.js — 사슬은 뚫렸고 화질은 판정 중

분류: 증거 · 2026-08-07 · 대상 없음(**아직 레포 코드 아님** — 스크래치패드 드라이런) ·
입력 `Downloads/20260807_155101_원본.mp4`

## 결론 먼저

**영상 → COLMAP → Brush → three.js/Spark 사슬이 끝까지 돌았다.** SfM 은 만점(241/241 ·
0.815px)이고 three.js 가 84,137개 가우시안을 실제로 그렸다. **화질만 미판정** — 8,000 steps
산출물은 미학습 상태(바늘 모양 가우시안)라 못 쓴다. 30,000 steps 재학습 결과를 기다린다.

**이 영상은 실험용이다** (주인님 · 맵 세팅 후 본 영상을 다시 찍는다). 그래서 이 문서의
목적은 결과물이 아니라 **파이프라인이 도는가와 어디서 넘어지는가**다.

## 입력 — 공유본과 원본이 10배 다르다

| | 공유받은 것 | 폰 원본 (`adb pull`) |
|---|---|---|
| 해상도 | 592×1280 | **1080×2336** |
| 코덱·비트레이트 | H.264 · 3.8 Mbps | **HEVC · 40.5 Mbps** |
| 용량 | 7.2 MB | 81.3 MB |

길이는 둘 다 16.07초 · 482프레임 · 30fps. **공유본으로 판단하면 안 된다** — 처음에
"해상도가 모자라 다시 찍어야 한다"고 적었는데 원본을 보니 근거가 사라졌다.

```bash
adb shell 'find /sdcard/DCIM -iname "*20260807_1551*"'
adb pull /sdcard/DCIM/Camera/20260807_155101.mp4 ~/Downloads/20260807_155101_원본.mp4
```

## 학습 — 맥에서 우분투 GPU 로 옮겼다

| | 맥 (M5 10코어) | **우분투 (RTX 5060 8GB)** |

| 8,000 steps | 17분 | — |
| 30,000 steps | 약 64분 (환산) | 진행 중 · GPU 100% · VRAM 2.5GB · 66°C |

**Colab T4 는 검토했다 가 기각했다** — 인용 기준 T4 가 45~90분이라 맥과 같은 구간이고,
무료 티어는 세션이 끊긴다. 우리 랩에 5060 이 놀고 있는 걸 늦게 알았다(§배운 것 ④).

### 로봇 호스트에서 GPU 작업을 돌리는 규칙 (신설)

`192.168.30.240` 은 `fr5-bridge`·`tb-bridge` 가 사는 기계다. 그래서 셋을 지킨다:

1. **`lastObserved` 가 전부 `null` 일 때만 시작한다** — 누가 조그 중이면 안 건다
2. **작업 폴더는 `~/FR5Web/` 밖** (`~/splat-work/`) — 배포가 `rsync --delete` 라 트리 안은 지워진다 (D45 와 같은 함정)
3. **`nice` 를 건다** — 실측 CPU 132%/16스레드라 브리지 여유는 충분했지만 규칙으로 둔다

COLMAP 은 **일부러 맥에 남겼다.** 우분투에 깔면 SfM 이 5분 빨라지는 대신 의존성 20여 개가
안전 서비스가 도는 기계에 얹힌다. 그 거래는 안 한다. 로봇 호스트에 올린 것은
**Brush 바이너리 하나뿐**이다.

## 넘어진 곳 셋 — 전부 "에러 없이 조용히 실패"였다

### ① COLMAP 4.x 에서 옵션이 개명됐다

`--SiftExtraction.use_gpu` → **`--FeatureExtraction.use_gpu`**,
`--SiftMatching.use_gpu` → **`--FeatureMatching.use_gpu`**.
인터넷 예제는 대부분 3.x 기준이다. 개명된 옵션을 주면 그 단계만 조용히 건너뛰고
다음 단계가 `No images with matches` 로 죽는다 — **원인이 두 단계 앞에 있다.**

brew 빌드는 `without CUDA` 라 GPU SIFT 가 OpenGL 경로로 가서 헤드리스에서 불안정하다.
맥에서는 `use_gpu 0` 으로 고정한다.

### ② Spark 는 `SparkRenderer` 를 씬에 넣어야 그린다

`SplatMesh` 만 `scene.add()` 하면 **로드는 성공하고**(`numSplats` 정상, 콘솔 경고 0)
**화면만 검다.** 실렌더 검증이 "로드됐다"만 보면 통과해 버리는 모양이다.

```js
const spark = new SparkRenderer({ renderer });
scene.add(spark);                    // ← 이게 없으면 에러 없이 검은 화면
scene.add(new SplatMesh({ url: '...' }));
```

`SplatMesh` 는 `Box3.setFromObject` 로도 안 잡힌다(반경 0). 카메라를 맞추려면
`.ply` 에서 중심을 직접 뽑아야 한다.

### ③ MCP 브라우저 탭에서는 `requestAnimationFrame` 이 안 돈다 — **이건 우리 실렌더 검증 전체에 걸린다**

MCP 탭은 포그라운드가 아니라 rAF 가 스로틀돼 **아예 안 돈다.** 렌더를
`setAnimationLoop` 안에만 두면 카메라가 영원히 원점에 멈춰 있고, `await rAF` 를 하면
45초 CDP 타임아웃이 난다. 화면은 검고 콘솔은 깨끗하다.

**우회 — 그리기를 함수로 빼서 바깥에서 부른다.**

```js
window.draw = (a, d, h) => { place(a, d, h); renderer.render(scene, camera); };
renderer.setAnimationLoop(() => { ... });   // 사람이 볼 때만 쓰인다
```

픽셀을 읽어 판정하려면 `WebGLRenderer({ preserveDrawingBuffer: true })` 도 필요하다.
