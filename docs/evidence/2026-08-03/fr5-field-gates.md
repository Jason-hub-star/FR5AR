# FR5 실기 게이트 4건 + 그리퍼 첫 실동작 — 우분투 호스트에서

분류: **증거**. 2026-08-03 오전, 브리지 호스트를 우분투로 옮긴 상태에서 남은 실기
게이트를 닫고, 그리퍼(PGE A-100-40)를 웹 스택의 SDK 경로로 처음 움직였다.

## 실기 게이트 실측

| 게이트 | 결과 |
|---|---|
| 2클라이언트 조종권 | **통과** — mac-a 보유 중 mac-b claim → 409 "조종권은 mac-a 에게" · mac-b 의 release 도 409 |
| 10분 폴링 (WS `/ws/state`) | **통과** — 600초 프레임 16,728(평균 27.9fps) · JSON 깨짐 0 · 재연결 0. **단 최대 프레임 공백 5.4초 1회** — xmlrpc 무타임아웃(GAP OPEN)과 같은 결로 추정: `_in_drag_teach` 잠금 보유 중 지연이 전 구독자를 세운다 |
| 우분투 재부팅 자동 기동 | **통과** — reboot 후 **45초** 만에 서비스 응답 복귀 (systemd user 서비스+linger). 단 **로봇 자동 연결은 없다** — 부팅 후 DISCONNECTED 로 시작, 사람이 /connect 해야 한다 (설계 논점으로 등재) |
| /state JSON 간헐 깨짐 | **브리지 무죄 확정** — 원인은 개발 맥의 rtk 훅이 파이프 출력을 510B에서 자른 것. WS 10분 0건이 재확인 |

## 그리퍼 — 정체 확정과 첫 실동작

- **실물 라벨 육안 확인: PGE A-100-40** (대환). 3D 메시·장착값(`gripper-mount.json`)과 일치 —
  모델·실물 불일치 우려 해소. 펜던트의 "PGI-140"은 SDK 대환 선택지가 하나뿐이라 빌려 쓰는 것
- 펜던트 설정(제조업체 DAHUAN·유형 PGI-140·D1.0·말단 1번)은 `SetGripperConfig(company=4,
  device=0)` 과 1:1. `GetGripperConfig` 실측 `[_, 4, 0, 0]`
- **스모크 2회 (손가락 개폐 육안 확인, 주인님 입회)** — 브리지 정지 → 단독 스크립트
  (20003 단일 클라이언트 규칙) → `ActGripper(1,1)` 활성화 0→1 → `MoveGripper` 30%→80% →
  브리지 재기동·재연결. 로봇 팔 부동, 손가락만 동작
- **주의 실측 2건** (STACK §그리퍼에 등재): 지령 pos%와 읽기 pos%의 방향이 반대
  (지령 30→읽기 76, 지령 80→읽기 53) · `GetGripperMotionDone`이 이동 직후 `[1,0]` —
  필드 순서 의심. 둘 다 구현 전 캘리브레이션 실측 항목

## 확인하지 않은 범위

- 그리퍼 지령↔읽기 방향·스케일의 정식 캘리브레이션 (표만 만들면 됨 — 구현 때)
- 힘(force%) 상한의 안전 실측 — 이번엔 30% 고정, 물체 파지 없음
- 5.4초 프레임 공백의 정확한 원인 격리 (타임아웃 수리 후 재측정이 판정)
