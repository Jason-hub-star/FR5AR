## 2. 실렌더가 잡은 결함 6개

**코드만 봐서는 하나도 안 보였다.**

1. **탄두 노즈콘이 뒤집혔다** — `rotation.z = -π/2` 면 원뿔의 좁은 끝이 `+X`(동체 쪽)를
   향한다. 뾰족한 쪽이 동체에 박혀 **노즈가 떨어져 있는 것처럼** 보였다. → `+π/2`
2. **척의 받침 기둥이 척 앞을 가렸다** — 기둥과 척판이 같은 `z` 라 3점 조가 안 보였다.
   → 기둥을 `faceD/2 + pedD/2` 만큼 뒤로
3. **방폭 격벽(2400)이 해체 셀을 통째로 가렸다** — 배치를 보는 화면인데 배치를 가리면
   소품이 아니라 방해물이다. → **기본 높이 1200(허리)**
4. **관측창이 벽체에 묻혀 안 보였다** — 통벽 안에 유리판을 넣었더니 렌더에 안 나온다.
   → 벽을 **좌·우·위·아래로 쪼개 진짜 구멍**을 냈다
5. **조가 큐브 덩어리로 보였다** — `box(w,w,d)` 정사각 단면. → 반경 방향으로 긴 계단 2단
6. **bbox 가 인자를 넘었다** (`partTray` 722/700 · `blastWall` 380/300 · `warhead` 70/65 ·
   `chuck` 427/420) — 테두리·캡·밴드가 밖으로 나갔다. **눈이 아니라 숫자로만 잡히는 결함**이고,
   배치 충돌·도달범위 검사가 bbox 를 쓰므로 그냥 두면 실제보다 넓게 점유한다고 판정한다

## 3. 화면 반영에서 **기존 버그 둘**이 드러났다

소품과 무관하게 원래부터 있던 것이다.

### ① 스테이션이 `posMm[2]` 를 버리고 바닥에 그려졌다

`layout-view.js:220` 이 `posMm: [x, y, st.baseMm ?? 0]` 였다. `baseMm` 은 **어디에서도
설정되지 않는다**(전 저장소 검색 0건). 그런데 도달 판정 `reachCheck`(`schema.js:67`)는
같은 `posMm` 을 **3D 로** 재고 있었다.

> **초록 링은 z=900 기준으로 켜지는데 물건은 바닥에 놓여 있었다.**

판정과 화면이 다른 높이를 봤다. → `st.baseMm ?? st.posMm[2] ?? 0`.
`baseMm` 은 명시 override 로 남긴다.

### ② `validateLayout` 이 출하 예제에서 실패하고 있었다

`store` 스테이션의 `posMm` 이 `[10800, 6600]` 2개짜리인데 스키마는 3개를 요구한다.
**게이트가 `validateLayout` 을 안 부른다** — 그래서 아무도 몰랐다. → `[10800, 6600, 0]`.

수정 후 A·B 둘 다 검증 OK. 도달 판정도 설계 의도대로 나온다 —
A: `in`·`meas` 닿고 `out`·`store` 는 AMR 이 나른다.

## 4. 배치안

`examples.js` 의 `STATIONS`·`PROPS` 를 해체 라인으로 교체했다.
**스테이션 id 와 좌표는 그대로 뒀다** — AMR 경유점이 id 를 참조하므로 이름·부품만 바꿨다.

props 21개 전부 조립되고 미지 `type` 은 경고 후 건너뛴다.

## 5. Dashboard 실화면 — **여기서 D43 급 버그가 하나 더 나왔다**

`npm run dev:dash` 로 실제 메인뷰를 띄웠다 (`dashboard-defense-line.png`).

**첫 화면에 방 밖으로 판 4개가 떠 있었다.** 추적하니 **창 유리·창틀 9개가 `Z()` 를
건너뛰고 있었다** — 씬 z 가 `+1.60·+3.60·+1.40` 이었고 있어야 할 자리는 `−1.60·−3.60·−1.40`,
즉 **방 반대편 밖**이다.

`layout-view.js` 는 파일 머리에 이렇게 못박아 두고 있었다 —
*"이 파일에서 평면도 Y 를 씬에 넣는 곳은 전부 이 함수를 지난다 (하드 룰 5)."*
창 코드만 그 규약 밖에 있었다. **D43 이 잡은 거울 사상과 같은 종류다.**

### 게이트가 왜 못 잡았나 — 시험용 배치안에 창이 없었다

`scripts/check/scene-axes.sh` 에는 **`b.max.z < 0.3` 검사가 이미 있었다.** 그런데 그 게이트의
시험용 배치안 `L` 에 `windows` 도 `doors` 도 없어서 **그 코드 경로가 아예 안 돌았다.**
검사는 있는데 검사할 물건이 없었던 것이다.

→ 픽스처에 창 2개·문 1개를 넣었다. 버그를 일부러 되돌려 `방 z 범위 [-4.13, 1.70]` 로
**FAIL 이 뜨는 것까지 확인**했다.

**교훈** — 게이트의 픽스처가 실제 데이터의 부분집합이면, 없는 필드의 버그는 영원히 안 잡힌다.
