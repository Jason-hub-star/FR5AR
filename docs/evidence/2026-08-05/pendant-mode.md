# 펜던트를 잠근 건 우리였다 — 화면에서 되돌려 놓았다

분류: **증거**. 2026-08-05 저녁. 결정은 **D72**, 계약은 `API-CONTRACT.md` §모드 전환.

## 증상과 진짜 원인

팀원이 **"펜던트에서 수동·드래그가 잠겨 로봇을 손으로 못 움직인다"** 고 했다.
펜던트 고장이나 설정 문제로 의심했는데, 원인은 우리 ARM 시퀀스의 마지막 두 줄이었다.

```python
a.exit_drag_teach()   # DragTeachSwitch(0)
a.set_mode(0)         # 자동 모드
```

**우리가 잠갔다.** 게다가 `DISARM` 은 `stop()` + `enable(False)` 뿐이라 **모드를 되돌리지
않는다** — 껐다 켜도 잠긴 채로 남는다. **들어가는 문만 만들고 나오는 문을 안 만들었다.**

## 설계를 한 번 뒤집었다

처음엔 "`ARMED` 에서는 전환 거부, `DISARM` 이 선행"으로 짰다. 주인님이 뒤집었다 —
**드래그 티칭은 서보가 켜져 있어야 된다.** DISARM 을 강제하면 서보가 내려가 잠금을 푸는
길이 다시 막힌다. **규칙이 스스로를 막는 모양이었다.**

**하드 룰 4 를 지키는 것은 전환 금지가 아니다** — `check_motion` 의 `mode != 0` 이
수동 모드에서 우리 조그·moveJ 를 이미 거부하고, 드래그 중에는 `_common_safety` 가
그리퍼까지 막는다. **방어선이 원래 거기 있었다.**

## 같이 막은 구멍

`check_arm` 이 `inDragTeach` 를 안 봤다. 다른 명령은 전부 막는데 ARM 만 안 막아서,
**사람이 팔을 잡고 있는데 ARM 을 누르면 손 안에서 팔이 굳었다** (조건 25).
모드 전환을 넣는 순간 실제로 일어날 수 있는 시나리오라 함께 닫았다.

## 안 넣은 것 — 드래그 티칭 스위치

팔을 푸는 것은 펜던트의 **3위치 인에이블 스위치**다. 쥐면 풀리고 놓으면 잠긴다.
웹 버튼은 놓아도 풀린 채라 그 장치를 무력화한다 (`SAFETY-RULES.md` §FR-HMI).
`inDragTeach` 는 **읽기만** 한다. 모드 전환은 **권한만** 넘기므로 이 논리에 걸리지 않는다.

## 화면

토글은 헤더 안전 바의 **STOP 옆**에 뒀다 — 어느 탭에서도 사라지지 않는다. 잠긴 펜던트를
푸는 유일한 길이라 숨으면 안 된다. 생김새는 STOP 과 같고 **색만 중립**이다
(주요 동작은 중립 흑백 · D38). 수동일 때 `모드` 칩이 주황으로 바뀐다.

⚠ 그 과정에 **존재하지 않는 CSS 토큰(`--c-bg-raise`)** 을 써서 배경이 비어 있었다.
실제 토큰(`--c-btn`·`--c-btn-fg`·`--c-line-strong`)으로 고쳤다. STOP 글자색도
`#fff` → `var(--c-bg)` 로 바꿨다 — 다크 테마에서 대비가 2.8 로 기준(4.5) 미달이었다.

## 검증

```
uv run python -m unittest discover FR5/bridge   (모드 게이트 10건 신설)
node scripts/check/fr5-bridge-verify.mjs        ARMED 인 채 전환 → mode 1 · 서보 ON 유지
node scripts/check/fr5-web-verify.mjs           토글 상시 존재 · 비조종권 비활성 · 수동↔자동 왕복
실기 — 화면 토글 → **펜던트가 실제로 풀렸다** (주인님 확인) · `/state.mode` 0→1
```

## 확인하지 않은 범위

- **되돌리기는 사람 몫이다** — 자동 복귀 타이머가 없다. 잊으면 다음 사람의 조그가
  `auto 모드가 아니다` 로 거부되는데, 토글이 헤더에 늘 있어 막히지는 않는다
- **펜던트와 브리지의 쓰기 경쟁은 여전히 미측정** — `20003` 은 클라이언트 하나뿐이다
- 드래그 티칭이 실제로 되는지는 **이 세션에서 안 봤다** — 모드가 풀린 것까지만 확인했고,
  이후 측정은 펜던트 조그로 했다
