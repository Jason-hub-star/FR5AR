# 작업셀을 로봇이 직접 짚었다 — 상판과 벽이 좌표로 들어왔다

분류: **증거**. 2026-08-05 저녁. 조건 12 의 카테시안 절반을 채운 실측.
절차 정본은 `docs/ref/runbook/WORKCELL-MEASURE.md`, 결정은 **D73**.

## 왜 자로 잰 숫자로 안 됐나

주인님이 자로 재 주신 값이 있었다 — 상판 `85.8 × 58cm`, 바닥에서 `98.3 + 1.5cm`, 벽 `90.7cm`.
그런데 **자는 바닥 기준이고 게이트는 로봇 기준**이라 둘을 잇는 변환이 없었다.
로봇에게 직접 짚게 하면 변환이 필요 없다.

## 짚은 5점 (tool 1 · user 1)

| | x | y | z | 무엇 |
|---|---|---|---|---|
| P1 | -16.1 | -210.9 | -346.2 | 상판 가까운 모서리 (원점) |
| P2 | 779.1 | -196.8 | -344.7 | 긴 변 — **도달 한계에서 멈춤** |
| P3 | -6.9 | -798.2 | -346.6 | 짧은 변 끝 |
| P4 | 409.8 | -1397.8 | 96.5 | 벽 (높은 점) |
| P5 | 318.7 | -1391.2 | -96.9 | 벽 (낮은 점) |

## 그 자리에서 한 교차검증 — 방법이 옳다는 증명

```
|P3−P1| = 587.3mm   자로 잰 580 대비 +7.3 (1.3%)
P1 의 두 변 사이각 = 90.1°        직각 대비 +0.1°
z 세 점 = -346.2 / -344.7 / -346.6   퍼짐 1.9mm
```

**짧은 변이 7mm 안에 맞고 각이 90.1° 다.** 그래서 긴 변의 `|P2−P1| = 795.3`(기대 858) 부족
62.7mm 는 측정 오차가 아니라 **로봇이 진짜 못 간 것**으로 확정됐다.

**못 간 이유는 팔 길이가 아니라 허리다** — `j1` 이 `-179.49°` 에서 멈췄고 컨트롤러가 오류
`3/1` 을 냈다. FR5 의 `j1` 은 **±175°(총 350°)** 라 360° 를 못 돈다(협동로봇 배선).
그때 읽힌 손끝이 원점에서 1051mm 였는데 사양 도달범위가 922mm 다 — **오류 상태의 값은
도달 못 한 목표**였다.

⚠ **그 자세에서는 우리 조그로 못 빠져나온다.** `j1` 목표가 URDF 한계 밖이라 게이트가
전부 거부한다. 펜던트로만 되돌릴 수 있다 (GAP OPEN).

## 확정된 모양

```
상판   x ∈ [-16.1, 842.0]   y ∈ [-798.2, -210.9]   윗면 z = -345.8
벽     y ≈ -1400            상판 긴 변과 나란함
```

긴 변은 **858 로 넓게** 잡았다 — 못 가는 데를 막아도 손해가 없고, 팔꿈치를 반대로 접으면
갈 수도 있다. 상판은 **평면이 아니라 사각 기둥**이다: `x·y` 가 안일 때만 높이를 건다.
실제로 짚는 동안 손끝이 상판 **밖에서 346mm 아래**에 있었다 — 높이 하나로 막았으면
정상 자세부터 거부됐다.

## 게이트가 선 가정을 실기가 확인했다

작업영역은 **기구학이 상태 스트림과 같은 좌표계일 때만** 참이다. 그 가정을 ARM 이 매번
대조하게 만들었고, 실기 첫 판정이 이것이다:

```
작업영역 기구학↔스트림 최대차 0.0mm · fk=[357.4, 10.9, -11.6]
```

**0.0mm.** `GetForwardKin` 과 20004 스트림이 같은 좌표계다. 5mm 를 넘으면 ARM 이 거부한다.

## 확인하지 않은 범위

- **실기에서 거부되는 것을 아직 못 봤다.** 거부 논리는 mock 57/57 로만 확인했다.
  팔이 상판 위로 갈 일이 생기면 그때 눈으로 본다 (지금 손끝은 상판 밖에 있다)
- **벽 각도가 부정확하다** — 두 점이 수평으로 91mm 밖에 안 떨어져, 상판 길이로 늘리면
  ±70mm 까지 벌어진다. 그래서 벽 여유를 100mm 로 크게 잡았다. 벽을 따라 멀리 한 점을
  더 짚으면 확정된다
- **팔꿈치·상완은 판정 밖이다** — 손끝만 본다. 벽 여유가 큰 두 번째 이유다
- **좌표계에 묶여 있다** — `tool 1 · user 1` 이 바뀌면 전부 거짓이다. 게이트가 대조해
  거부하지만, `config.yaml` 의 `toolCoordId` 는 **브리지가 로봇에 넣지 않는다**
  (`SetToolCoord` 호출 없음 · GAP OPEN)
- 자로 잰 벽 `90.7cm` 와 우리 계산 `60.6cm` 가 안 맞는다. 기준점이 다른 것으로 보이나
  **확인하지 않았다** — 게이트는 로봇이 짚은 값을 쓴다
