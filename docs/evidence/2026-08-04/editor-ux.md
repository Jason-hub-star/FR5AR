# 편집기 조작 — 선택 표식 · 우클릭 · 편의 4개 (2026-08-04)

무대(프리셋·소품)는 `presets.md`. 이 문서는 **손으로 만지는 부분**만 다룬다.
전부 헤드리스 CDP 로 **실제로 눌러서** 확인했다 — 좌표만 읽고 넘기면 링이 어디 뜨는지·
골라지는지를 영영 확인 못 한다.

# 3차 — 링을 버리고 발자국 윤곽으로 (2026-08-04)

그림: `select-outline.png` (파랑=선택 섬 2.6×1.4 · 주황=호버 북쪽 벤치 5.0×0.7)

**"링이 너무 크다"** 는 크기 문제가 아니라 **모양 문제였다.** 외접원이라
3.8m × 0.62m 컨베이어의 반대각선 1.93m 가 반경이 됐다 — 좁은 쪽으로 3배 넘친다.
비율로 줄이면 긴 물체는 여전히 모양이 틀리고 작은 물체는 안 보인다.

**발자국 사각 윤곽으로 바꿨다.** 크기가 곧 물체의 발자국이라 **조절할 값이 아예 없다.**
실렌더에서 인자와 정확히 일치했다:

| 물체 | 인자 | 윤곽 |
|---|---|---|
| `island` benchRun | 2600 × 1400 | **2.6 × 1.4** |
| `runN` benchRun | 5000 × 700 | **5.0 × 0.7** |
| `meas` partTray | 640 × 440 | **0.64 × 0.44** |
| `in` chuck | ⌀320 | **0.32 × 0.32** |
| `door-1` | 1800 폭 | **1.89 × 0.32** (문틀 포함) |

상자는 **월드 축 정렬**이다. 우리 회전이 90° 단위뿐이라 그게 곧 돌아간 발자국이다.
자유 각도를 쓰게 되면 그때 로컬 상자로 바꾼다 — 지금 하면 안 쓰는 코드다.

## 물체를 빛나게 하는 길은 막혀 있다

`parts.js` 의 재질은 **전 부품이 공유**한다 (`M.body` 하나를 열여섯 부품이 쓴다).
하나를 `emissive` 로 물들이면 **그 재질을 쓰는 게 전부 빛난다.** 인스턴스마다 복제하면
공유 규약이 깨지고 재질 수가 배로 는다. `OutlinePass` 는 `EffectComposer` 파이프라인이
필요한데 이 화면엔 없다 — 그 하나를 위해 후처리 사슬을 들이지 않는다.

## thebuggeddev/anatomy 에서 본 것

소스를 받아 `app/lib/three/hotspots.ts` (371줄) 를 읽었다. README 에는 없다.

| 기법 | 우리에게 |
|---|---|
| **화면좌표 피킹** — 마커를 투영해 24px 안에서 가장 가까운 것. 메시 레이캐스트 안 함 | **터틀봇이 가구 뒤에 가려 안 잡히던 문제의 답.** 아직 안 넣었다 (GAP OPEN) |
| **선택 펄스 4.5초 후 정지** (`PULSE_SECONDS`) | 눈길은 끌되 렌더러를 계속 깨우지 않는다. 안 넣었다 — 지금은 윤곽만으로 충분하다 |
| `sizeAttenuation:false` + `setPixelSize` | 줌과 무관하게 화면상 크기 고정. 우리 윤곽은 월드 크기가 곧 정보라 안 맞는다 |
| `polygonOffset` + 깊이 버퍼 가림 | 우리는 `depthTest:false` 로 항상 위에 그린다 — 바닥 표식이라 가려지면 안 된다 |

# 4차 — 격벽 반짝임의 진짜 원인 (2026-08-04)

2차에서 "고쳤다"고 적은 것이 **덜 고친 것**이었다. 주인님이 다시 지적했다.

```
본체  y 0 ~ hMm         ← 윗면 y = hMm
캡    y hMm-90 ~ hMm    ← 윗면 y = hMm    ← 같은 평면
```

2차에서 옆면(x·z)만 어긋나게 하고 **윗면을 그대로 뒀다.** 두 면이 정확히 같은 높이면
깊이 버퍼가 앞뒤를 못 정해 카메라가 움직일 때마다 픽셀 단위로 승자가 바뀐다 —
그게 반짝임이다. **재질 문제가 아니다** (`M.dark` 는 metalness 0.2 로 얌전하다).

캡을 **세 방향 전부** 키워 본체 밖으로 내밀었다 (`lengthMm+30 · capH+8 · tMm+30`).
실제 코핑도 그렇게 생겼다.

## 눈으로 두 번 놓쳤으므로 규약에 적었다

일회성 진단 스크립트로 부품 16종의 자식 상자를 전수 대조했다 — 두 상자가 **어느 축의
같은 쪽 면이 정확히 일치하고 나머지 두 축이 겹치면** 후보다. `blastWall` 은 이제
`y.min=0` 1건만 남는다 (본체·기초의 바닥면 — 바닥 슬래브가 덮어 안 보인다. 모든 부품이 같다).

**게이트로는 안 만들었다.** 다른 부품에서 30~70건씩 나오는데 대부분 무해하다
(안쪽에 파묻힌 면·서로 등을 맞댄 면). 걸러내려면 포함관계까지 풀어야 하고,
시끄러운 게이트는 결국 아무도 안 본다. 대신 `parts.js` 조립 규약에 한 줄 넣었다 —
**"두 조각의 겉면을 같은 평면에 두지 마라."**

## 확인하지 않은 것

- 다른 부품에도 같은 종류가 남아 있다 — 진단 스크립트가 후보를 내지만 어느 것이 실제로
  보이는 면인지는 안 걸렀다. 반짝이는 게 눈에 띄면 그때 같은 방법으로 잡는다

# 5차 — 우클릭 메뉴 · 객체 복제 · 단축키 (2026-08-04)

그림: `context-menu.png`

## `복제` 가 무엇을 복제하는지 안 보였다

`복제` 버튼은 **배치안(맵) 전체**를 복사하는 것이었는데, 이름만 보면 고른 물건을 복사하는
것으로 읽힌다. 게다가 **물건 복제는 아예 없었다.**

- 씬 버튼을 `배치안 복제` · `배치안 삭제` 로 못 박았다 — 무엇에 대한 동작인지 이름에 넣는다
- **물건 복제를 만들었다.** 우클릭 메뉴와 `Ctrl+D`

소품은 200mm 비껴 놓는다 — 정확히 겹쳐 놓으면 새로 생긴 게 안 보여서 "안 눌렸나" 싶어
또 누르게 된다. 문·창은 벽 위에서 폭만큼 비키고 벽 끝에서 잘린다. AMR 은 도킹 자리를 옮긴다.

## 우클릭 메뉴가 단축키를 가르친다

복제 · 90° 회전 · 되돌리기 · 삭제 넷을 **단축키와 함께** 적었다. 단축키는 전부터 있었지만
아무 데도 안 적혀 있어서 아무도 몰랐다 — 메뉴가 그걸 알려주는 자리다.

- 우클릭은 **고르기도 같이 한다.** 안 그러면 다른 게 선택된 채 메뉴만 떠서 어느 것에 대한
  메뉴인지 알 수 없다
- **빈 곳 우클릭은 브라우저 기본 메뉴를 그대로 둔다** — 새로고침·검사를 막지 않는다
- `Esc` 로 선택 해제를 추가했다

## 실제로 눌러서 나온 값

```
버튼: 이름 | 배치안 복제 | 배치안 삭제
메뉴: benchRun / 복제 Ctrl+D / 90° 회전 R / 되돌리기 Ctrl+Z / 삭제 Del
우클릭 복제 → 소품 17 → 18 · 새 것이 선택됨(benchRun-3) · 메뉴 닫힘
Ctrl+D      → 소품 18 → 19
Esc         → 선택 null
```

**첫 판에서 메뉴가 화면 밖으로 나갔다** — `clientX/Y`(뷰포트 기준)를 3D 컨테이너 안에
그대로 얹어서, 팔레트 폭·머리글 높이만큼 밀렸다. 캔버스 기준 좌표로 바꿨다.

## 확인하지 않은 것

- **폰에는 우클릭이 없다.** 길게 누르기가 `contextmenu` 로 오는지 안 봤다 (iOS 는 안 올 수 있다).
  폰에서는 `90° 회전` 버튼과 `삭제` 버튼이 여전히 유일한 길이다 (GAP OPEN)
- 메뉴가 `pointerleave` 로 닫힌다 — 대각선으로 움직이다 잠깐 벗어나면 닫힌다. 손으로 써 봐야 안다

# 6차 — 편의 기능 4개 (2026-08-04)

그림: `edit-guide.png` (끄는 중 가이드 선 + `틈 200 · 1275mm`)

## ① 치수 가이드 — 좌표가 아니라 **틈**이 알고 싶은 값이다

끄는 동안 **가장 가까운 벽·이웃까지의 빈 거리**를 내고 바닥에 선을 긋는다.
"이 벤치를 벽에서 800mm 띄우자" 가 지금까지는 좌표를 역산해야 나왔다.

3D 글자는 안 쓴다(비싸다) — 선만 3D 로 긋고 **숫자는 `onPick` 으로 보내 DOM 패널이 적는다.**
축마다 **더 가까운 쪽 하나**만 그린다. 양쪽을 다 그리면 화면이 선으로 덮인다.

## ② 가려진 것도 잡힌다 — 단, **작은 것만 도와준다**

레이캐스트 먼저, 커서가 어떤 물건 **가운데에서 20px 안**이면 그쪽을 준다
(`thebuggeddev/anatomy` `hotspots.ts` 의 `pick()` 과 같은 발상).

**처음엔 크기를 안 가렸다가 부작용이 났다** — 벤치(5.0m)와 그 위 상부장(4.6m)처럼 가운데가
가까운 큰 것끼리 서로 클릭을 훔쳤다. 큰 물건은 어디를 눌러도 레이캐스트로 잡히므로
도와줄 이유가 없다. **최대 변이 1m 미만일 때만** 근접 규칙을 쓴다.

```
amr1 → amr1   amr2 → amr2   in(⌀320) → in        ← 전에는 앞의 가구가 잡혔다
runN → runN   wcN  → wcN    island   → island    ← 큰 것끼리 안 훔친다
```

## ③ 방 밖으로 못 나간다

발자국 반쪽만큼 안쪽에서 멈춘다. **단일과 다중을 한 길로 합쳤다** — 처음엔 단일만
클램프했더니 여럿을 함께 끌 때 방을 넘어갔다(y=9200). 지금은 **묶음 전체의 상자**로
이동량을 자른다.

좌표를 `Math.round` 로 못 박았다 — 클램프가 격자 밖 값을 내는데 그대로 두면 저장분에
`9700.000047` 같은 숫자가 남는다 (하드 룰 5).

## ④ 다중 선택 — Shift+클릭

같은 거리만큼 함께 움직이고, **되돌리기는 한 덩어리**다.

```
island·convOut 둘 선택 → 끌기 → 이동량 [[800,-200],[800,-200]] · 되돌리기 +1
```

**묶어 놓고 끌면 묶음이 풀리는 버그**가 있었다 — 끌기 시작의 평범한 클릭이 묶음을 지웠다.
이미 묶인 것을 잡으면 유지한다.

## ⑤ 물건 크기 조절

부품마다 인자 이름이 다르다 (`lengthMm` · `wMm` · `diaMm`). `catalog.js` 의 **`SIZE_MM`**
이 무엇을 보여줄지 정하고, 값은 그 물건의 `opts` 로 간다.

```
runN 선택 → 칸: 길이=5000 · 깊이=700 · 높이=950
길이 → 3000 → opts {lengthMm:3000} · 윤곽 5.0 → 3.0
```

**현재 값은 재서 보여준다.** 팩토리 기본값은 코드 안에만 있어 화면이 모른다. 서명을
문자열로 파싱하는 길도 있지만 **압축 빌드에서 인자 이름이 바뀌어** 개발에선 되고 배포에선
깨진다 — 그 종류의 버그는 안 만든다. `sizeMmOf()` 가 실제로 만들어 재고 캐시한다.

**게이트가 두 개를 잡았다** — 크기 키가 실제로 형태를 바꾸는지 검사하자마자:
- `chair({hMm})` 는 **인자를 받기만 하고 한 번도 안 썼다.** 서명이 거짓말이었다 → 지웠다
- 처음 검사가 상자 *크기*만 봐서 `wallCabinet.baseMm`(위치를 올리는 손잡이)을 죽은 키로
  오판했다 → 상자 **전체**(min·max)를 보게 고쳤다

## 딸려 나온 수리

**배치안이 바뀌면 3D 노드가 통째로 새로 만들어진다.** 선택 표식이 죽은 노드를 가리켜
크기를 바꿔도 윤곽이 옛 크기로 남았다 → `reselect(ids)` 로 id 를 다시 잡는다.
위치만 고칠 때는 새 노드가 같은 자리라 **증상이 안 보였다** — 크기를 넣고서야 드러났다.

## 확인하지 않은 것

- **손으로 안 눌렀다.** 전부 합성 이벤트다
- **폰에서 안 봤다.** Shift 도 우클릭도 없다 — 폰의 다중 선택·메뉴는 길이 없다
- 높이 칸이 `950` 으로 뜬다 — 벤치 뒷턱이 상판보다 50mm 높아 **잰 값이 인자보다 크다.**
  한 번 고치면 `opts` 값이 정본이 되어 어긋남이 사라진다. 첫 표시만 근사다
