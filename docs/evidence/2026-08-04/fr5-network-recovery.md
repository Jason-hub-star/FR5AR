# 실기 재연결 — 로봇이 아니라 우분투 랜 설정이 범인이었다

분류: **증거**. 2026-08-04 오후. 주소 셋이 한 세션에 바뀌었고, 그 과정에서 얻은 실측 넷.

## 무엇이 문제였나

`/우분투` 가 0단계에서 멈췄다. 처음 판정은 "우분투가 꺼졌다" 였는데 **틀렸다** — 맥과
우분투가 서로 다른 `/24` 에 있었을 뿐이다. 그 뒤로도 판정이 두 번 더 뒤집혔다.

| 시점 | 관측 | 그때 내린 판정 | 실제 |
|---|---|---|---|
| 시작 | `192.168.10.49` 무응답 | "PC 가 꺼졌다" | 맥 `30.9` · 우분투 `40.4` — **망이 갈렸다** |
| 중간 | 로봇 포트 전부 닫힘 · `GetSoftwareVersion=-4` | "펜던트가 막았다" | **아무도 안 듣고 있었다** (랜 IP 소실) |
| 중간 | 10초간 수신 0패킷 | "선 반대편에 로봇이 없다" | **조용한 구간만 봤다** — 688KB 를 받던 연결이 있었다 |
| 끝 | — | — | **`enp3s0` 이 DHCP 라 주소를 반납했다** |

**근본 원인** — 로봇 쪽 랜 프로필이 `ipv4.method: auto` 였다. 로봇은 DHCP 서버가 아니므로
주소를 못 받고, NetworkManager 가 **가지고 있던 주소까지 반납한 뒤 장치를 내려놨다.**
그러면 `192.168.57.0/24` 로 가는 경로가 사라지고 모든 패킷이 **와이파이 게이트웨이로 샌다**:

```
192.168.58.2 via 192.168.30.1 dev wlx…   ← 로봇 반대 방향
```

## 판정을 뒤집은 계측

추측을 세 번 접게 만든 것은 전부 커널이 들고 있던 숫자다.

- `ss -tni` 의 **`bytes_received:688024` · `lastrcv:282465`** — "죽었다" 가 아니라
  **"4분 45초 전까지 살아 있었다"**. 좀비 소켓과 진짜 단절을 가른다
- `minrtt:0.149ms` 가 앞서 잰 ping 값과 일치 — **같은 상대**임을 증명
- `carrier_up_count/down_count = 6/6` — 선이 여러 번 뽑혔다 꽂혔다
- `statistics/rx_packets` 증가량 — 링크(1000Mb/s)는 살아도 **말은 안 한다**를 구분

**교훈** — `ping` 실패는 "장치 없음" 이 아니다. ICMP·ARP·TCP·링크·수신량을 따로 봐야
"꺼짐 / 다른 망 / 경로 없음 / 조용함" 이 갈린다.

## 확정된 값

| 항목 | 값 | 근거 |
|---|---|---|
| 우분투 | **`192.168.30.240`** (와이파이 고정) | 인터넷 정상 확인 |
| 로봇 | **`192.168.57.2`** | `20003`·`20004`·`8080` 전부 열림 + 연결 성공 |
| ⚠ 랜선 자리 | **컨트롤러 1번 포트** | **비상정지 박스 쪽 포트에 꽂으면 로봇이 `192.168.58.2` 로 보인다** |
| 우분투 유선 | `192.168.57.10/24` + `192.168.58.10/24` | 두 자리 모두 대비 |

`58.2` 는 FAIRINO 공장 기본값이다. 같은 로봇이 **꽂는 포트에 따라 다른 주소로 보인다** —
`config.yaml` 에 경고로 적었다.

## 실기로 닫힌 것 둘

**① 조종권 토큰이 실기에서 왕복했다** (D55 · 어제는 mock 뿐이었다) —
`claim` → 토큰 발급 → 그 토큰으로 `release` 성공.

**② "읽기는 공존한다" 가 실측이 됐다.** 로봇은 **서보 ON · 모드 1(수동)** 상태였다 —
펜던트 세션이 남긴 상태다. 그 위에 우리가 `OBSERVE_ONLY` 로 붙어 관절값을 읽었고
아무것도 깨지지 않았다. 포트가 갈리는 것도 확인했다:

```
펜던트 웹앱 → 로봇 :80 · :9999
우리 브리지 → 로봇 :20003(명령) · :20004(상태)
```

읽은 값 — 관절 `[-58.86, -94.08, 90.89, -84.97, -92.90, 16.51]` ·
TCP `[87.5, -151.1, 18.1]` mm · 안전 플래그 전부 정상.
2초 간격 3회에서 J4 가 `-84.97 → -84.98` 로 미세하게 떨린다 — **캐시가 아니라 실시간**이다.

**그리고 20분 뒤, 로봇이 실제로 움직인 것이 읽혔다.**

```
15:14  [ -58.9, -94.1,  90.9,  -85.0, -92.9, 16.5]
15:37  [-154.7, -80.0, 126.8, -133.6, -89.7, 23.4]   ← J1 이 96° 움직였다
```

**우리는 그 사이 어떤 명령도 보내지 않았다** (`OBSERVE_ONLY` 는 구조적으로 못 보낸다).
사람이 펜던트로 움직인 것이다. 즉 **펜던트가 로봇을 조작하는 동안 우리 읽기가 계속
살아 있었고, 그 움직임이 우리 화면 값에 그대로 들어왔다.**

정지 상태 공존이 아니라 **조작 중 공존**이 확인된 것이다 — 이게 오늘 얻은 가장 강한 값이다.

## 확인하지 않은 범위

- **쓰기가 배타인가는 못 쟀다.** 동료가 웹앱을 닫아 경쟁 상대가 없었다.
  펜던트가 **작업 중일 때** 우리가 `20003` 을 잡으면 어떻게 되는지가 진짜 질문이고,
  그건 동료 동의를 받고 재야 한다 (GAP OPEN)
- **유선 고정이 아직 안 굳었다** — 주소는 붙었지만 저장된 `ipv4.method` 는 여전히 `auto` 로
  되밀린다. 지금은 `connecting (getting IP configuration)` 상태로 위태롭게 붙어 있다.
  netplan 파일(`99-robot-lan.yaml` · `dhcp4: false`)로 못 박는 것이 남았다 (GAP OPEN)
- ARM 하지 않았다 — 서보를 올리는 것은 사람이 옆에 있을 때 화면에서 (하드 룰 3)
- 충돌 감지가 실제로 반응하는지는 여전히 미검증 (D53 의 진짜 완료 판정)
