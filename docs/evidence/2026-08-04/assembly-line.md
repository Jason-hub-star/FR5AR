## 탄두는 안 움직인다 — 해체 셀 재설계 (2026-08-04, 5차)

그림: `cell-v2.png` (셀 근접 · 15초 · 팔 2대)

### 무엇이 틀렸었나

전 판은 작업물이 `store → in → meas → out` 을 **떠다녔다.** 실제 해체는 반대다 —
**지그가 탄두를 밑에서 물어 공중에 세워 잡고, 팔이 측면에서 축을 맞춰 접근해 손목(j6)을
돌려 유도부를 풀어낸다.** 탄두가 흔들리면 그 작업 자체가 성립하지 않는다.

주인님이 준 도면이 그걸 말하고 있었고, 화면은 반대로 그리고 있었다.

### 계약이 먼저 (하드 룰 1)

`SHARED-CORE.md` — **`arm` 하나 → `arms[]`**. 해체 셀에 투입·배출 컨베이어가 붙으면서
이송을 맡는 팔이 따로 서는데, 단일 필드로는 못 적는다.

| 칸 | 뜻 |
|---|---|
| `role: 'process'` | 해체 — **실물이 있다.** FR5 한 대뿐이고 게이트가 그걸 강제한다 |
| `role: 'transfer'` | 이송 — **실물이 없다.** `model` 을 FR5 로 두면 검증이 실패한다 |

⚠ 같은 모형을 둘 세우면 **어느 쪽이 진짜인지 화면이 말하지 못한다.** 그래서 이송팔은
형태부터 다르게 그린다(관절형 6축이 아니라 기둥+수평붐 갠트리형)이고, 도달 링도
파랑(`--c-info` = 시뮬레이션)이다. 실측 수치를 이 팔에 붙이지 않는다.

**옛 배치안은 읽을 때 자동으로 배열이 된다** — `migrateLayout()` 한 곳에서만 (하드 룰 5).
저장소에서 나오는 길목이 `datasource` 하나뿐이라 화면과 게이트는 언제나 지금 모양만 본다.

### 새 셀 — U자 흐름

```
   [투입 ▶▶▶ 동쪽으로]  y=3050
                 ╲
       이송팔(5200) ──▶ [지그 6000] ◀── FR5(6800)     ← 탄두 축이 한 직선
                 ╱                          모두 y=4000
   [◀◀◀ 배출 서쪽으로]  y=4950
```

**팔 자리가 자유변수가 아니다.** 탄두 축 위, 노즈 쪽에 FR5 가 선다 — 지그까지 800mm
(도달 922, 여유 122). 이송팔은 반대편에서 두 컨베이어 끝(각 955mm)과 지그(800mm)를
전부 1000mm 안에 둔다.

**투입과 배출이 반대 방향**이다. 들어오는 줄과 나가는 줄이 갈려야 라인으로 읽힌다.

`sort`(분리물 트레이) 스테이션은 **뺐다** — 해체 조각을 개체로 두지 않기로 했고,
섬 위에서 지그·FR5 베이스와 자리를 다퉜다.

### 실제로 눌러서 나온 값 — 31/31

```
팔이 두 대 선다              {"fr5":180,"tf1":-80}   fr5 = URDF · tf1 = 절차적
작업물이 무대에 선다          0s  [5100, 3050] 0단계    ← 투입 컨베이어 끝
해체 중 탄두가 고정된다       6s  [6000, 4000]
                            21s [6000, 4000]        ← **한 mm 도 안 움직인다**
탄두가 단계별로 쪼개진다      0s=0 · 15s=1 · 26s=3
투입에서 배출까지 자리가 바뀐다 [5100,3050] → [5100,4950]
투입 중엔 이송팔만 돈다       fr5=180°(제자리) tf1=−80°(탄두 쪽)
지그 작업 중엔 FR5 가 지그를 본다 fr5=180° tf1=0°
```

**`해체 중 탄두가 고정된다` 가 이번 재설계의 판정이다.** 6초와 21초의 좌표가 같은 값이어야
하고, 실제로 같다.

**닿는 팔만 돈다** — 투입 컨베이어의 탄두를 FR5 가 쳐다보고 있으면 라인이 거짓말을 한다.
자기 `reachMm` 안일 때만 돌고 아니면 세운 자세로 돌아온다.

### 옛 저장분을 실제로 심어 봤다

`localStorage` 에 **옛 모양**(`arm` 하나 · `current` 포인터)을 손으로 넣고 열었다.

```
열렸나   scenes 1 · name "옛 배치안" · saveErr false
팔 모양  [{ id:'fr5', role:'process', model:'FR5', baseYawDeg:45, reachMm:922 }]
콘솔오류 0
```

`id` 와 `role` 이 없던 자리에 채워졌고 나머지 값은 그대로다. 사람이 저장분을 고칠 일이 없다.

### 게이트가 잡은 것

- **`sort` 트레이가 떠 있었다** — 섬(깊이 1000) 밖으로 190mm 나갔다. 게이트가
  `받칠 것 없이 떠 있다` 로 잡았고, 결국 그 스테이션을 뺐다
- 컨베이어 y 를 3100/4900 → **3050/4950** 로 물렸다. 섬과 10mm 물리는 자리였다

`scripts/check/layout.sh` 에 **팔 규약 검사**가 붙었다 — 팔 id 중복 · `basePosMm` 모양 ·
`reachMm` · **실물 팔이 둘 이상이면 실패** · 이송팔에 FR5 모형을 달면 실패.

### 확인하지 않은 것

- **손으로 안 눌렀다** · **폰에서 안 봤다** (GAP OPEN 유지)
- **j6 회전은 그림이 아니라 글자다** — 화면에 "j6 회전 · 분리 중" 이 뜨지만 실제로
  손목이 도는 것은 안 그린다. 6축 궤적은 시연 녹화가 있어야 한다 (GAP OPEN)
- **컨베이어 위 탄두는 안 흐른다** — 놓인 소품이다. 흐르게 하려면 series 가
  컨베이어 시간을 선언해야 한다
- `compareA`/`compareB` 는 **옛 무대 그대로** 두었다 — 팔 위치 하나만 다른 비교라
  U자 흐름을 넣으면 그 비교가 흐려진다
- `scripts/check/layout.sh` 실행 중 `clutter: command not found` 잡음이 있다.
  판정에는 영향이 없지만 **이전부터 있던 것**이고 heredoc 이 백틱을 삼키는 자리다

## 일직선 라인 — 9:16 방 · FR5 두 대 · 리프터 (2026-08-04, 6차)

그림: `line-cell.png` (셀 근접 · 팔 선택 상태) · 레퍼런스 `lifter-ref.png`(저장소 밖)

### 무엇이 바뀌었나

| | 전 | 지금 |
|---|---|---|
| 방 | 12000 × 8000 (가로) | **6750 × 12000 — 정확히 9:16 (세로)** |
| 컨베이어 | 두 줄, 셀 옆을 지남 | **한 줄이 방을 관통해 밖으로 나간다** |
| 낮은 끝 | 없음 | **램프 2600mm 에 걸쳐 620mm 내려온다** |
| 고정 | 회전 척 | **리프트 클램프** (신규 부품) |
| 팔 | FR5 1 + 이송팔 1 | **FR5 2대**, 리프터를 마주 본다 |
| 팔 편집 | 불가 | **고르고 옮기고 되돌린다** |

**방이 9:16 인 이유가 컨베이어다.** 라인이 한 줄로 서서 방을 관통하려면 긴 축이 필요하고,
정사각에 가까운 방에서는 그 줄이 안 선다.

```
남(y=0)                                                       북(y=12000)
┌ 벽 ──────────────────────────────────────────────── 개구부 ─┐
│ AMR ▸ [▁▂▃ 램프] ═══ 컨베이어 ═══[리프터]═══ 컨베이어 ═══▶ 밖
│                          FR5-A ◀   ▶ FR5-B
└──────────────────────────────────────────────────────────────┘
```

### 램프 — AMR 은 900mm 위로 못 올린다

`conveyor` 가 `rampMm`(경사 구간의 수평 길이)·`dropMm`(그 구간에서 낮아지는 높이)를 받는다.
남쪽 끝이 **280mm** 까지 내려오므로 AMR 은 밀어 넣는 것으로 끝나고 나머지는 경사가 한다.

레일은 두 토막(평평 + 기운 것)이고 롤러 높이는 `topAt(x)` 하나가 정한다.
**크기 손잡이(`SIZE_MM`)에는 안 넣었다** — 램프는 겉상자를 안 바꿔서 게이트의 "죽은 키" 검사에
걸린다. 죽은 키가 아니라 **상자를 안 바꾸는 키**라 그 목록에 넣는 게 틀린 것이다.

### 리프트 클램프 — 새 부품

Codex 레퍼런스 → 절차적 코드. 형태의 정체는 셋이다 — **양쪽 승강 기둥(볼스크류+리니어 레일) ·
그 사이를 오르내리는 크로스바 · 크로스바 위의 V블록 한 쌍.** 이 셋이 없으면 그냥 받침대로 읽힌다.

**첫 판이 규약을 어겼다** — 옆 클램프가 `wMm` 을 **270mm 넘어** 배치안에서 옆 물건과 겹쳤고
게이트가 잡았다(`padA ↔ lift`). 인자가 곧 발자국이어야 겹침 검사·크기 칸이 같은 숫자를 본다.
지금은 700·900·1200 어느 값이든 bbox 가 정확히 그 값이다.

**회전 척은 안 지웠다** — `compareA/B` 프리셋이 아직 쓴다. 새 라인에서만 안 쓴다.

### 팔이 편집 단위가 됐다

`userData.item = { kind: 'arm', … }` 을 팔 자리에 달았다. 잡는 자리는 **받침대 하나**다 —
URDF 전체를 피킹 대상으로 두면 팔이 커서 뒤의 물건을 전부 가린다. 도달 링과 URDF 는
`raycast` 를 껐고, 선택 윤곽은 `fitFrom` 으로 받침대만 잰다(안 그러면 윤곽이 1.8m 가 된다).

**받침대를 팔이 직접 든다.** 처음엔 배치안 소품(`bench`)을 밑에 깔았는데, 같은 자리에
편집 단위가 둘이라 **팔을 누르면 받침이 잡혔다**(실렌더가 잡았다). 지금은 `basePosMm[2]`
하나가 받침 높이를 정하고, 팔을 옮기면 받침이 따라온다.

### 실제로 눌러서 나온 값 — 31/31

```
fr5a 클릭        → "FR5 fr5a / FR5"  · x 2495 · y 6000 · 회전 0
x 를 2200 으로   → fr5a@2200,6000,850   (z 는 안 건드린다)
⌘Z              → fr5a@2495,6000,850
FR5 가 두 대 선다  {"fr5a":0,"fr5b":180}
도달 밖이면 안 돈다  투입 자리(y=1500)에서 두 팔 다 세운 자세
리프터를 마주 본다  fr5a=0° fr5b=180°
해체 중 고정      10s [3375,6000] = 22s [3375,6000]
투입 → 배출       [3375,1500] → [3375,11200]
탄두 단계         0s=0 · 14s=1 · 29s=3
```

숫자줄 — `팔 fr5a 922mm · fr5b 922mm · 투입(낮은 끝), 실험실 밖으로, 공급 보관대는 팔이 안 닿아요`.
**세 자리가 일부러 도달 밖이다** — 그게 컨베이어와 AMR 이 있는 이유다.

### 게이트가 잡은 것 셋

1. **리프터가 발자국을 270mm 넘었다** (위)
2. **팔이 리프터에 안 닿았다** — 평면 875mm 였는데 팔은 750 대 위, 탄두는 1050 공중이라
   실제 거리가 942 로 922 를 넘었다. **평면 거리만 재면 틀린다.** 880·850 으로 조정해 902
3. **게이트가 화면과 다른 규칙을 썼다** — `baseMm` 은 프롭이 실제 놓이는 높이인데 게이트는
   `posMm[2]` 만 봐서 **바닥에 선 리프터를 "떠 있다"** 고 잡았다. 화면 쪽 규칙으로 맞췄다

### 확인하지 않은 것

- **손으로 안 눌렀다** · **폰에서 안 봤다**
- **팔 받침대가 겹침 검사에 안 들어간다** — 팔은 `props` 가 아니라 `arms` 라 바닥 겹침
  검사 밖이다. 받침을 소품 위에 겹쳐 세워도 게이트가 조용하다 (GAP OPEN)
- **컨베이어 위 탄두는 안 흐른다** · **j6 회전은 글자로만 뜬다** (아래 참조)
- 램프 경사에서 탄두가 **기울어 놓이지 않는다** — 소품이라 수평 그대로다

## 공정을 조립으로 뒤집었다 + 내보내기 (2026-08-04, 9차)

그림: `assembly-line.png` (36초 · 크레인이 완성품을 배출 컨베이어로)

### 문서가 안에서 갈라져 있었다

D50 은 **"데모 과제는 페트병 뚜껑 체결 · 화면은 미사일 조립"** 이라 적었는데 D51 이 무대를
**"해체 라인"** 으로 잡았다. 그 뒤 코드가 전부 해체 쪽으로 갔다. **주인님 확인으로 조립이
정본이다** — D50 쪽이 맞았다 (D63).

고친 SSOT — `PRD.md`(8곳) · `MILESTONES.md`(5곳) · `SHARED-CORE.md`(9곳) · D51 제목.
**하드 룰 1 대로 문서를 먼저 고치고 코드를 짰다.**

**`warhead` 팩토리는 안 고쳤다.** `stage` 는 원래 **완성도**였고(0 완성 · 3 빈 케이싱),
조립은 그 값을 **3 → 0 으로 읽는 것**뿐이다. 같은 값을 두 이름으로 부르지 않는다.

### 흐름

```
팔레트 ─fr5b─▶ 램프(낮은 끝) ═convA═▶ 리프터(공중 고정) ◀fr5a─ 신관 트레이
                                          │ 조립 3→0
                                   크레인이 든다 ─▶ convB ─▶ 밖으로
```

**팔 둘의 역할이 갈린다 — 기하학이 시킨 것이다.** 한 팔이 팔레트와 리프터를 동시에 못 잡는다
(도달 922mm 인데 그 둘은 4.6m 떨어져 있다). 게이트가 도달 **4/6** 으로 확인한다 —
`pile`·`load` 는 투입 팔, `lift`·`fuze` 는 조립 팔, `ship`·`exit` 는 일부러 밖(크레인·컨베이어 몫).

### 크레인은 축이 둘이다

**트롤리는 거더 위(x), 브리지는 레일 위(y).** 리프터 → 배출은 **y 이동**이라 트롤리만
움직이면 크레인이 가만히 있다 — 첫 판이 정확히 그랬다(32~38초에 트롤리 x 가 계속 0).
브리지를 부분그룹으로 떼어 레일을 따라 달리게 했다.

```
20s [트롤리 0, 브리지 -800]   ← 리프터 위
39s [트롤리 0, 브리지 +1700]  ← 배출 컨베이어 위
```

매 프레임 크레인 30개 메시를 다시 만들지 않는다 — `userData.crane` 에 손잡이만 실어 준다.

### 내보내기 · 가져오기

저장이 브라우저 한 대라(D46 전까지) **팀원에게 배치안을 넘길 길이 아예 없었다.**
팀 공유 저장소가 붙기 전까지의 다리다.

- **새 형식을 안 만든다** — 배치안 전문 그대로다. 그래야 가져오기가 스키마 하나만 본다
- **가져오기는 새 씬으로** 들어온다. 열려 있는 배치안을 안 건드린다 — 잘못된 파일을 골라도
  잃는 게 없어야 한다
- **스키마를 반드시 본다.** 아무 JSON 이나 받으면 화면이 그 자리에서 죽는다
- 옛 모양(`arm` 하나)은 **읽는 길목과 같은 함수**로 올린다 (하드 룰 5)


  기준 보정은 안 넣었다 (GAP OPEN)
- **충돌을 안 본다** — 사람이 만든 자세가 다른 팔·소품과 부딪히는지 판정하지 않는다

- **주인님의 "맵 1" 은 여전히 못 봤다** — 브라우저 안에 있다. 내보내기 버튼이 그 길이다
