## 편집기 — 고르기·끌기·돌리기 — 관제화면 편집기 — 실렌더 검증 (2026-07-31)

배치안 3D 를 **에디터처럼** 만들었다 (참고: `Jason-hub-star/ArduinoDT`).
아래는 전부 브라우저에서 실제로 재본 값이다. "될 것이다" 는 없다.

주소 — **https://fr5dashboard.vercel.app** (공개 별칭)
배포별 URL `fr5dashboard-4qblc1om8-…vercel.app` 은 302 — 로그인 벽. [[fr5web-deploy-alias]] 그대로다.

### 고친 버그 넷 — 전부 **측정으로** 찾았다

#### ① 끌면 카메라가 55m 밖으로 날아갔다

물체 좌표 계산은 **맞았다** (재현: 결과 3.18/5.59 · 기대 3.2/5.6).
콘솔로 카메라를 찍어 보니 `[55.29, 23.58, 41.85]` — OrbitControls 가 같은
`pointerdown` 으로 궤도를 시작했고, 화면 좌표가 캔버스 밖(`-341, 914`)이 됐다.

원인은 **끄는 시점**이었다. `stage.onTick(() => controls.enabled = !edit.isDragging())`
는 **다음 프레임**에 돈다. OrbitControls 가 먼저 등록돼 있어 이미 늦었다.

→ 리스너를 **캡처 단계**로 걸고, 물체를 집은 그 자리에서 `controls.enabled = false`
+ `stopPropagation()`. 측정: `카메라_안움직임: true`.

#### ② 물건을 놓을 때마다 시점이 기본값으로 돌아갔다

`LayoutView` 의 `useEffect` 가 `[layout]` 에 걸려 있어, 커밋 → `layout` 새 객체 →
**무대를 통째로 다시 만듦** → 카메라 리셋. 편집 중에 이러면 못 쓴다.

→ 효과를 둘로 쪼갰다. **무대(카메라 포함)는 마운트에 한 번**, 내용물만 갈아끼운다.
시점 맞추기는 배치안 id 가 바뀐 첫 순간에만.

측정 — 카메라를 `[3, 14, 22]` 로 일부러 틀어 놓고 물건 하나를 옮긴 뒤:

| 항목 | 값 |
|---|---|
| 시점 유지 | **true** (`3,14,22` 그대로) |
| 무대 재생성 안 됨 | true |
| ch1 이동 | `1150, 3400` → `2000, 4600` (기대 1950 → 격자 100mm 스냅 2000) |
| 되돌리기 | (1) |

#### ③ 링·좌표가 부모 좌표계와 섞여 있었다

호버·선택 링은 `scene` 에 직접 붙는데 물체의 **로컬** `position` 을 썼다.
지금은 방 그룹이 평행이동뿐이라 상수가 상쇄돼 맞아 보였다 — **회전·스케일이 하나만
끼면 조용히 틀린다.** `getWorldPosition` 과 `parent.worldToLocal` 로 명시했다.

#### ④ 배치안을 갈면 아무것도 안 골라졌을 것이다

`pickRoot` 를 값으로 잡아두면 A↔B 전환 뒤 **죽은 그룹을 계속 겨눈다.**
함수로 받아 매번 현재 내용물을 묻는다.

### 폰

| 항목 | 값 |
|---|---|
| `touch-action` | `none` (안 끄면 페이지가 스크롤되며 `pointercancel` 로 끌기가 끊긴다) |
| 터치 끌기 | **된다** — hood1 `5600,7550` → `6100,8400` (100mm 격자) |
| 시점 유지 | true |
| 세로 스크롤 | 없음 |
| 픽셀비 | 좁은 화면 **1.5** (기본 2) — 흰색 모형이라 계단이 잘 안 보인다 |
| 회전 | **버튼**으로도 된다 (`90 → 180`). 폰에는 키보드가 없다 |

레이아웃은 `calc(100vh - 104px)` 매직넘버를 **없앴다**. 폰에서 머리글이 두 줄이 되는
순간 숫자줄이 화면 밖으로 밀렸다. 플렉스로 바꾸고 **`#root` 를 뚫었다** —
React 가 끼워 넣는 `#root` 에 높이를 안 주면 3D 칸이 0 이 되고, 절대배치한
힌트·패널이 머리글 위로 겹쳐 올라온다 (스크린샷으로 확인한 뒤 고쳤다).

### 아직 아닌 것

- **편집 결과가 저장되지 않는다.** React 상태에만 있다 — 새로고침하면 사라진다.
  슬롯형 config (`H` 단계) 에서 `Shared/data/config/` 로 내린다
- 배포는 **로컬 빌드 산출물 업로드**다. 모노레포 workspaces 는 하위 폴더에서
  `npm install` 이 안 풀린다 — Vercel 빌드로 옮기려면 루트 기준 설정이 따로 필요하다
- `dist` 7.2MB 중 6.6MB 가 **아직 안 쓰는** URDF·그리퍼 STL 이다
  (`publicDir` 이 `Shared/assets` 전부를 복사한다). L2 에서 팔을 세울 때 쓴다

### 실렌더가 잡은 결함 둘 — 코드로는 안 보였다

#### 1. 폰에서 저장 배지가 3D 를 44px 먹었다

`아직 저장되지 않았어요` 배지가 늘면서 머리줄이 **두 줄로 접혔다.**

| | 편집 전 | 편집 중 |
|---|---|---|
| 고친 뒤 | 캔버스 415px · 머리줄 48px | **415px · 48px** |
| 고치기 전 | 캔버스 467px · 머리줄 48px | 423px · **92px** |

고친 방법 — **폰에서 `배치안 편집` 제목을 숨겼다.** 바로 위 탭에 `배치안` 이 이미 있어 같은 말이다.
줄인 것이지 더한 것이 아니다.

#### 2. 선택 패널이 시점·회전 버튼을 덮었다

폰에서 `.view3d-pick` 이 좌우로 늘어나 위쪽의 `시점 맞추기` · `90° 회전` 을 가렸다.
**착수 전에는 "겹칠 수도 있다" 로만 적었고, 실렌더로 확정됐다.**

고친 방법 둘 —
- 폰에서 선택 패널을 **아래로** 내렸다 (`top: auto; bottom`)
- **물건을 고르면 안내가 자동으로 접힌다** — 고를 줄 안다는 건 안내를 읽었다는 뜻이다.
  덕분에 안내와 선택 패널이 같은 자리를 써도 **동시에 뜨지 않는다**

겹침 판정은 사각형 교차로 계산했다: `hint↔tools = false` · `pick↔tools = false` · 가로 넘침 `false`.

## 저장·되돌리기 — 편집 저장·되돌리기 — 실렌더 검증

2026-07-31. 크롬 · `npm run dev:dash` (localhost:5174) · 1512px.
골 계약은 `docs/goals/GOAL-editor-undo-save.md`.
**GAP-MATRIX 의 "편집한 배치안이 저장되지 않는다" 를 닫는 기록이다.**

### 왕복 확인 — 브라우저에서 측정한 값

| # | 확인 | 결과 |
|---|---|---|
| 1 | 물건 2개를 옮기면 편집 2건이 쌓이나 | `dirty 1 → 2` · `past 2` |
| 2 | `localStorage` 에 실제로 들어가나 | `fr5.layout.edits` 존재 · 화면 상태와 **문자열 일치** |
| 3 | **새로고침해도 남나** | `dirty 2` · 저장분이 새로고침 전과 **완전 일치** |
| 4 | 새로고침 뒤 되돌릴 기록이 없을 때 `⌘Z` | 아무 일도 안 일어남 (`dirty 2` 유지) — 의도한 동작 |
| 5 | **`⌘Z` 가 한 단계만 되돌리나** | 편집 직전 스냅샷과 **완전 일치** (`undoRestoredExactly`) |
| 6 | 되돌린 뒤 저장분도 따라오나 | 저장분 == 화면 상태 |
| 7 | **A 와 B 가 따로 저장되나** | B 로 가면 `dirty 0`, A 로 돌아오면 `dirty 2` 이고 A 내용 **그대로** |
| 8 | 저장이 실패하면 | 배지가 `저장할 수 없어요 · 새로고침하면 사라져요` 로 바뀌고 **편집은 계속된다** |
| 9 | 저장이 다시 되면 | 다음 편집에서 `이 브라우저에 저장됐어요` 로 복귀 |

8번은 `localStorage.setItem` 을 `QuotaExceededError` 를 던지도록 갈아끼워 재현했다.
**사파리 프라이빗을 실제로 띄운 것이 아니다.**

### 되돌리기를 두 버튼으로 나눈 이유

전에는 `되돌리기 (3)` 하나였다. **개수를 보여주면서 한 번에 전부 지웠다** — 배신이다.

| 버튼 | 하는 일 | 보이는 때 |
|---|---|---|
| `되돌리기` | 한 단계 (`⌘Z`·`Ctrl+Z` 와 같다) | 되돌릴 기록이 있을 때 |
| `처음으로` | 이 배치안의 편집을 전부 | 편집이 있을 때 |

`처음으로` 도 기록에 쌓인다 — 잘못 눌러 다 날려도 한 번 되돌리면 돌아온다.

### 어떻게 지었나 (미니멀 사다리)

- **네이티브 `localStorage` 하나로 끝냈다.** 상태관리 라이브러리·IndexedDB 안 썼다. 새 의존성 0, 새 파일 0
- `edits` 와 `past` 를 **한 상태에 묶었다.** 따로 두면 갱신 순서가 어긋나 한 번 눌렀는데 두 단계가 되돌아간다
- 되돌리기 기록은 50개까지. 넘으면 오래된 것부터 버린다
- **깨진 저장분은 조용히 버린다** — 편집기가 안 뜨는 것보다 낫다. 예시 배치안이 바뀌어
  없는 id 가 남아도 안전하다: 얹을 때 있는 것만 얹는다

**천장** — 이 저장은 **브라우저 한 대 안에서만** 산다. 팀 공유·기기 간 동기화는
`Shared/data/config/` 슬롯이 할 일이다 (이관 H 단계).

### 확인하지 않은 범위

- **크롬 하나뿐이다.** 사파리 프라이빗은 예외를 흉내냈을 뿐 실제로 안 띄웠다
- **터치가 아니라 합성 PointerEvent 로 끌었다.** 실제 손가락은 안 해봤다
- 되돌리기 50개 상한에 실제로 닿게 해보지 않았다
- 탭(배치안↔생산성 비교)을 오갈 때의 저장 유지는 안 봤다

### 덤으로 발견한 것 — 고치지 않았다

테스트 중 **`pointerup` 이 유실되자 편집기가 반응을 멈췄다** (`dragging` 이 물린 채 남는다).
`interaction.js` 는 `pointercancel` 을 안 듣는다. 다만 이건 **합성 이벤트에서만 재현했다** —
실제 입력에서는 `setPointerCapture` 가 막아준다. **관찰되지 않은 문제를 먼저 막지 않는다**는
원칙대로 고치지 않고 GAP-MATRIX 에 OPEN 으로 올렸다.

### 게이트

```
npm run build:dash           → ✓ 136ms
bash scripts/check/all.sh    → 전체 통과
```

**`ready-for-review`** — 크롬 1종·데스크톱 폭에서만 봤다.

저장분과 화면 상태는 매 단계 **문자열까지 일치**했다.

### 실렌더가 잡은 결함 셋 — 전부 코드 게이트를 통과한 상태였다

#### 1. 회전이 항상 0° 로 떴다

3D 노드의 `userData.item` 은 `{kind, id, type}` **셋만** 담는다
(`Shared/view3d/parts.js:162`). 회전을 실어 나르지 않는다.
그래서 실제로 180° 인 물건이 화면에 **0° 로 보였다.**

골의 Boundaries 가 `Shared/**` 수정을 금지하므로 **거기를 고치지 않고**,
패널이 **배치안 데이터에서 직접 읽게** 바꿨다. 정본은 배치안이지 3D 노드가 아니다.

#### 2. 되돌린 뒤 패널만 옛 값을 들고 있었다

`⌘Z` 로 데이터는 돌아갔는데 입력칸은 `5000` 을 그대로 보여줬다.
`picked` 가 **고른 순간의 사본**이라 배치안이 바뀌어도 안 따라온다.
→ 패널이 항상 배치안에서 읽게 했다. **끄는 중(`live`)에만** 손끝을 따라간다.

#### 3. 회전만 바꿔도 좌표가 옛날로 되돌아갔다

②를 고치면서 커밋할 때 `picked` 를 그대로 실어 보냈더니, 회전 커밋에
**고른 순간의 좌표**가 같이 실려 위치를 덮어썼다.
→ 커밋은 **지금 화면에 보이는 값**을 바탕으로 보낸다.

셋 다 같은 뿌리다 — **"화면이 보여주는 값의 정본이 어디인가"** 를 안 정해서 생겼다.

### 재사용하지 않은 것과 그 이유

AR 의 `AR/src/features/ui/number-pair.js` 가 **같은 버그를 이미 고쳤다.**
하지만 그건 **바닐라 DOM + 슬라이더·숫자 쌍**이고 여기는 React 이며 슬라이더도 필요 없다.
**코드는 못 가져왔고, 가져온 것은 규칙 한 줄이다** —

> 타이핑 중(`onChange`)에는 입력칸의 `value` 를 절대 되쓰지 않는다.
> 자르기·격자 맞추기는 손을 뗄 때(`blur`) 한 번만 한다.

입력칸 셋은 `NumBox` 하나로 만들었다. 같은 칸을 세 번 복사하지 않았다.

### 확인하지 않은 범위

- **크롬 하나뿐이다.** 사파리·파이어폭스에서 안 봤다
- **폰 폭에서 안 봤다.** 입력칸 셋이 늘어 선택 패널이 더 넓어졌다 — 접히는 모양 미확인
- 실제 키보드가 아니라 **합성 `input`·`focusout` 이벤트**로 쳤다.
  브라우저 창이 포커스를 안 가진 상태라 `blur()` 가 안 먹어 이벤트를 직접 쐈다
- 화살표 키·스피너로 값을 올리고 내리는 경로는 안 봤다

## 배포본 실렌더 — 관제화면 배포 — 배포본 실사용에서 잡은 결함 셋

2026-07-31. `https://fr5dashboard.vercel.app` · 크롬.
배포는 `bash scripts/dev/deploy-dashboard.sh` (빌드 산출물만 올린다 · D24).

### 왜 이 기록이 필요한가

**세 결함 모두 `bash scripts/check/all.sh` 와 `npm run build` 를 통과한 상태였다.**
그중 둘은 로컬 실렌더도 통과했고 **배포본을 실제로 클릭해서야** 나왔다 —
합성 PointerEvent 로는 재현되지 않는 종류였다.

### 잡은 것 셋

#### 1. 한국어 조사가 틀렸다 (첫 배포본)

화면에 `"보관 선반는 팔이 안 닿아요"` 가 떴다. **물건 이름이 배치안에서 오기 때문에
조사를 문장에 박을 수 없다.** 종성 유무로 `은/는` 을 고르는 함수를 넣었다 —
한글 음절은 `((코드 - 0xAC00) % 28)` 이 종성 번호다.

손검산 — `보관 선반은` · `배출대는` · `계측기는` · `시료 투입은` · `작업대는`.

#### 2. 고르기만 해도 편집이 생겼다

배포본을 클릭했더니 `runN1` 의 y 가 **7620 → 7600** 으로 바뀌고 저장 배지가 떴다.

원인은 **끌기가 시작되는 기준이 없던 것**이다. 클릭 중 손이 1px 만 흔들려도
`onMove` 가 격자로 스냅해 메시를 옮기고 `onUp` 이 커밋했다.
예시 좌표에 100mm 배수가 아닌 값이 여럿이라(7620 · 7820 · 4350 · 3050 · 1750)
**고를 때마다 물건이 최대 50mm 밀렸다.**

고친 방법 — `interaction.js` 에 문턱 `SLOP_PX = 4`.
**넘기 전에는 `onMove` 에서 곧바로 되돌아간다.** 놓을 때만 막으면 메시는 이미 움직여 있어
화면과 배치안이 갈라진다. 그래서 **시작 지점에서 막았다.**

#### 3. 끌기가 끝나도 미리보기 모드가 안 꺼졌다

`onMove` 는 끄는 동안 `live: true` 로 손끝 좌표를 패널에 보낸다. 그런데 `onUp` 이
그 표시를 안 지워서 **끌기가 끝난 뒤에도 패널이 손끝 좌표를 계속 보고 있었다.**
되돌리기를 해도 패널은 놓은 자리에 얼어붙었다.

고친 방법 — 커밋할 때 `live` 를 끈다 (`LayoutView.jsx`).
