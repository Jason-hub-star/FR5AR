# 좌표 직접 입력 — 실렌더 검증

2026-07-31. 크롬 · `npm run dev:dash` (localhost:5174) · 1512px.
골 계약은 `docs/goals/GOAL-editor-coord-input.md`.

## 왜 필요했나

끌기는 **100mm 격자에 붙어 그 사이 값을 못 넣는다.** 실험실 실측 치수가 나오면 바로 막힌다.

## 검증 — 브라우저에서 측정한 값

`runN1`(benchRun)을 골랐다. 초기값 `x 2600 · y 7620 · 회전 180°` 로
`Shared/data/layout/examples.js` 의 값과 **정확히 일치**했다.

|---|---|---|

| x `5000` | x 5000 · y 7620 · 회전 180 | 나머지 안 건드림 |
| y `3000` | x 5000 · y 3000 · 회전 180 | |

저장분과 화면 상태는 매 단계 **문자열까지 일치**했다.

## 실렌더가 잡은 결함 셋 — 전부 코드 게이트를 통과한 상태였다

### 1. 회전이 항상 0° 로 떴다

3D 노드의 `userData.item` 은 `{kind, id, type}` **셋만** 담는다
(`Shared/view3d/props/index.js:162`). 회전을 실어 나르지 않는다.
그래서 실제로 180° 인 물건이 화면에 **0° 로 보였다.**

골의 Boundaries 가 `Shared/**` 수정을 금지하므로 **거기를 고치지 않고**,
패널이 **배치안 데이터에서 직접 읽게** 바꿨다. 정본은 배치안이지 3D 노드가 아니다.

### 2. 되돌린 뒤 패널만 옛 값을 들고 있었다

`⌘Z` 로 데이터는 돌아갔는데 입력칸은 `5000` 을 그대로 보여줬다.
`picked` 가 **고른 순간의 사본**이라 배치안이 바뀌어도 안 따라온다.
→ 패널이 항상 배치안에서 읽게 했다. **끄는 중(`live`)에만** 손끝을 따라간다.

### 3. 회전만 바꿔도 좌표가 옛날로 되돌아갔다

②를 고치면서 커밋할 때 `picked` 를 그대로 실어 보냈더니, 회전 커밋에
**고른 순간의 좌표**가 같이 실려 위치를 덮어썼다.
→ 커밋은 **지금 화면에 보이는 값**을 바탕으로 보낸다.

셋 다 같은 뿌리다 — **"화면이 보여주는 값의 정본이 어디인가"** 를 안 정해서 생겼다.

## 재사용하지 않은 것과 그 이유

AR 의 `AR/src/features/ui/number-pair.js` 가 **같은 버그를 이미 고쳤다.**
하지만 그건 **바닐라 DOM + 슬라이더·숫자 쌍**이고 여기는 React 이며 슬라이더도 필요 없다.
**코드는 못 가져왔고, 가져온 것은 규칙 한 줄이다** —

> 타이핑 중(`onChange`)에는 입력칸의 `value` 를 절대 되쓰지 않는다.
> 자르기·격자 맞추기는 손을 뗄 때(`blur`) 한 번만 한다.

입력칸 셋은 `NumBox` 하나로 만들었다. 같은 칸을 세 번 복사하지 않았다.

## 확인하지 않은 범위

- **크롬 하나뿐이다.** 사파리·파이어폭스에서 안 봤다
- **폰 폭에서 안 봤다.** 입력칸 셋이 늘어 선택 패널이 더 넓어졌다 — 접히는 모양 미확인
- 실제 키보드가 아니라 **합성 `input`·`focusout` 이벤트**로 쳤다.
  브라우저 창이 포커스를 안 가진 상태라 `blur()` 가 안 먹어 이벤트를 직접 쐈다
- 화살표 키·스피너로 값을 올리고 내리는 경로는 안 봤다
