# 증거 — 그리퍼 장착값 실측 (2026-07-30)

분류: **증거**. 이 시점에 브라우저에서 실제로 확인한 것만 적는다.
확정 결과는 `web/config/gripper-mount.json`에, 배경은 `docs/ref/STACK.md` §그리퍼에 있다.

## 무엇을 닫았나

`fairino5_v6.urdf`에 그리퍼가 없어 코드로 붙여야 했고, **두 값이 미지였다** —
축 방향과 `wrist3_link` → 그리퍼 원점 오프셋. 둘 다 확정했다.

## 확인 방법

`web/robot.html`(AR 없는 3D 뷰)을 띄우고 콘솔에서 재는 방식.
**AR 위에서 맞추지 않았다** — 마커 떨림과 정합 오차가 섞이면 원인을 못 가른다.

## 실측값

### 손목 플랜지 — `wrist3_link` 로컬

| 항목 | 값 |
|---|---|
| 메시 Z 범위 | **53.2 ~ 99.0 mm** (80×80×45.8 원판) |
| 플랜지 면 | 먼 쪽 = **Z = 99.0 mm** |
| 공구 방향 | **+Z** |

링크 원점이 메시보다 53.2mm 앞에 있다. URDF만 보면 플랜지가 53.2인지 99.0인지 알 수 없어
**두 값을 다 넣어 보고 골랐다** — 53.2로 두면 그리퍼가 원판 안에 파묻힌다.

### 그리퍼 — STL 3개 합성 바운딩 박스 (자기 조립 좌표계, mm)

| 축 | 범위 | 크기 | 뜻 |
|---|---|---|---|
| X | −42.5 ~ 36.9 | 79.4 | 폭. 손가락 개폐 방향 |
| Y | −71.98 ~ 85.02 | 157.0 | **접근 방향(+Y).** 몸통 132 + 손가락 |
| Z | −340.14 ~ −311.14 | 29.0 | 두께 |

**Z가 −325mm 부근인 것은 조립 오프셋**이다. 세 STL이 원점에서 325mm 떨어진
공통 좌표계에 구워져 있어, 서로의 상대 위치는 이미 맞다.

## 유도

```
장착면 중심 = (0, −71.98, −325.64) mm      ← Y 최소면, 두께·폭 중심
Rx(+90) 적용 → (0, +325.64, −71.98)        ← +Y 를 +Z 로 보낸다
목표 = wrist3 로컬 (0, 0, 99.0)
이동 = 목표 − 회전결과 = (0, −325.64, +170.98) mm
```

**회전은 +90°다. 처음 추정한 −90°는 방향이 반대였다** (Rx(−90)은 +Y를 −Z로 보낸다).
추정을 그대로 썼다면 그리퍼가 팔 안쪽으로 파묻혔다.

## 검산 — 손목 로컬 좌표계

마운트 변환은 자세와 무관하므로 로컬에서 한 번 재면 끝난다.

| 항목 | 측정 | 판정 |
|---|---|---|
| 그리퍼 Z 범위 | **99.0 ~ 256.0 mm** | 플랜지 면(99.0)에서 시작 |
| 플랜지와의 간격 | **0.00 mm** | 접함 ✓ |
| Y 범위 | −14.5 ~ 14.5 | 두께 29mm가 축에 중심 ✓ |
| 공구축 XY 이탈 | (−2.8, 0) mm | 그리퍼 몸통 자체의 비대칭. 오류 아님 |

## 밟은 함정 4개

| 함정 | 증상 | 원인·해결 |
|---|---|---|
| importmap 누락 | 모듈 해석에서 **통째로 멈춤** | `URDFLoader`가 `three/examples/jsm/loaders/STLLoader.js` 등 bare 지정자를 쓴다. `grep -rhoE "from '[^']+'" web/js`로 전부 찾아 매핑 |
| `loadMeshCb` 시그니처 | `done is not a function` | 실제는 `(path, manager, material, done)` 4개. **직접 짜지 말고 기본 로더를 쓴다** — STL과 URDF 재질을 이미 처리한다 |
| `hidden` 이 안 먹음 | 로딩 화면이 캔버스를 계속 가림 | `#loading { display: flex }`가 `hidden`의 `display:none`을 덮는다. `#loading[hidden] { display: none }` 필요 |
| 월드 AABB로 거리 측정 | 자세를 바꾸면 99mm가 67mm로 보임 | 축 정렬 바운딩 박스는 공구 축이 기울면 실제보다 커진다. **손목 로컬 좌표계에서 재야** 자세와 무관 |

## 남은 미확정

`rotationDeg[2]`(공구 축 중심 회전)는 0으로 둔 임시값이다.
손가락 개폐 방향이 실물과 맞는지는 **실물 그리퍼를 봐야** 정해진다 — 3D 표시에는 영향이 없다.

## 재현

```bash
bash scripts/dev/serve.sh 8123
open http://localhost:8123/robot.html
```
콘솔에 `focusWrist(0.33)` — 손목을 크게 본다. `robot` · `gripperGroup` · `gcfg`가 노출돼 있다.
