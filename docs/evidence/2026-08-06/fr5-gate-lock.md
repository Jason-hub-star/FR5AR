## 넣는 순간 나온 것 — 이게 진짜 이유였다

붙이고 나서 `all.sh` 를 **연달아** 돌리자 흔들렸다. 혼자 돌리면 3/3 초록인데
`all.sh` 안에서는 어떤 때는 모드 전환 넷이, 어떤 때는 `DISARM → 서보 OFF` 가 빨개졌다.

**`.mjs` 가 자기 자식의 자식을 안 죽인다.**

```
uv run … uvicorn      ← .kill() 이 여기까지만 간다
  └ python uvicorn    ← 살아남아 5155·5157 을 계속 쥔다
npm run dev:fr5
  └ vite              ← 살아남아 5176 을 계속 쥔다
```

`lsof` 로 실측한 유령: `python 5155 LISTEN` · `vite 5176 LISTEN`.
다음 실행의 uvicorn 은 포트를 못 잡고, 검증은 **죽은 옛 브리지에 말을 걸어** 첫 검사부터
11건이 무더기로 실패한다. 원인은 마지막 실패가 아니라 **지난번 실행**에 있다.

**이게 `.mjs` 를 손으로만 부르던 진짜 이유다.** 손으로는 한 번 부르고 끝이라 절대 안 보인다.
"손으로 부르는 검증" 은 **연달아 돌려 본 적이 없는 검증**과 같은 말이었다.

고침 — `detached: true` 로 프로세스 그룹을 따로 만들고 `process.kill(-pid, 'SIGKILL')` 로
그룹째 죽인다. 예외·중단에도 남지 않게 `process.on('exit')` 에도 건다.

### 딸려 나온 뿌리 하나 — 고정 `sleep` 과 삼켜진 클릭

같은 흔들림의 나머지 절반은 **"왔겠지" 로 기다린 것**이었다.

- `fr5-bridge-verify` 는 WS 명령을 보내고 `sleep(300)` 뒤에 상태를 읽는다. 안 왔으면
  그 뒤 검사 넷이 줄줄이 빨개져 **원인이 어디인지 안 보인다.** 흔들린 6곳을 `until()`
  (조건 폴링 · 제한시간 4초)로 바꿨다. 조건이 오면 즉시 지나가고, 안 오면 그대로 실패한다
- `fr5-web-verify` 의 `clickText` 는 버튼을 못 찾으면 `?? 'notfound'` 를 돌려줬고 **아무도
  안 봤다.** 상태가 바뀌며 조작대가 다시 그려지는 사이에 누르면 클릭이 허공으로 가고,
  실패는 **그 다음 검사**에서 터진다. 버튼을 기다리고, 못 찾으면 던지게 고쳤다

**남은 고정 `sleep` 이 21곳이다** — 지금은 안 흔들리지만 뿌리는 같다. GAP 에 P2 로 남겼다.
