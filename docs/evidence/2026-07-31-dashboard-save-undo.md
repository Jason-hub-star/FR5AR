**사파리 프라이빗을 실제로 띄운 것이 아니다.**

## 되돌리기를 두 버튼으로 나눈 이유

전에는 `되돌리기 (3)` 하나였다. **개수를 보여주면서 한 번에 전부 지웠다** — 배신이다.

| 버튼 | 하는 일 | 보이는 때 |
|---|---|---|
| `되돌리기` | 한 단계 (`⌘Z`·`Ctrl+Z` 와 같다) | 되돌릴 기록이 있을 때 |
| `처음으로` | 이 배치안의 편집을 전부 | 편집이 있을 때 |

`처음으로` 도 기록에 쌓인다 — 잘못 눌러 다 날려도 한 번 되돌리면 돌아온다.

## 어떻게 지었나 (미니멀 사다리)

- **네이티브 `localStorage` 하나로 끝냈다.** 상태관리 라이브러리·IndexedDB 안 썼다. 새 의존성 0, 새 파일 0
- `edits` 와 `past` 를 **한 상태에 묶었다.** 따로 두면 갱신 순서가 어긋나 한 번 눌렀는데 두 단계가 되돌아간다
- 되돌리기 기록은 50개까지. 넘으면 오래된 것부터 버린다
- **깨진 저장분은 조용히 버린다** — 편집기가 안 뜨는 것보다 낫다. 예시 배치안이 바뀌어
  없는 id 가 남아도 안전하다: 얹을 때 있는 것만 얹는다

**천장** — 이 저장은 **브라우저 한 대 안에서만** 산다. 팀 공유·기기 간 동기화는
`Shared/data/config/` 슬롯이 할 일이다 (이관 H 단계).

## 확인하지 않은 범위

- **크롬 하나뿐이다.** 사파리 프라이빗은 예외를 흉내냈을 뿐 실제로 안 띄웠다
- **터치가 아니라 합성 PointerEvent 로 끌었다.** 실제 손가락은 안 해봤다
- 되돌리기 50개 상한에 실제로 닿게 해보지 않았다
- 탭(배치안↔생산성 비교)을 오갈 때의 저장 유지는 안 봤다

## 덤으로 발견한 것 — 고치지 않았다

테스트 중 **`pointerup` 이 유실되자 편집기가 반응을 멈췄다** (`dragging` 이 물린 채 남는다).
`interaction.js` 는 `pointercancel` 을 안 듣는다. 다만 이건 **합성 이벤트에서만 재현했다** —
실제 입력에서는 `setPointerCapture` 가 막아준다. **관찰되지 않은 문제를 먼저 막지 않는다**는
원칙대로 고치지 않고 GAP-MATRIX 에 OPEN 으로 올렸다.
