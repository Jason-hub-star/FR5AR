# ARCHITECTURE — 구조

분류: **SSOT**. 새 폴더를 만들거나 코드를 어디 둘지 모를 때 여기를 먼저 고친다.

## 우리 몫은 시각화다

팀 안에서 역할이 갈렸다(2026-07-30). **이 경계를 넘지 않는다.**

| | 누가 | 무엇 |
|---|---|---|
| **우리** | 이 저장소 | **관제화면과 AR — 배치안 편집, 지표 표시·비교, 실물 위 겹쳐 보기** |
| 팀원 | 다른 코드 | 생산성 수치를 내는 알고리즘 (시뮬레이션·계산) |
| 팀원 | 다른 코드 | AMR 자율주행 |

**우리는 수치를 만들지 않는다. 받아서 보여준다.** 그래서 우리가 지켜야 할 것은 둘이다 —
**받는 모양(계약)을 우리가 먼저 제시하는 것**, 그리고 **나중에 데이터베이스·백엔드로
바꿔 끼울 수 있게 격리해 두는 것**.

## 전체 그림

```
[FR5 컨트롤러] ─TCP:8080─ [브리지 서버 :5055] ─REST/WS─┐
   실물 로봇        공식 파이썬 SDK · FastAPI            │
                                                        ├─ 관제화면 (PC, React)   ← 우리
[팀원의 알고리즘] ─────── 지표 데이터 ──────────────────┤
[팀원의 AMR]                                            └─ AR 화면 (폰, 바닐라)   ← 우리
```

**목표는 실기 ↔ 우리 대시보드·AR 이다.** 유니티 펜던트는 이 그림에 없다 —
같은 로봇을 이미 실기로 붙여 본 **선례**이고 받쳐야 할 클라이언트가 아니다.
검증된 숫자와 함정만 가져온다 (`unity/unity-bridge-protocol.md`).
나중에 붙이려면 변환 라우트 하나를 더한다 — 우리 계약은 그대로 둔다.

**브리지 서버가 로봇의 유일한 관문이다.** 클라이언트는 로봇과 직접 말하지 않는다.
안전 상한을 한 곳에서 강제하고 조종권 충돌을 한 곳에서 막기 위해서다.

**지표 데이터는 로봇 경로와 별개다.** 팀원 알고리즘이 어디서 돌든 우리는
`Shared/data/datasource/` 하나로만 받는다 (아래 §확장성).

## 확장성 — 데이터 출처를 한 곳으로 격리한다

지금은 팀원의 알고리즘도, 데이터베이스도, 백엔드도 없다. **그래도 화면은 지금 만든다.**

```
화면 (Dashboard/features/metrics · layout   ·   AR/features/overlay)
   ↓  이 경계만 안다
Shared/data/datasource/    ← 함수 몇 개. 화면은 출처를 모른다
   ├── mock.js              지금: 손으로 만든 JSON
   ├── http.js              나중: 팀원 API · 백엔드
   └── (db)                 나중: 데이터베이스
```

**화면은 `fetch`를 직접 부르지 않는다.** 부르는 순간 출처가 화면에 박히고,
나중에 백엔드를 붙일 때 화면을 전부 다시 짜야 한다.

목업에서 실물로 바꾸는 작업이 **파일 한 개 교체**여야 한다. 그게 이 경계의 완료 판정이다.

착수하는 사람이 SSOT 를 뒤지지 않고 바로 시작한다. 상한 15줄, 게이트가 잰다.

## UI 통일 — 디자인 토큰은 `Shared/tokens/` 한 곳

`AR` 과 `Dashboard` 가 따로 스타일을 쌓으면 같은 프로젝트로 안 보인다.
**토큰만 공유하고 컴포넌트는 공유하지 않는다.**

| 공유한다 | 공유하지 않는다 |
|---|---|
| 색 팔레트 · 간격 스케일 · 타이포 스케일 · 반경 · 그림자 | 버튼·패널·표 같은 컴포넌트 스타일 |
| 상태 색 (정상/경고/위험) — **안전 표시가 두 화면에서 같아야 한다** | 레이아웃 |

CSS 커스텀 속성 한 파일이다. 두 프로젝트가 각자 import 한다.

**왜 컴포넌트는 공유하지 않나** — AR 은 카메라 영상 위의 반투명 오버레이고
대시보드는 밀도 높은 데이터 화면이다. 요구가 정반대라, 공용 컴포넌트를 만들면
양쪽 다 어정쩡해진다. 토큰은 그 위험이 없다.

**토큰 이름은 의미로 짓는다** — `--c-danger` 는 되고 `--c-red` 는 안 된다.
AR 은 어두운 배경, 대시보드는 밝은 배경이라 같은 빨강이 두 곳에서 다르게 보인다.

## 비전 → 로봇 움직임 (확장 지점 · 안전이 먼저다)

"비전 인식값에 따라 로봇 움직임이 바뀐다"는 **자동으로 명령이 생성되는 경로**다.
**하드 룰 3**(속도 상한 + 사람 확인 없이 큰 동작 금지)과 정면으로 부딪힌다.

**그래서 비전은 명령을 만들지 않는다. 제안을 만든다.**

```
Vision  ──제안(proposal)──▶  Backend/safety.py  ──검사 통과분만──▶  로봇
                                    │
                     ┌──────────────┴──────────────┐
                     │ 속도 상한 · 관절 변화 상한   │
                     │ 도달 범위 · 조종권          │
                     │ **큰 동작이면 사람 확인**    │
                     └─────────────────────────────┘
```

| 규칙 | 왜 |
|---|---|
| 비전은 `POST /proposal` 로 **제안만** 보낸다 | 명령 주인은 한 명이다 (하드 룰 4) |
| 서버가 검사하고 **거부 사유를 응답한다** | 클라이언트를 믿지 않는다 |
| 상한 안의 작은 보정만 자동 통과 | 큰 동작은 사람 확인 |
| 비전이 죽으면 **아무 일도 안 일어난다** | fail-closed (`SAFETY-RULES.md`) |
| 제안·판정·실행이 전부 기록된다 | 나중에 왜 움직였는지 답할 수 있어야 한다 |

**계약은 `Vision/` 코드가 생길 때 `API-CONTRACT.md` 에 먼저 적는다.** 지금은 이 경계만 못 박는다.

## 자율주행 로봇(TurtleBot) — 열어두는 방식

**지금 코드를 만들지 않는다.** 대신 확장 지점 둘만 이미 있다.

1. **배치안의 `amr` 블록** — 도킹 위치·경로점. 이미 모델에 있다 (`SHARED-CORE.md`)
2. **`Shared/data/datasource/`** — AMR 실시간 위치가 필요해지면 여기 함수 하나가 늘어난다.
   화면은 출처를 모르므로 바뀌지 않는다

**AMR 을 우리가 몰지 않는다** (`PRD.md` §범위 밖). 우리는 경로를 그리고 이동거리를 표시한다.
그 선을 넘으면 안전 책임이 우리에게 온다.

## 각 층이 책임지는 것

| 층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 브리지 서버 | 로봇 연결, 상태 폴링·브로드캐스트, 안전 검사, 조종권, 지점 저장, 경로 계산 | 화면 렌더링 |
| `Dashboard/` | 배치안 편집, 지표 표시·비교, 조작 UI, 3D 표시 | **지표 계산** · 안전 판단 |
| `AR/` | 마커 정합, 배치안·경로를 실물 위에 겹치기 | 배치안 편집 · 로봇 명령 |
| `Shared/data/` | 배치안 모양 · 단위 · 설정 · **데이터 출처를 아는 유일한 곳** | 화면·렌더링·계산 |
| `Shared/view3d/` | URDF·궤적·안전 범위 렌더링 (바닐라 three) | **React** · 데이터 가져오기 |
| 팀원 알고리즘 | 생산성 수치 산출 | — (우리 저장소 밖) |
| 팀원 AMR | 자율주행 | — (우리 저장소 밖) |

## 좌표계

| 곳 | 단위 | 축 |
|---|---|---|
| 로봇 · API 계약 | 도(°), 밀리미터(mm) | 로봇 베이스 기준 |
| URDF · 3D 내부 | 라디안, 미터 | Z-up |
| three.js 화면 | 라디안, 미터 | **Y-up** → `robot.rotation.x = -π/2` |
| AR 마커 | 미터 | 마커 원점 → 로봇 원점 변환은 설정값 |

**변환은 경계에서 한 번만.** 중간에서 또 바꾸면 원인을 못 찾는다.

## 상태 흐름

```
로봇 상태 폴링 (서버, 33ms 목표 — 실측 27Hz)
   → 안전 검사 통과분만
   → WebSocket 브로드캐스트 (전원)
   → 3D 관절 갱신 · AR 겹치기 갱신
```

명령은 반대 방향이되 **조종권을 가진 하나만** 통과한다. `stop`은 예외로 항상 통과한다.

## 아직 정하지 않은 것

- 기록 저장소 — 파일 / SQLite / Supabase 중 미정. 지난 프로젝트 Supabase 스키마 재사용 가능
- AMR(TurtleBot) 연계 지점 — 기종 확정 후. 확장 지점은 이미 둘 있다 (위 §TurtleBot)
- **파이썬 SDK 가 macOS 에서 되는지** — `Backend/` 착수 시 첫 관문
