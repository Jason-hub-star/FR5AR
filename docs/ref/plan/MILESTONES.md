분류: **SSOT**. Phase별로 무엇을 시연할 수 있는지, 완료 판정은 무엇인지 본다.

# MILESTONES — 마일스톤

> 각 단계는 AC를 2~3개 충족해야 완료한다.
> 갱신 2026-07-31 — 실기 readback으로 V0 앞의 H0 게이트를 닫고 V5~V7을 구체화했다.

## 순서가 바뀐 이유

목표가 **배치별 생산성 비교**로 확정됐고, **우리 몫은 시각화**다
(`ARCHITECTURE.md` §우리 몫). 그래서 순서가 뒤집혔다.

| | 서버가 필요한가 | 팀원 코드가 필요한가 |
|---|---|---|
| **L1~L3 (배치 실험)** | **아니오** | **아니오** — 목업으로 판정이 선다 |
| **S1 (무대 전환)** | **아니오** | **아니오** — 소품 함수만 바꾼다 (D51) |
| V0~V7 (FR5 플랫폼) | 예 (`FR5/bridge/` 미착수) | 일부 — V6 후보 생성기는 팀원/별도 작업기 |
| **L4 (동작별 비교 · F10)** | 예 — 시연 궤적이 나와야 한다 | 아니오 |

**막힌 것이 없는 쪽을 먼저 한다.** V0는 브리지 서버 코드가 아직 없고
Fairino SDK 설치 경로도 미확인이다. L1~L3은 지금 당장 갈 수 있다.

L1~L3이 끝나면 **목업 숫자로 성공 판정 문장이 화면에서 나온다.**
그 뒤 H0~V7이 실물 수치·조작·슬롯·시뮬레이션 결과를 그 자리에 채운다.

## S1 무대 전환 — 방산 조립 라인 (D51·D66)

**목표:** 소품을 과학실험실에서 **탄두 조립 라인**으로 갈아끼운다. **L1~L3 과 독립이다** —
배치안 모델·좌표·편집 조작은 안 바뀌고 `type` 이 가리키는 함수만 바뀐다.

**스타일은 안 바꾼다** — 화이트 모형(텍스처 없음, 디테일은 형태에서). 재질은 기존 6개
(`shell`·`body`·`steel`·`dark`·`glass`·`screen`)만 쓴다. 소품 11개가 275줄이니 하나에 15~20줄이다.

| 기존 소품 | 방산에서의 역할 | 손볼 것 |
|---|---|---|
| `safetyFence` | 알루미늄 프레임 + 유리 격벽 | **그대로** |
| `bench` · `benchRun` | 조립 작업대 · 라인 작업대 | 그대로 |
| `shelf` | 부품 랙 | 선반 경사 |
| `workstation` · `instrument` | 제어반 · 검사 장비 | 그대로 |
| `isolator` | **원격 취급 셀 / 차폐 부스** | 이름·라벨만 |
| `chair` · `clutter` · `fumehood` | — | **버렸다** (2026-08-04 집행 · D62) |

| 신규 소품 | 형태 | 비고 |
|---|---|---|
| `conveyor` | 프레임 + 롤러 반복 + 리니어 레일 | 1사이클의 입구 |
| **`warhead`** | 원뿔(노즈) + 원통(동체) + 밴드 | **작업물 — 아래 참조** |
| `chuck` | 회전 척 + 3점 조 | 탄두를 물어 돌린다 |
| `partTray` | 격자 트레이 + 구멍 | 4단계 "분류" 의 산출물 자리 |
| `blastWall` | 두꺼운 벽 + 관측창 | `fumehood` 를 대체 |

**화면이 방산으로 읽히는 최소 조합은 `conveyor`+`warhead`+`chuck` 셋이다.** 나머지는 배경이다.

### 탄두는 소품이 아니라 작업물이다

다른 소품은 배치안에 고정으로 놓이지만 탄두는 로봇이 **집고 옮기고 분해**한다.
팩토리가 단계를 인자로 받는다 — `warhead({ stage })`,
`0` 조립완성 → `1` 유도부 분리 → `2` 신관 분리 → `3` 주탄약 분리.
**F10 의 진척 표시가 여기서 공짜로 나온다** — 사이클이 진행되며 탄두가 쪼개지는 것이 곧 진행률이다.

⚠ **치수는 실물 페트병(약 Ø65×220mm)에 맞춘다.** 실제 포탄 치수로 그리면 실물 점유 부피를
넘어 D51 규칙을 어기고, AR 에서 사람이 충돌 여지를 오판한다. **비율만 탄두처럼 간다.**

### 저작 방법 — 참조 이미지는 Codex 가 만든다 (2026-08-03 실측)

**`codex exec` 는 이미지를 생성한다.** 실측으로 확인했다 — 1536×1024 PNG,
"흰 배경 · 회색 · 텍스처 없는 화이트 모형" 을 요청하니 **우리 스타일 그대로** 나왔다.
사진풍이 아니라 우리가 쓰는 무텍스처 모형이라 그대로 참조로 쓴다.

```
codex exec --skip-git-repo-check "…이미지를 만들어라"
→ ~/Library/Application Support/orca/codex-accounts/<id>/home/generated_images/<uuid>/*.png
```

⚠ **Codex 는 우리 폴더에 못 쓴다** — 샌드박스라 "읽기 전용" 으로 거부한다. 위 경로에서
직접 복사한다. 파일명을 지정해도 소용없다.

**스타일 문구를 고정한다** — 소품마다 이 앞머리를 그대로 붙여야 11개가 한 벌로 보인다.

> 순백색 배경, 무광 회색 단색, 텍스처·로고·글자 없음, 3/4 정면 뷰,
> 부드러운 스튜디오 조명, 그림자 약간. 건축 화이트 모형 스타일(사진풍 아님).

**생성물은 저장소에 안 넣는다.** 한 장이 1.2MB 이고 `Shared/assets/` 는 `publicDir` 로
`dist` 에 통째 복사된다(GAP OPEN). **재생 가능한 자산은 이미지가 아니라 위 문구다** —
필요하면 1분 만에 다시 뽑는다.

파이프라인은 **Codex 이미지 → img2threejs → `parts.js` 함수** 다.
img2threejs 는 미설치이므로 쓸 때 `git clone` 한다 (`STACK.md` §에셋 저작).

**전부를 이 경로로 보내지는 않는다.** 소품 하나가 20줄이라, 박스 조합(`partTray`·`blastWall`)은
손코딩이 더 싸다. **곡면·반복 구조가 있는 것**(`conveyor` 롤러 · `warhead` 외형 ·
`chuck` 3점 조)만 이미지→코드 경로를 탄다.

### Acceptance Criteria

- [ ] 기존 배치안 파일이 **고치지 않아도 열린다** — 없어진 `type` 은 화면이 죽지 않고 그 소품만 빈다.
- [ ] `Shared/assets/` 용량이 안 늘었다 (절차적 코드로만 추가 · `STACK.md` §에셋 저작).
- [ ] 소품 함수가 `parts.js` 규약을 따른다 — `userData.item` 에 `{kind,id,type}` 을 싣는다.
- [ ] 실렌더 증거를 `docs/evidence/` 에 남긴다 (하드 룰 2).

## L4 동작별 생산성 비교 (F10) — 와우모먼트

**목표:** 같은 배치·같은 작업을 **사람 시연 / 후처리 궤적 / 학습된 정책**으로 각각 돌려
사이클 타임을 나란히 본다. **L3 화면의 비교 축을 하나 더 만드는 것**이지 새 화면이 아니다.

**선행** — 모방학습 사다리 2(시연 녹화·후처리)까지면 값 두 개가 나온다.
세 번째(정책)는 사다리 4가 필요하다. **두 개만으로도 L4 는 성립한다.**

### Acceptance Criteria

- [ ] 같은 작업의 궤적 두 개 이상을 나란히 재생하고 사이클 타임 차이가 % 로 나온다.
- [ ] 각 궤적의 출처(`demo`/`postproc`/`policy`)가 화면에 표시된다 (L3 의 출처 규약과 같은 방식).
- [ ] 값이 하나뿐이어도 화면이 죽지 않는다 (비교 대상 부족을 그렇게 말한다).
- [ ] **1사이클 = 1발 조립** 으로 분모가 고정돼 있다 (D51·D66).
