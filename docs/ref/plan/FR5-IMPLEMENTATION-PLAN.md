분류: **SSOT**. FR5 웹 조작기의 화면·구현 순서·실기 게이트를 정한다.

# FR5-IMPLEMENTATION-PLAN — 실기 기준 상세 계획

## 결정

- Unity 런타임은 쓰지 않는다. 기존 Unity 코드는 **검증값과 로직 원본**으로만 참조한다.
- FR5는 `FR5/src/` + `FR5/bridge/`의 독립 수직 배포 단위다. 루트 범용 `Backend/`는 만들지 않는다.
- `Dashboard/`는 배치·생산성·FR5 요약과 링크만 제공하며 로봇 명령은 보내지 않는다.
- 팀원에게 FR5 조작 URL은 별도 배포한다. 같은 LAN의 `FR5/bridge/`가 정적 웹과 API를 함께
  제공해 버전이 갈라지지 않게 한다.
- 시뮬레이터는 웹이나 브리지 안에 넣지 않는다. 별도 작업 실행기가 후보를 만들고, 웹은 작업 요청·
  비교·승인·슬롯 활성화만 한다.

근거 실측은 `docs/evidence/2026-07-31/fr5-live-readback.md`, 통신 모양은
`docs/ref/contract/API-CONTRACT.md`, 안전 판정은 `docs/ref/contract/SAFETY-RULES.md`가 정본이다.

## 실기 기준선

**현재 주소는 `192.168.58.2:8080` 이다** (2026-08-05 · D68 — 펜던트가 대역을 정했다).
첫 readback 은 2026-07-31 에 `192.168.57.2` 에서 났고, 그 뒤 한 번 옮겼다. **주소를
코드 기본 로봇으로 박지 않는 이유가 이것이다** — 같은 FR5라도 다른 개체·다른 배선이
배정될 수 있으므로 연결은 다음 두 값을 분리한다.

```jsonc
{
  "robotId": "fr5-lab-a",              // 우리 시스템의 안정적인 이름
  "endpoint": "192.168.58.2:8080",     // 현장 설정, 교체 가능 (D68)
  "expectedModel": "FR5",
  "observed": {                          // 연결할 때 SDK로 다시 채움
    "controller": "FR_CTRL_FV2.010.12",
    "servo": "FR_SERVO_FV5.043.16",
    "end": "FR05_End_FV2.010.11",
    "sdk": "C#SDK-V1.2.4",
    "web": "Web-3.9.3"
  }
}
```

비밀번호는 프로필·DB·브라우저 저장소에 넣지 않는다. 향후 SDK에서 일련번호를 읽을 수 있는지
원본 필드 전수 확인 후 `observed` 식별값을 강화한다.

## 화면은 4개 작업 패널 + 상시 안전 바 (2026-08-05 · D74 — 5개에서 줄였다)

상단의 **연결·조종권·Enable·모드·비상정지·충돌·기록 상태 바**는 어느 패널에서도 사라지지
않는다. 본문은 한 화면에 모두 우겨 넣지 않고 다음 4개 작업 패널로 나눈다.

| 패널 | 반드시 넣을 것 | 넣지 않을 것 |
|---|---|---|
| 1. Live | 3D 쌍둥이, 6축/TCP 현재값, 작업영역 경계, 연결 진단, 조그, 그리퍼, 속도 상한, stop | 슬롯 편집·장기 그래프 |
| 2. Teach | 현재 자세 캡처, 지점 목록, 이름·tool/user 좌표계, **궤적 녹화**, 이동 전 **경로 고스트** | 승인·연속 실행 |
| 3. Program | 지점을 카드/슬롯 순서로 조합, move/grip/wait, 버전 diff, draft→approve→run | 임의 코드 편집기 |
| 4. History | 명령·상태·차단 사유·제안·승인·실행 타임라인, 출처(`demo`/`postproc`/`policy`), 필터, 재생, 내보내기 | 실기 명령 재전송 |

**Optimize 패널은 없다** (D74). 후보 비교는 PRD 가 `§범위 밖`("최적해를 찾지 않는다")으로
그었고, 남는 알맹이인 **승인은 Program 이 이미 갖고 있다.** 생산성 비교 화면은 관제화면
(`GOAL-dash-metrics-compare.md` · `GOAL-dash-motion-compare.md`)이 주인이다 —
**FR5 는 `run` 을 내보내고 관제화면이 읽는다.** 비교 화면을 두 곳에 두지 않는다.

스타일은 `Shared/tokens/tokens.css`와 Dashboard의 에디토리얼 아카데믹 규약을 공유한다.
정상·경고·정지·시뮬레이션 색은 의미로만 쓰고, 선택 상태는 흑백 토큰을 쓴다.

### 레이아웃 — 3D 는 고정, 오른쪽만 바뀐다 (2026-08-03 확정)

```
┌─────────────────────────────────────────┐
│ [안전바] phase · 조종권 · 서보 · [STOP]  │  ← 항상
├──────────────────┬──────────────────────┤
│                  │ Live  Teach  Prog  Hist │ ← 탭은 오른쪽에만 붙는다 (넷)
│   3D 쌍둥이       ├──────────────────────┤
│   (항상 보임)      │  선택한 패널          │
│                  ├──────────────────────┤
│                  │ 조그 · 그리퍼 (상시)   │  ← 어느 탭에서도 조작 가능
└──────────────────┴──────────────────────┘
```

**왜 이렇게 하나** — Teach 는 로봇을 조그하며 쓰는 화면이다. 탭이 전체를 갈아치우면
"자세를 만든다 → 캡처한다" 사이에 화면이 두 번 바뀌고, 돌아올 때마다 목록 상태가 리셋된다.
3D 와 조작기를 고정하면 **작업 흐름이 안 끊긴다.**

- 조그·그리퍼 조작대는 오른쪽 아래에 **상시** 둔다. Live 패널의 소유물이 아니다
- 패널 전환은 오른쪽 영역만 바꾼다 — 3D 카메라 각도·선택 상태가 유지된다
- 안전 바와 STOP 은 최상단 고정 (기존 규칙 유지)

### 폰은 보기 전용 (2026-08-03 확정)

**폰·태블릿에서는 상태·기록 확인과 STOP 만 된다.** 조그·캡처·승인 같은 조작은 PC 에서만.
주머니 속 오터치가 로봇을 움직이는 경로를 **구조적으로** 없앤다 — 화면을 좁히는 게 아니라
조작 컨트롤 자체를 내보내지 않는다. STOP 은 예외다: 위험을 줄이는 방향이라 어디서든 받는다.

### 확인 절차는 한 모양으로 (2026-08-03 확정)

위험한 동작은 **전부 같은 모양**을 쓴다 — `[ ] <무슨 일이 일어나는지 한 줄>` 체크박스 +
실행 버튼. ARM · 슬롯 승인 · 정책 실행 · 시연 삭제가 모두 이 형태다. 모양이 다르면
사용자가 매번 새 절차를 배워야 하고, 급할 때 틀린다.

**대신 체크박스 문구가 매번 달라야 한다.** "확인했습니다" 같은 고정 문구는 몇 번 만에
무의미해진다. 무엇이 실제로 일어나는지를 문구가 말한다 — 예: "현장에 사람이 있고 로봇
반경 안에 아무도 없습니다" / "승인하면 이 리비전이 실기에서 실행됩니다".

## 안전 상태와 연결 순서

```text
DISCONNECTED → PREFLIGHT → OBSERVE_ONLY → OWNER_HELD → ARMED → EXECUTING
                       ↘ 실패·불명·연결손실 → FAIL_CLOSED
```

1. 물리 링크와 PC 서브넷을 확인한다.
2. 후보 IP를 ARP/ping으로 찾고 TCP `:8080`을 확인한다. 펜던트의 포트 이름만 믿지 않는다.
3. `Connect → GetVersion → ReadState`까지만 실행해 모델·버전·6축 배열·안전 필드를 검증한다.
4. 이 단계까지는 `OBSERVE_ONLY`이며 로봇을 Enable하거나 모드를 바꾸지 않는다.
5. 조종권, 현장 작업자 확인, 안전조건 19개, 속도/변위 상한을 모두 통과해야 `ARMED`가 된다.
6. 명령 전후 상태와 차단 사유를 기록한다. 연결 손실·필드 누락·버전 불일치는 fail-closed다.

무선은 초기 범위가 아니다. 필요하면 컨트롤러 설정을 임의 변경하지 않고 격리된 AP/브리지로
동일 LAN을 운반한 뒤 지연·손실·재연결 게이트를 별도로 통과시킨다.

## 슬롯과 기록

슬롯은 코드 파일 업로드가 아니라 검증 가능한 선언형 단계 목록을 기본으로 한다. 원시 Python/C#
업로드는 안전 게이트를 우회하므로 범위 밖이다.

```text
draft → approved → active → retired
```

⚠ **`simulated`·`reviewed` 를 뺐다** (2026-08-05 · D74). 시뮬레이터를 안 들이기로 했으니
`simulated` 는 아무도 못 만드는 상태였고, `reviewed` 는 `approved` 와 사람이 같은 동작으로
찍는다. 상태를 늘리면 전이표만 커지고 게이트는 안 세진다. 정본은 `GOAL-program-slots.md`.

- 변경할 때마다 불변 `revisionId`를 만든다. 활성 버전은 포인터만 바꾼다.
- diff는 단계 추가/삭제/순서, 지점값, 속도, 그리퍼, 대기조건을 나란히 보여준다.
- 실기 실행은 `approved` 리비전만 가능하며 당시 robot profile·tool/user·펌웨어를 고정 기록한다.
- 녹화는 명령 이벤트와 상태 샘플을 분리한다. 상태 원본은 보존기간·다운샘플 규칙을 둔다.
- History 재생은 실기 재실행이 아니라 시간축 시각화다.

## 저장 단위와 GPU (2026-08-05 개정 · D74)

저장 단위는 `point`, `trajectory`, `slotRevision`, `run`, `event` 다.
~~`simulationJob`·`candidate`~~ 는 시뮬레이터를 안 들이기로 하면서 **지웠다** — 아무도 안
만드는 이름을 계약에 두면 다음 세션이 그걸 구현해야 하는 줄 안다.

저장은 **`~/fr5-data/` 아래 표준 라이브러리 JSON 파일**이다 (D45 — 배포 트리 밖).
모든 프레임을 행으로 쪼개지 않고 궤적 하나를 파일 하나로 둔다. DB 도입은 부하를 실측한 뒤
결정하고, 그때도 `datasource` 뒤에서 바뀌므로 화면 계약은 안 바뀐다.

**GPU 는 후보 생성이 아니라 정책 학습에만 필요하다** (사다리 6). 학습은 오프라인이고
로봇 옆 브리지에서 돌지 않는다.

## 다른 앱과의 경계

| 소비자 | FR5에서 받는 것 | FR5로 보내는 것 |
|---|---|---|
| Dashboard | 연결·작업·안전 요약, 후보/실측 지표 | 승인된 배치/작업 선택; 로봇 명령은 없음 |
| AR | 로봇 자세, 승인 경로, 작업공간·충돌 표시 | 정합/검토 결과 |
| Vision | 제안과 신뢰도 기록 결과 | 실행이 아닌 `proposal`만 전송 |
| TurtleBot | 협업 실행 상태·hand-off 이벤트 | 슬롯 오케스트레이터를 통한 이벤트 |
| Database | 프로필·슬롯·시뮬레이션·실행·기록 | datasource/bridge 경유 조회 결과 |

FR5와 TurtleBot 브리지는 서로 직접 호출하지 않는다. 협업 순서는 별도 슬롯/오케스트레이터가
두 관문의 클라이언트가 된다.
