# 슬라이스 계획 — AR 겹쳐 보기

분류: 조사 · 2026-07-30 개정 · **주제 확정 전에 만들 수 있는 유일한 슬라이스**

## 두 트랙을 가른다

한 문서에 섞으면 오차를 재다가 회의 시간이 와서 **보여줄 게 없는 상태**가 된다.

| 트랙 | 목적 | 보는 사람 | 우선순위 |
|---|---|---|---|
| **A · 설득** | "AR 됩니다"를 폰으로 보여주기 | 팀원 | **회의 전까지 A를 끝낸다** |
| **B · 실증** | 정합 오차가 쓸 만한지 판단 | 우리 내부 | A 3단계 이후 언제든 |

시간이 부족하면 **B를 미룬다.** A는 미룰 수 없다.

## 왜 이 슬라이스를 먼저 하나

| 이유 | 근거 |
|---|---|
| 주제와 무관 | 무대가 공장이든 카페든 "AR이 된다"는 사실은 안 바뀐다 |
| 로봇 없어도 A트랙 5단계까지 됨 | 마커 한 장 + 폰 |
| 가장 큰 미지를 닫는다 | 정합 오차 ±5~15mm가 **문헌값이고 실측이 아니다** |

수렴 루프(`rnd/V3-PORT-CONVERGE-LOOP-2026-07-29.md`)에서 뽑은 킬-실험이 B트랙이다.

# A트랙 — 설득

## 완료 판정

1. 팀원 3명의 폰(**아이폰 포함**)에서 QR 하나로 열린다
2. **로봇이 궤적을 따라 움직인다** — 정지 모델이 아니라
3. **실물 로봇 옆에서 3D가 겹쳐 보인다** (로봇 접근 가능할 때)
4. **두 사람이 각자 폰으로 동시에 본다**

### 1단계 — HTTPS 먼저 (코드보다 먼저)
Vercel에 빈 페이지를 올려 **폰에서 카메라 권한 창이 뜨는지만** 확인한다.
3D도 마커도 없이. 여기서 막히면 나머지가 의미 없다.

```bash
cd web && vercel --prod
```

판정 — 아이폰 사파리에서 카메라 허용 창이 뜬다.

### 2단계 — 마커 위에 상자 하나
AR.js 최소 예제. 로봇 없이 `BoxGeometry` 하나만.
**떨림과 인식률을 여기서 본다.** 로봇을 올리면 원인 분리가 어려워진다.

판정 — 마커를 비추면 상자가 뜨고, 마커를 가리면 사라진다.

### 3단계 — 상자를 FR5로 교체 ✅ 2026-07-30 완료
`urdf-loader`로 우리 URDF를 마커 좌표계에 붙인다. `Shared/view3d/robot.js` — **AR 전용이 아니라
V0 화면과 공유하는 모듈**이다.

**그리퍼도 함께 붙인다.** URDF에는 팔 링크 7개뿐이라 코드로 `wrist3_link`에 매단다.
데모에서 그리퍼를 빼면 나중에 붙는 순간 "전에 본 것과 다르다"가 된다 —
용량(3.4MB)보다 일관성이 비싸다.

그리퍼 STL은 **밀리미터**, 팔 URDF는 **미터**다. `scale 0.001`을 빼면 1000배로 뜬다.
장착값은 `Shared/data/config/gripper-mount.json`에 있고 실측으로 확정했다
(`evidence/2026-07-30/gripper-mount.md` — 플랜지 간격 0.00mm).

**좌표계가 세 번 꺾인다.**
```
URDF(Z-up) → three.js(Y-up)  : robot.rotation.x = -π/2
three.js → 마커 좌표계        : markerRoot.add(robot)
스케일                        : URDF는 미터. 마커 20cm 기준으로 맞춘다
```

판정 3종 (전부 확인됨)
- 삼각형 **128,584개** (팔 58,482 + 그리퍼 70,102) — `scripts/check/assets.sh` 기준값과 일치
- 그리퍼가 손목 플랜지에 접한다 (1000배로 날아가지도, 파묻히지도 않았다)
- 마커 옆에 실물 크기로 선다. 팔 길이가 922mm로 보인다

**그리퍼 정합은 AR 없이 3D 뷰(`AR/robot.html`)에서 먼저 끝냈다** —
AR 위에서 맞추면 마커 떨림과 정합 오차가 섞여 원인을 못 가른다.

### 4단계 — 궤적 애니메이션 ★ 설득력의 핵심

**정지된 로봇은 3D 뷰어와 구별이 안 된다.** 움직이는 궤적이 있어야 AR이 된다.

이미 검증된 코드가 있다 — FK 보간으로 점 61개, 경로 길이 0.742m
(`evidence/2026-07-29/urdf-web-render.md`).

```
① 시작·끝 관절값 두 개를 잘게 나눈다
② 각 단계마다 FK를 돌려 손끝 위치를 얻는다
③ 점들을 TubeGeometry(가는 관)로 이어 반투명 재질을 씌운다
   — 얇은 Line은 굵기 조절이 안 돼 폰에서 잘 안 보인다
④ 로봇이 그 경로를 따라 움직인다 (관절값 보간 + requestAnimationFrame)
⑤ 재생·정지 버튼 하나
```

**역기구학은 필요 없다.** 저장된 자세가 관절값이고 MoveJ가 관절을 직접 보간하기 때문이다.

판정 — 허공에 경로가 그려지고, 로봇이 그 선을 따라 움직인다. **"이 경로로 지나갑니다"**가 보인다.

### 5단계 — 안전 범위
반투명 원기둥. 반지름은 FR5 도달거리 **922mm**.
궤적이 이 안에 있는지 눈으로 확인된다.

**이게 AR의 실제 용도다** — mm 정밀이 아니라 "여기까지 오지 마라".

### 6단계 — 실물 옆 시연 ★ 비용 0, 효과 최대

로봇에 접근 가능하면 **반드시 이걸 한다.** 허공에 뜬 모델과 실물 위에 겹친 모델은 완전히 다르다.

```
① 마커를 로봇 베이스 옆 고정판이나 테이블에 붙인다
   — 베이스는 알루미늄이라 반사로 인식률이 떨어진다
② 마커 원점 → 로봇 원점 오프셋을 한 번 잰다 (자로)
③ 그 값을 설정 파일에 넣는다. 코드에 박지 않는다
④ 실물과 3D가 겹치는지 확인한다
```

판정 — 화면에서 실물 로봇과 3D 로봇의 윤곽이 겹친다.

### 6.5단계 — 화면 표시 숨기기 (사진·영상용)

실물 위에 겹친 장면을 남길 때 HUD와 버튼바가 정작 봐야 할 곳을 가린다.
**화면 두 번 탭** 또는 우상단 **⤢**로 숨긴다. 되돌릴 길을 남기려 토글 버튼만 남는다.

토글을 **우상단**에 둔 이유 — 하단에 두면 좁은 화면에서 버튼바가 2줄로 접힐 때 겹친다.
"버튼바 높이 + 여유"를 상수로 박는 방식은 줄 수가 바뀌면 깨진다.

`AR/robot.html`도 같은 이유로 패널을 접을 수 있다 — 폰에서 320px 패널이 화면을 거의 덮는다.
좁은 화면에서는 오른쪽 사이드바가 아니라 **아래에서 올라오는 시트**로 바뀐다.

### 7단계 — 폰 2대 동시 ★ 주제와 직결

정적 페이지라 **추가 작업이 없다.** 두 대가 같은 URL을 열면 된다.
각자 다른 각도에서 같은 로봇을 본다.

이게 프로젝트 주제(팀이 함께 쓴다)를 **말이 아니라 장면으로** 보여주는 부분이다.

판정 — 두 사람이 각자 폰으로 동시에 보고, 각도가 달라도 둘 다 제자리에 붙어 있다.

# B트랙 — 실증 (내부용)

A트랙 3단계 이후 언제든. **팀원에게 보여줄 것이 아니다.**

자를 마커 옆에 놓고 화면 속 로봇 베이스 원점이 실제 원점에서 몇 mm 벗어나는지 잰다.

| 거리 | 정면 | 45° | 떨림(폰 고정 시) |
|---|---|---|---|
| 0.5 m | | | |
| 1.0 m | | | |
| 1.5 m | | | |
| 2.0 m | | | |

기록 위치 — `docs/evidence/2026-07-30/ar-marker-accuracy.md`

**나쁜 결과도 결과다.** 오차가 크면 AR의 용도를 "안전 범위 표시"로 좁히면 된다.
회의 전에 아는 게 낫다.

## 파일

```
AR/ar.html                    AR 화면
AR/src/features/marker/ar-marker.js            마커 정합 · 스무딩
Shared/view3d/robot.js           URDF 로드 (3D 슬라이스와 공유)
Shared/view3d/path.js           FK 보간 · 궤적 생성 · 애니메이션
Shared/data/config/marker-offset.json  마커 원점 → 로봇 원점 오프셋
Shared/assets/marker/             마커 패턴
docs/evidence/2026-07-30/ar-marker-accuracy.md
```

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 폰에서 카메라 안 열림 | **1단계에서 먼저 확인.** Vercel HTTPS로 해결됨 |
| 마커 떨림 | 스무딩 옵션. 안 되면 최근 프레임 평균 |
| **약 10MB 첫 로딩** | 로딩 표시(%)를 넣었다. 느리면 그리퍼 몸통(2.9MB)부터 데시메이션 — STL이 이미 바이너리라 형식 변환으로는 못 줄인다 |
| **마커가 바로 안 뜬다** | 검출기가 첫 검출까지 수십 프레임을 먹는다. HUD에 "마커를 찾는 중"을 띄웠다. **2~3초 기다리라고 안내한다** |
| **광택지·연한 인쇄** | 검출을 결정하는 것은 크기가 아니라 흑백 명도차다(약 130 이상 필요). 무광 용지, 100% 배율, 고른 조명 |
| **UI가 카메라 화면을 가림** | 화면을 **두 번 탭**하거나 우상단 **⤢**를 누르면 HUD·버튼바가 숨는다. 실물 옆 시연·사진 촬영용. 상태는 기억된다 |
| 아이폰만 안 됨 | AR.js는 WebXR을 안 쓰므로 원리상 된다. `playsinline` 확인 |
| 로봇 접근 불가 | 6단계를 건너뛴다. 4단계(궤적)에 무게를 싣는다 |
| 오차가 큼 | 용도를 "안전 범위 표시"로 좁힌다 |

## 준비물

- **마커 인쇄** — `Shared/assets/marker/marker-print-A4-170mm-bc5.png` (A4 한 장으로 끝) 또는
  A3 240mm판. 실측 결과 **A4로도 2m는 된다** (`evidence/2026-07-30/marker-detect.md`).
  100% 배율·무광 용지. **딱딱한 판에 평평하게** 붙인다
- 인쇄 후 **검은 사각형 한 변을 자로 재서** `Shared/data/config/marker-offset.json`의
  `markerSizeMm`에 넣는다 — 틀리면 로봇 크기가 틀리고 오차 측정이 무의미해진다
- 자 또는 줄자
- 팀원 폰 **2대 이상** (아이폰 1대 포함)
- 로봇 — **A트랙 5단계까지는 불필요.** 6단계에만 필요

## 배포

**Vercel.** 로봇이 없는 화면이라 정적 배포로 충분하다 (`DECISION-LOG` D9).
로봇 상태를 실시간으로 받는 단계에서는 터널이 필요하다.

## 이 슬라이스가 끝나면 정해지는 것

- AR을 필수로 넣을지, 여유 있으면 할지
- AR의 용도 — 정밀 안내인가, 안전 범위 표시인가
- 회의에서 **"AR 됩니다"를 말이 아니라 폰으로** 보여줄 수 있는지
