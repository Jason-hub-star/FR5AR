## 제1원칙 — 막는 쪽으로 실패한다 (fail-closed)

**값을 못 읽으면 통과가 아니라 차단이다.**

v3의 조건 목록에 `connection service missing` · `gripper readback missing` ·
`boundary data missing` · `dry-run preview artifact missing` 이 있는 이유가 이것이다.
"정보가 없다"를 "문제가 없다"로 읽으면 안 된다.

구현 규칙 — 판정 함수의 기본 반환값은 **차단**이고, 모든 조건을 통과했을 때만 허용으로 바꾼다.
`try/except`에서 예외를 삼키고 허용을 반환하는 코드는 금지한다.

## 제2원칙 — 서버가 강제한다

클라이언트(웹·폰·유니티)를 믿지 않는다. 속도 상한과 조건 검사는 **서버에서만** 한다.
클라이언트의 검사는 사용자 편의를 위한 것이지 안전장치가 아니다.

## 제3원칙 — `stop`은 항상 통과한다

조종권·상한·조건과 무관하게 즉시 실행한다. 정지를 막는 조건은 만들지 않는다.

### 서보 스트리밍 상한 (모방학습 · 2026-08-03 신설)

"한 명령당 5°" 는 **점 대 점(MoveJ)을 전제한 규칙**이다. 8ms 주기로 목표가 흘러드는
`ServoJ` 에는 그대로 쓸 수 없다 — 프레임마다 5° 면 초당 625° 가 된다. 형태를 바꿔 다시 쓴다.

| 항목 | 값 | 근거 |
|---|---|---|
| 관절 각속도 | **≤ 30°/s** (전 축) | 10% 속도 상한의 각속도 환산치. 실측으로 조정한다 |
| 프레임 간 변화 | `각속도 상한 × 실제 경과시간` | 주기가 늦어지면 허용치도 함께 줄어야 한다 |
| 명령 주기 결손 | 연속 3프레임 지연이면 **스트리밍 종료 후 정지** | 끊긴 스트림을 이어붙이면 로봇이 튄다 |
| 스트리밍 최대 지속 | 세션당 상한을 둔다 (값 미정) | 무한 스트림은 사람 확인 없는 장시간 자동 운전이다 |
| 시작·종료 | `ServoMoveStart` / `ServoMoveEnd` 를 반드시 짝으로 | 시작만 하고 끝내지 않으면 다음 명령이 안 먹는다 |

**정지는 여기서도 최우선이다.** 스트리밍 중에도 `stop` 은 잠금을 기다리지 않고 나가며,
`stop` 이 들어오면 스트림 소스를 먼저 끊고 `ServoMoveEnd` 로 닫는다.

## 설정이 전제다 — 조건 4·5·25 는 공짜가 아니다 (2026-08-04 · 공식 매뉴얼 대조)

**우리 게이트는 컨트롤러가 주는 값을 읽는다. 그 값이 만들어지려면 컨트롤러 쪽 설정이
선행돼야 한다.** 매뉴얼을 대조하니 그 전제가 서 있지 않았다.

| 우리 조건 | 전제 | 안 서면 |
|---|---|---|
| 4·5 충돌 | 컨트롤러 **충돌 감지가 켜져 있고 민감도가 설정**됐을 것 | `collisionState` 가 영영 0 — **조건이 종이호랑이가 된다** |
| 4·5·25 | **말단 하중(무게·무게중심)과 설치 방향**이 설정됐을 것 | 매뉴얼 명시 — "드래그 기능과 충돌 감지가 정상 작동하지 않는다" |

- **충돌 감지는 기본으로 켜져 있지 않다.** 매뉴얼상 프로그램 맨 앞에 넣는 명령어로 켠다.
  우리는 펜던트 프로그램을 돌리지 않고 SDK 로 직접 움직이므로 **브리지가 켜야 한다**
- **기본 민감도는 사람 접촉에 반응하지 않는다** — 매뉴얼 원문: "손으로 세게 밀거나 때려도
  반응하지 않을 만큼 둔감하다". 값을 넣지 않는 것은 끈 것과 다르지 않다
- 설정의 **주인은 브리지**다 (D53). ARM 할 때마다 넣는다 — 펜던트에서 누가 바꿔도
  우리 값으로 돌아와야 위 표의 전제가 산다

### 기본인자는 "안전한 기본" 이 아니다 (2026-08-05)

`SetCollisionStrategy(strategy, safeTime, safeDistance, safeVel, safetyMargin[6])` 는
**뒤 4개가 파이썬 기본인자**다. 우리는 `strategy` 하나만 넘겨 왔고, 그래서 감지 **후**
어떻게 서는지를 4개 항목이나 벤더가 대신 골라 주고 있었다. 벤더 SDK 원문(`Robot.py`) 기준:

| 인자 | 범위 | SDK 기본값 |
|---|---|---|
| `safeTime` | 1000~2000ms | 1000 (최솟값) |
| `safeDistance` | 1~150mm | 100 |
| `safeVel` | 50~250mm/s | **250 = 최댓값** |
| `safetyMargin[6]` | 1~10 | **[10]×6 = 최댓값** |

넷 중 셋이 자기 범위의 **가장 느슨한 끝**이다. "충돌 감지를 켰다"는 기록은 있는데
**켠 뒤의 정지 거동은 아무도 안 골랐다**는 뜻이고, SDK 판올림이 기본값을 바꾸면
우리 안전 범위가 diff 한 줄 없이 움직인다.

→ **지금 값은 기본값과 같지만 `config.yaml` 에 박아서 같다.** 옮긴 게 아니라 고정한 것이다.
조이는 것(특히 `safeVel`·`safetyMargin`)은 **실기 확인 뒤에** 한다 — 벤더 문서가 이 값들의
의미(정지 프로파일인지 판정 임계인지)를 주지 않아, 지금 낮추면 근거 없이 낮추는 것이 된다.
강사 자료 예시값 `(0, 200, 50, 20, 10…)` 은 `safeTime` 200·`safeVel` 20 이 **위 범위 밖**이라
그대로 베끼지 않는다. 같은 자료의 `strategy 0`(에러 후 **일시정지**)보다 우리 `2`(에러 후
**정지**)가 강하므로 `strategy` 는 유지한다.

### FR-HMI 가 없다 — 위치 방어선은 우리 소프트리밋 하나다

매뉴얼(안전설정 p14)은 컨트롤러의 **간섭 영역·안전 정지 모드가 3위치 인에이블 장치가 달린
전용 티치펜던트(FR-HMI)를 전제**로 하며, 없으면 "Enable 실패 또는 크래시" 가 날 수 있다고
적는다. 우리 배치에는 FR-HMI 가 없다.

→ **컨트롤러의 위치 기반 안전망을 우리 방어선으로 세지 않는다.** 관절 한계는
`safety.py` 의 URDF 소프트리밋이 사실상 유일한 방어선이다. 그래서 그 값은 낮추지 않고,
컨트롤러가 보고하는 소프트리밋과 **대조해 어긋나면 기록**한다.

## 그리퍼 힘 상한

`MoveGripper` 는 `force` 와 `rotTorque` 를 인자로 받는다 (`STACK.md` §그리퍼).
**상한 없이 부르지 않는다** — 체결처럼 끝에서 힘이 걸리는 작업은 모터 과부하나 작업물 변형으로
끝난다. 기본값은 실물 확인 후 등재하고, 그 전에는 SDK 기본값에 기대지 않는다.

## 아직 확인 안 한 것

- `cmdPointError` 임계값 조절 방법 — 플래그(`c_uint8`)라 조절 불가. 필요하면
  `lastServoTarget`과 실제 관절값 차이를 서버가 직접 계산한다.
- 각 조건의 **판정 주기** — 상태 수신 30Hz 기준으로 몇 프레임 연속이어야 차단할지 미정.
