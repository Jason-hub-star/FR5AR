# SHARED-CORE — `AR` 과 `Dashboard` 의 공용 계약

분류: **SSOT**. 최상위 `Shared/` 안의 것을 정의한다.
**두 폴더가 동시에 깨지는 것은 전부 여기 있다.**

관련 — 폴더 경계 `BUILD-VITE.md` · 관제화면 `CONSOLE-REACT.md` ·
서버 계약 `API-CONTRACT.md` · 단위 규칙 `CODING-CONVENTIONS.md`

## 이 문서가 존재하는 이유

`Dashboard`는 배치안으로 **생산성을 측정**하고, `AR`은 같은 배치안을 실제 실험실
바닥에 **겹쳐서 검증**한다. 둘이 같은 배치안을 봐야 실험이 성립한다.

**모델이 갈라지면 두 화면 다 정상으로 보인다.** 대시보드가 측정한 배치와 AR이
보여주는 배치가 다른데, 어느 쪽에도 에러가 안 뜬다. 폴더는 갈랐지만 레포를 가르지
않은 이유가 이것이고(D17), 그래서 이 문서가 SSOT다.

## `Shared/` 에 넣는 기준

| 넣는다 | 넣지 않는다 |
|---|---|
| `AR`·`Dashboard` 둘 다 쓴다 | 한 쪽만 쓴다 → 그 폴더의 `features/` |
| 바뀌면 양쪽이 **같이** 틀려야 한다 | 한쪽만 영향받는다 |
| 데이터 모양·단위·설정, 바닐라 three 렌더링 | **화면** · React · UI |

**두 층으로 나눈다.** 층을 섞으면 React 가 `Shared` 로 새어 들어온다.

```
Shared/data/     프레임워크 무관. 렌더링 없음
    layout/  scenario/  timeline/  motion/  units/  config/  datasource/
Shared/view3d/     바닐라 three. **React 를 쓰지 않는다**
    robot/  trajectory/  safety/
Shared/assets/    URDF · STL · 마커
```

`Shared/`에 **화면을 두지 않는다.** 화면은 `AR/` 또는 `Dashboard/` 안에만 있다.
`Shared/`가 위 목록 밖으로 커지면 경계가 무너진 신호다.

## 1. `Shared/data/layout/` — 배치안 모델

새 목표(방산 탄두 **조립** 라인에서 팔+AMR 배치별 생산성 비교 · D51·D66)의 본체다.

### 원점 규칙 — 여기가 제일 잘 틀린다

**배치안의 원점은 실험실 바닥의 한 지점이다. 로봇 베이스가 아니다.**

로봇 팔의 위치가 **배치안의 변수**다. 로봇 베이스를 원점으로 삼으면 배치를 바꿀 때
좌표계가 따라 움직여 **배치안 A와 B를 비교할 수 없다.** 실험 자체가 무의미해진다.

| 항목 | 값 |
|---|---|
| 원점 | 실험실 바닥의 고정된 한 점 (AR 마커를 붙일 자리) |
| 축 | x·y = 바닥 평면, **z = 위** (Z-up) |
| 단위 | **밀리미터(mm) · 도(°)** — 계약의 바깥면은 항상 이것 |

**AR 마커도 바닥 원점에 붙인다.** 지금은 마커가 로봇 베이스 기준이라
`.env`의 `FR5_MARKER_TO_ROBOT_MM`이 `0,0,0`이다. 새 목표에서는 팔 위치가
배치안에서 오므로 **그 설정값의 역할이 없어진다** — 이관 시 함께 정리한다.

### 모양

```jsonc
{
  "id": "A",
  "name": "배치안 A — 팔을 중앙에",
  "unit": "mm-deg",                    // 고정. 다른 값을 쓰지 않는다
  "floor":  { "widthMm": 6000, "depthMm": 4000 },
  "arms": [                            // **배열이다.** 한 대짜리도 배열로 쓴다
    { "id": "fr5", "model": "FR5", "role": "process",   // 공정 — 실물이 있는 팔
      "basePosMm": [1500, 2000, 900],  // 바닥 원점 기준. z = 작업대 높이
      "baseYawDeg": 0,
      "reachMm": 922 },                // FR5 스펙값 — 편집 대상이 아니다
    { "id": "tf1", "model": "transfer", "role": "transfer",  // 이송 — **실물 없음**
      "basePosMm": [3000, 1200, 900], "baseYawDeg": 90, "reachMm": 800 }
  ],
  "stations": [
    { "id": "in",   "name": "시료 투입", "posMm": [800, 2000, 900] },
    { "id": "meas", "name": "계측기",    "posMm": [2200, 2000, 900] }
  ],
  "amr": {
    "model": "TurtleBot",
    "dockPosMm":   [500, 500, 0],
    "waypointsMm": [[500,500], [1500,800], [3000,2000]]   // 바닥 평면 2D
  },
  "zones": [                           // 바닥 구역 (2026-08-04). 아래 §zones
    { "id": "nogo1", "kind": "keepout", "name": "팔 작업반경",
      "polygonMm": [[2000,1500], [3200,1500], [3200,2600], [2000,2600]] }
  ],
  "verified": false                    // 실측으로 확인했나
}
```

### `arms[]` — 팔이 여럿일 수 있다 (2026-08-04)

전에는 `arm` 하나였다. 조립 셀에 **투입·배출 컨베이어**가 붙으면서 이송을 맡는 팔이
따로 서고, 단일 필드로는 그걸 못 적는다. 그래서 배열로 바꿨다.

| 칸 | 뜻 |
|---|---|
| `id` | 배치안 안에서 안 겹치는 이름. 편집·선택이 이걸로 붙는다 |
| `model` | `FR5` 면 URDF 실물 모형을 세운다. 그 외는 **절차적 팔**로 그린다 |
| `role` | `process`(공정 — 실물이 있다) · `transfer`(이송 — **실물이 없다**) |

⚠ **`role: "transfer"` 는 실물이 없다.** 화면에만 있는 팔이고, 그래서 `model` 을
`FR5` 로 두지 않는다 — 같은 모형을 두 개 세우면 **어느 쪽이 진짜인지 화면이 말하지 못한다.**
`화면=실물` 전제가 이 프로젝트에서 가장 비싼 오해다 (SR_24 · AR 겹쳐 보기).
실측 수치를 이 팔에 붙이지 않는다.

**옛 배치안(`arm` 하나)은 읽을 때 자동으로 배열이 된다** — `migrateLayout()` 한 곳에서만
한다(하드 룰 5). 저장분을 손으로 고치게 하지 않는다.

### `zones[]` — 바닥 구역 (2026-08-04)

**AMR 이 들어가면 안 되는 곳·충전하는 곳·조건부로만 들어가는 곳**을 배치안이 가진다.
없던 개념이라 새로 연다 — 로봇이 실제로 그 공간에 들어왔을 때 판정할 근거가 여기다.

| 칸 | 뜻 |
|---|---|
| `id` | 배치안 안에서 안 겹친다 |
| `kind` | `keepout`(진입 금지) · `charge`(충전소) · `restricted`(조건부 진입) — **이 셋뿐** |
| `name` | 사람이 읽는 이름 |
| `polygonMm` | 바닥 평면 다각형 `[[x,y], …]` **3점 이상**. 볼록일 필요 없다 |

**바닥 평면 2D 다.** 높이를 안 준다 — AMR 은 바닥을 굴러다니고, 높이를 넣는 순간
"어디까지가 구역인가"를 팔·소품과 또 맞춰야 한다. 필요해지면 그때 연다.

**`charge` 는 `amr.dockPosMm` 과 다른 것이다.** 도킹 **지점**은 그대로 `dockPosMm` 이고,
`charge` 구역은 **그 지점에 접근하는 자리**다 — 다른 로봇이 거기 서 있으면 충전을 못 한다.
지점과 구역을 한 칸에 합치면 "막혔다"를 표현할 방법이 없어진다.

#### 판정 규칙 — **로봇은 점이 아니다**

진입 판정은 **중심점이 아니라 로봇 반경을 포함**해서 한다. 중심으로만 보면 몸통이
반쯤 들어간 상태가 "밖"으로 읽힌다. 즉 `구역까지의 거리 < 로봇 반경` 이면 진입이다.

그리고 **들어가는 판정과 나오는 판정을 다르게 둔다.** pose 는 1Hz 이고 떨린다 —
같은 문턱을 쓰면 경계에서 진입/이탈이 깜빡인다. **진입은 즉시, 이탈은 여유를 두고**
판정한다 (`Shared/data/layout/schema.js` `zoneHits()`).

#### 좌표계 — 여기가 진짜 관문이다

구역은 **실험실 바닥 원점** 기준 mm 인데 로봇 pose 는 **SLAM 맵 원점** 기준이다.
둘을 잇는 `mapToLab` 이 아직 없다 (`TB-CONTRACT.md` §미래 접점 ③ · 측정 절차는 P4).
**변환은 브리지 경계 한 곳에서만** 한다 — 화면마다 하면 화면마다 다른 자리를 본다.

#### 누가 무엇을 하나 — 섞으면 안전이 깨진다

| 누가 | 무엇 |
|---|---|
| **배치안** | 구역을 소유한다 (SSOT) |
| **브리지** | 구역을 Nav2 keepout 으로 넘긴다 · `mapToLab` 변환 |
| **화면(AR·관제)** | **읽기 전용**으로 그리고 위반을 알린다 |

⚠ **화면이 "들어가지 마"를 로봇에 직접 보내지 않는다.** 회피는 로봇의 planner 가 한다
(하드 룰 4 · `TB-CONTRACT.md` §미래 접점 ④ "AR 은 읽기 전용 소비자"). 화면은 눈이지 손이 아니다.

### 두 폴더가 이 모델로 무엇을 하나

| | `AR/` | `Dashboard/` |
|---|---|---|
| `arms[].basePosMm` | 그 자리에 팔을 세운다 | 편집한다 |
| `arms[].reachMm` | 바닥에 도달 링을 그린다 | 스테이션이 **어느 팔의** 링 안인지 검사한다 |
| `stations` | 실물 작업대와 겹치는지 본다 | 편집한다 |
| `amr.waypointsMm` | 바닥에 경로를 그린다 | 이동거리를 계산한다 |

**AR은 읽기만 한다. 편집은 관제화면만 한다.** 폰에서 배치를 고치면 누가 무엇을
측정한 건지 알 수 없어진다.

### 아직 안 정해진 것

- **스테이션 종류·개수** — 실험 시나리오가 정해져야 나온다
- **작업대 높이(`z`)** — 실측 필요
- ~~AMR 모델~~ — **TurtleBot3 Burger ×2 로 확정** (D31 · `TB-CONTRACT.md`)
- **배치안을 어디에 저장하나** — 파일 / 브리지 서버 / 브라우저. `API-CONTRACT.md` 참조

**미확정인 채로 코드를 짜지 않는다.** 원점 규칙과 단위만 먼저 굳혀도 충돌은 막힌다.

## 1.5 `Shared/data/timeline/` — **배치안은 공간, series 는 시간**

배치안 모델에는 **시간이 없다.** `floor`·`arm`·`stations`·`amrs` 는 전부 "무엇이 어디에"다.
그런데 F8(생산성)·F10(동작 비교)·V4(기록 되감기)는 전부 **"언제 무슨 일이 있었나"** 를 묻는다.

**그 축을 배치안에 넣지 않는다.** 같은 배치안 위에서 시간만 다른 실행이 여러 벌이기
때문이다 — 그게 F10 의 정의다(같은 배치, 동작 A·B·C). 시간은 **별도 목록**으로 온다.

```jsonc
// series — 한 사이클(= 1발 조립 · D51·D66)에 일어난 일. 시각 오름차순. **stage 는 3 → 0**
[
  { "tSec": 0,  "event": "pick", "station": "pile", "stage": 3 },
  { "tSec": 9,  "event": "move", "station": "lift" },
  { "tSec": 16, "event": "join", "station": "lift", "stage": 2 },
  { "tSec": 36, "event": "out",  "station": "exit" }
]
```

| 칸 | 뜻 |
|---|---|
| `tSec` | 사이클 시작부터의 초. **필수** |
| `event` | 무슨 일 — `pick`·`feed`·`move`·`hold`·`join`·`hoist`·`drop`·`out` 따위. 표시용 이름이다 |
| `station` | 그때 **작업물**이 있는 스테이션 id. 좌표가 아니다 — 배치안이 좌표를 안다 |
| `armAt` | (선택) 그때 **팔이 향하는** 스테이션 id. 없으면 `station` 을 본다 |
| `amr` · `amrAt` | (선택) **어느 AMR 이 어느 스테이션으로** 가나. 짝으로 적는다 |
| `stage` | 탄두 **완성도** 0(완성)~3(빈 케이싱). 조립은 3→0. 안 적으면 **직전 값이 이어진다** |

**좌표를 series 에 넣지 않는다.** 넣으면 배치안을 옮겨도 재생이 옛 자리에서 돌고,
같은 series 를 배치안 A·B 에 태워 비교할 수 없다 — F8 이 무너진다.

**`amr`/`amrAt` 도 같은 이유다** — AMR 이 팔레트로 붙는 동안 작업물은 아직 팔레트 위에 있다.
한 사건이 **세 가지 자리**(작업물·팔·AMR)를 동시에 말할 수 있어야 한 사이클이 한 줄로 적힌다.

**`armAt` 이 따로 있는 이유** — 팔이 신관을 가지러 트레이에 갈 때 **작업물은 리프터에 그대로
있다.** `station` 하나로 두면 그 장면에서 탄두가 트레이로 날아간다. 작업물의 자리와
팔이 보는 곳은 **다른 값**이다 (2026-08-04).

### `stateAt(series, tSec)` — 시간 → 그 순간의 상태

```jsonc
{ "tSec": 12.4, "cycleSec": 24, "u": 0.516,
  "event": "join", "from": "lift", "to": "lift", "k": 0.35,   // from→to 사이 k 지점
  "warheadStage": 2, "empty": false }
```

- **순수 함수다.** 렌더링·React·전역 상태를 안 쓴다. `Shared/view3d/` 가 이걸 받아 그린다
- **결정적이다** — 같은 `t` 를 두 번 물으면 같은 값이다. 이게 성립해야 되감기가 성립한다
- 범위 밖 `t`·빈 목록·뒤섞인 순서에서 **던지지 않는다.** 편집 중에는 잠깐 틀린 상태가 정상이다
- `from`/`to` 를 좌표로 푸는 것은 **화면 쪽 일**이다 (배치안이 스테이션 좌표를 안다)

### 이 축을 쓰는 곳

| | 무엇을 |
|---|---|
| `Dashboard/` 배치 화면 | 작업물이 라인을 따라 흐르고 탄두가 단계별로 **합쳐진다** |
| `Dashboard/` 비교 화면 | 사이클 타임 · **동작 A·B·C 나란히 재생** (F10) |
| `AR/` | 아직 안 쓴다 — 폰에서 재생을 돌릴지는 정하지 않았다 |

**천장** — 관절 각은 **손으로 적은 키프레임**이지 잰 궤적이 아니다. 실기 시연 녹화가 오면
자세표를 그 값으로 바꿔 끼운다(`GOAL-imitation-demo.md`). **없는 궤적을 지어내지 않는다** —
움직이는 로봇은 숫자보다 훨씬 강하게 실물로 읽힌다.

## 1.6 `Shared/data/motion/` — **팔이 어떤 모양인가** (2026-08-04)

배치안이 공간을, `series` 가 시간을 든다면 여기는 **자세**를 든다.

2026-08-04 까지 이 표는 `Dashboard/src/features/layout/LayoutView.jsx` 안에 있었다.
React 파일이라 **`AR` 도 게이트도 못 읽었다** — 자세 이름에 오타가 나도 화면은 안 죽고
조용히 대기 자세로 넘어가서, 오타 하나가 "저 팔은 원래 저기서 안 움직여" 로 산다.
내리는 순간 `scripts/check/motion.sh` 가 생겼고 **첫 실행에서 NaN 버그를 잡았다.**

```
POSES        자세 이름 → { j1..j6 }     home · grip · unscrew · lowPile …
POSE_AT      사건 → 자세 두 벌          조립 팔
FEED_POSE_AT 사건 → 자세 두 벌          투입 팔 (역할이 다르면 뻗는 방향이 다르다)
CARRY_BY_ARM 사건 → 어느 팔이 들고 있나
poseFor(st, { feed })                   ← 화면은 이것만 부른다
```

**`j1` 은 자세에 없다.** 목표를 겨누는 각이라 배치안이 정하고(`view.armAim()`),
화면이 `easeAngle` 로 따라가게 얹는다. 자세가 `j1` 을 들면 팔이 배치안을 무시한다.

**관절 각을 `series` 에 박지 않는다** — §1.5 가 좌표를 금지하는 것과 같은 이유다.
팔을 200mm 옮기면 녹화한 각이 허공을 가리키고, **같은 시나리오를 배치안 A·B 에 못 태운다(F8).**
사건은 **이름**(`event`)을 부르고, 그 이름이 어떤 자세인지는 이 표가 안다.

**모르는 사건은 던지지 않고 대기 자세로 간다.** 계약상 `event` 는 자유 문자열이라
화면이 죽으면 안 된다 — 대신 게이트가 **어느 사건이 대기 자세로 서 있는지 매번 적는다.**

## 1.7 `Shared/data/scenario/` — **시간축을 담아 두는 그릇** (2026-08-04)

§1.5 가 `stateAt(series, t)` **함수**를 정했다면 여기는 그 `series` 를 **저장하는 모양**이다.
2026-08-04 까지 시나리오는 `datasource/mock.js` 안 `DEMO_CYCLE` **상수**였다 — 코드지
데이터가 아니라서 고칠 방법도, 배치안마다 다르게 줄 방법도 없었다.

```js
{
  id: 's1',
  name: '조립 라인 · 49초',
  unit: 'mm-deg',                       // 배치안과 같은 표식. 미래의 이관을 위해 둔다
  events: [
    { tSec: 0,  event: 'haul', station: 'pile', stage: 3 },
    { tSec: 4,  event: 'pick', station: 'pile', amr: 'amr1', amrAt: 'pile', stage: 3 },
    // …
  ],
}
```

**사건이 들 수 있는 것은 이름과 숫자뿐이다.**

| 칸 | 뜻 |
|---|---|
| `tSec` | 사이클 시작부터의 초. **유일한 필수 칸** |
| `event` | 무슨 일인가. 자유 문자열 — 모르는 이름은 화면이 그대로 보여준다 |
| `station` | 작업물이 있는 **자리 id** |
| `armAt` | 팔이 보는 **자리 id**. 작업물 자리와 다를 수 있다 |
| `pose` | 역할별 **자세 이름** — `{ process: ['grip','unscrew'], feed: '...' }` |
| `carry` | 이 구간에 물건을 든 역할 (`process`\|`feed`) |
| `amr` · `amrAt` | 어느 AMR 이 어느 자리로 |
| `stage` | 탄두 단계. 안 적으면 직전 값이 이어진다 |

**넣으면 안 되는 것 둘.**

- **좌표** — §1.5 그대로다. 박으면 같은 시나리오를 배치안 A·B 에 못 태운다
- **관절 각** — §1.6 그대로다. 팔을 200mm 옮기면 녹화한 각이 허공을 가리킨다

**`pose` 는 이름이지 각도가 아니다** (2026-08-04). 그래서 검사는 칸 이름이 아니라 **값의
모양**으로 가른다 — 문자열이면 통과, 숫자·객체면 거부. 칸 이름만 막으면 자세를 아예 못 부른다.

**역할 키는 `process`/`feed` 이고 배치안의 팔 id 가 아니다.** 팔 id 를 쓰면 그 시나리오가
배치안 하나에 묶여 F8 이 무너진다. 단 **지금 화면은 역할 필드가 아니라 자리로 가른다** —
`layout-view.js` `feedArmIds()` 가 `load` 자리에 닿는 팔을 투입 팔로 본다. 다음 사람이
`arms[].role` 을 찾다 못 찾을 자리라 여기 적어 둔다.

**사건이 자세를 들기 전에는 전역 표**(`POSE_AT`·`FEED_POSE_AT`·`CARRY_BY_ARM`)가 사건 **이름**으로
자세를 정했다. 이름을 자유롭게 지으면 그 표가 이름을 몰라 팔이 조용히 대기 자세로 선다 —
그래서 사건이 직접 들게 했다. 표는 옛 저장분을 위한 폴백으로만 남고 `migrateScenario` 가 채운다.

둘 다 **`validateScenario` 가 거부하고 `scripts/check/scenario.sh` 가 지킨다.** 규약만 적어
두면 다음 화면이 또 박는다 — 그게 이 파일에 게이트가 따라붙는 이유다.

**프리셋과 저장분은 다른 것이다.** `presets.js` 가 출하되는 기본값을 들고, 꺼낸 뒤로는 그냥
데이터라 프리셋과 인연이 끊긴다 (배치안의 D56 과 같은 규칙). **저장소가 비어도 재생이 돈다.**

## 2. `Shared/data/units/` — 변환은 여기 한 곳만

**하드 룰 5.** 지금 변환이 `robot-view.js` 안에 흩어져 있는데, "한 곳"이
명시적 모듈이 아니다. 이관할 때 여기로 모은다.

| 곳 | 단위 | 축 |
|---|---|---|
| 배치안 · 서버 계약 · 로봇 API | **mm · 도(°)** | Z-up |
| URDF · three.js 내부 | m · 라디안 | Z-up |
| three.js 화면 | m · 라디안 | **Y-up** → `rotation.x = -π/2` |
| AR 마커 좌표 | **마커 한 변 = 1** | `scale = 1000 / 마커mm` |

실측으로 알아낸 것 둘 — 지우지 말 것.

- **그리퍼 STL은 밀리미터, 팔 URDF는 미터다.** `meshScale: 0.001` 없이 붙이면 1000배로 뜬다
- **궤적 점은 로봇 로컬 좌표로 돌려준다.** 월드 좌표로 주면 AR 마커 스케일(약 7배)이
  섞여 경로 길이가 그만큼 늘어난다 — 실제로 4.754m로 나온 적이 있다 (정답 0.951m)

## 2.5 슬롯 — 마커·맵을 이름으로 교체한다

**지금 문제** — 마커를 바꾸려면 `.env` 에서 숫자 셋(`BARCODE` `MM` `TO_ROBOT_MM`)을
같이 고쳐야 한다. 하나만 어긋나면 화면에 아무것도 안 뜨고 콘솔 에러도 없다.
맵(실험실 도면)이 생기면 같은 문제가 반복된다.

**해법 — 슬롯을 파일에 두고 `.env` 는 "어느 슬롯" 만 고른다.**

```
Shared/data/config/slots/markers.json   ← 커밋한다. 팀이 같이 본다
Shared/data/config/slots/maps.json      ← 커밋한다
.env                                     ← 커밋 안 한다. 기계마다 다른 "선택"
```

```jsonc
// slots/markers.json — 인쇄한 마커마다 한 칸
{
  "lab-a4": { "barcode": 2, "sizeMm": 143, "label": "실험실 A4 인쇄본",
              "note": "프린터가 84% 로 줄여서 실측 143mm", "verified": true },
  "lab-a3": { "barcode": 5, "sizeMm": 240, "label": "실험실 A3", "verified": false }
}
```

```bash
# .env — 한 줄만 바꾼다
FR5_ACTIVE_MARKER=lab-a4
FR5_ACTIVE_MAP=lab-2f
```

**왜 이 갈라치기인가**

| | 어디에 | 왜 |
|---|---|---|
| 슬롯 **정의** | JSON (커밋) | 중첩 구조다. `.env` 는 평평한 key=value 라 안 맞는다. 그리고 **팀이 같이 봐야 한다** |
| 활성 슬롯 **선택** | `.env` (커밋 안 함) | 기계마다·사람마다 다르다. 내 폰은 A4, 발표는 A3 |
| 결과 | 생성된 JSON | 산출물. 손으로 안 고친다 |

- **생성기가 없는 슬롯 이름을 거부한다** — 오타가 런타임까지 안 간다
- URL 로 그 폰만 임시 교체 — `?marker=lab-a3` (지금의 `?bc=`·`?mm=` 을 대체)
- `⚙` 는 그대로 — 잰 값을 즉시 넣는 용도다

**구현 시점** — Vite 이관과 함께 한다. 지금 `config.mjs` 를 고치면 곧 옮길 경로에
코드를 쓰는 셈이다. 그때 `/맵교체` 명령도 같이 만든다 (`~/.claude/commands.md` 의
로봇 예시가 그 이름이다) — 지금 만들면 없는 기능을 부르는 명령이 된다.

## 3. `Shared/data/config/` — `.env` 가 SSOT

브라우저는 환경변수를 읽을 수 없다. 그래서 `.env`를 SSOT로 두고 JSON으로 굽는다.

```bash
vi .env
node scripts/build/config.mjs      # → Shared/data/config/*.json
```

- **JSON은 산출물이다.** 손으로 고치면 다음 생성에서 사라지고, 게이트가 잡는다
- 값이 범위를 벗어나거나 바코드 원본이 없으면 **생성 자체가 멈춘다.**
  번호가 틀리면 화면에 아무것도 안 뜨는데 콘솔 에러도 없어서, 미리 막는 편이 싸다
- Vite에서는 **fetch 하지 않고 빌드 시 import 한다** — 파일이 깨지면 빌드가 실패한다
  (`BUILD-VITE.md` §설정)
- 우선순위: **URL 파라미터 > `⚙` 저장값 > 생성된 JSON**. 앞의 둘은 그 폰에서만이다

## 4. `Shared/data/datasource/` — 데이터가 어디서 오는지 아는 유일한 곳

**우리 몫은 시각화다.** 생산성 수치는 팀원 알고리즘이 내고, 나중에 데이터베이스·백엔드가
붙는다 (`ARCHITECTURE.md` §우리 몫·§확장성). 그 변화를 **화면이 겪지 않게** 하는 경계다.

```
Shared/data/datasource/
  index.js     화면이 부르는 함수들 — getLayouts() · getMetrics(layoutId)
  mock.js      지금: 손으로 만든 JSON (배치안 A·B)
  http.js      나중: 팀원 API · 백엔드 · 데이터베이스
```

| 규칙 | 왜 |
|---|---|
| **화면은 `fetch`를 직접 부르지 않는다** | 출처가 화면에 박히면 백엔드를 붙일 때 화면을 다시 짠다 |
| 목업 → 실물 교체가 **파일 한 개**여야 한다 | 이 경계의 완료 판정이다 |
| 응답에 **`source`**(`mock`/`sim`/`measured`)를 싣고 **화면에 표시**한다 | 목업을 실측으로 오인해 보고하는 것이 가장 비싼 사고다 |
| 선택 필드가 없으면 그 칸만 비운다 | 팀원이 처리량 하나만 내도 화면이 그날 돈다 |

받는 모양은 `API-CONTRACT.md` §생산성 지표에 있다 — **우리가 제시하는 요구 모양**이고,
필수는 `throughputPerHour`와 `cycleTimeSec.mean` 둘뿐이다.
