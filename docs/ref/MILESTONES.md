# MILESTONES — 마일스톤

> 각 단계는 AC를 2~3개 충족해야 완료한다.
> 갱신 2026-07-30 — 목표 확정(`PRD.md`)으로 **L1~L3이 V0 앞에 붙었다.**

## 순서가 바뀐 이유

목표가 **배치별 생산성 비교**로 확정됐고, **우리 몫은 시각화**다
(`ARCHITECTURE.md` §우리 몫). 그래서 순서가 뒤집혔다.

| | 서버가 필요한가 | 팀원 코드가 필요한가 |
|---|---|---|
| **L1~L3 (배치 실험)** | **아니오** | **아니오** — 목업으로 판정이 선다 |
| V0~V4 (플랫폼) | 예 (`server/` 미착수) | 아니오 |

**막힌 것이 없는 쪽을 먼저 한다.** V0는 브리지 서버 코드가 아직 없고
Fairino SDK 설치 경로도 미확인이다. L1~L3은 지금 당장 갈 수 있다.

L1~L3이 끝나면 **목업 숫자로 성공 판정 문장이 화면에서 나온다.**
그 뒤 V0~V4가 실물 수치를 그 자리에 채운다.

## L1 배치안 편집 (F7)

**목표:** 평면도에서 팔·스테이션·AMR 경로를 옮겨 배치안을 만들고 저장한다.

### Acceptance Criteria

- [ ] 배치안 두 개(A·B)를 만들어 이름으로 구별하고 다시 불러온다.
- [ ] 좌표가 **실험실 바닥 원점 기준 mm·도**로 저장된다 (SR_23).
- [ ] 스테이션이 팔의 도달 범위(922mm) 밖이면 경고가 뜬다 (UR_24).

## L2 배치안 AR 검증 (F9)

**목표:** 폰으로 실제 바닥에 배치안을 겹쳐 통로·작업대와 충돌하는지 본다.

### Acceptance Criteria

- [ ] 마커를 비추면 배치안의 팔·스테이션·AMR 경로가 바닥에 겹쳐 보인다.
- [ ] 관제화면에서 고친 배치안이 폰에서 **같은 값으로** 보인다 (모델이 갈라지지 않았다).
- [ ] AR 화면에서 배치안을 고칠 수 없다 (읽기 전용).

## L3 생산성 비교 (F8)

**목표:** 배치안 두 개의 지표를 나란히 보고 차이를 % 로 말한다. **목업으로 완성한다.**

### Acceptance Criteria

- [ ] 목업 두 개로 비교 화면이 동작하고 "A가 B보다 몇 % 낫다"가 화면에 나온다.
- [ ] 출처(`mock`/`sim`/`measured`)가 화면에 표시된다 (SR_24).
- [ ] 선택 지표 필드를 지워도 그 칸만 비고 화면이 죽지 않는다 (SR_25).
- [ ] 목업→실물 교체가 `Shared/data/datasource/` **파일 한 개**로 끝난다 (SR_26).

## V0 브리지 + 상태 스트림

**목표:** `:5055` 브리지 서버가 로봇 관절·TCP·모드·안전코드를보낸다. Mock 모드를 동시에 지원한다.

### Acceptance Criteria

- [ ] 브리지 서버가 `GET /state`로 로봇 상태를 반환한다. Mock 모드에서는 가짜 관절값이 흐른다.
- [ ] WebSocket `/ws/state`로 초당 30회 브로드캐스트한다. 접속한 전원이 같은 값을 받는다.
- [ ] 브라우저 한 탭에서 6축 관절값이 실시간으로 흐른다.

## V1 웹 티칭 펜던트

**목표:** 웹에서 조그·자세 저장·시퀀스 재생·비상정지를 하고, 3D URDF가 브라우저에서 렌더된다.

### Acceptance Criteria

- [ ] 팀원이 자기 노트북 브라우저에서 관절을 움직인다.
- [ ] 실물이 움직이면 브라우저 3D 로봇도 같은 자세로 움직인다.
- [ ] 이동 지점을 저장하고 다른 사람이 불러서 재생한다.

## V2 조종권 + 다중 접속

**목표:** 세 명이 동시에 접속하고 한 명만 조종하며 나머지는 관전한다.

### Acceptance Criteria

- [ ] 세 명이 같은 WebSocket에 접속하면 접속자 목록이 보인다.
- [ ] 조종권이 있는 한 사람만 로봇 명령이 통과한다.
- [ ] 조종권이 없는 사람이 명령을내면 거부되고 사유가 표시된다.

## V3 폰 겹쳐 보기

**목표:** 마커 위에 로봇과 예정 경로를 겹친다. QR 하나로 다른 사람 폰에서 뜬다.

### Acceptance Criteria

- [ ] 앱 설치 없이 QR로 폰에서 AR 화면이 열린다.
- [ ] 마커를 비추면 로봇 베이스 위치가 정합된다.
- [ ] 저장된 지점과 예정 경로가 실물 위에 겹쳐 보인다.

## V4 기록·되감기

**목표:** 명령·상태가 남고 나중에 타임라인에서 다시 재생해 원인을 짚는다.

### Acceptance Criteria

- [ ] 조종·상태·안전코드가 시간순으로 기록된다.
- [ ] 지난 시연을 타임라인에서 다시 재생한다.
- [ ] 기록을 보고 어떤 명령이 어떤 결과를 냈는지 판단할 수 있다.
