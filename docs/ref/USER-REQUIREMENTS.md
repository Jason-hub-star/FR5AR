# USER-REQUIREMENTS — 사용자 요구정의서

분류: **SSOT**. 이 문서가 답하는 질문 — **누가 쓰고, 무엇을 할 수 있어야 하는가.**
근거: v3 화면 21개(화면 13 + 팝업 8) · 버튼 192개 · 안전 조건 24개 · SDK 필드 150개
관련: `PRD.md`(왜) · `FEATURE-SPEC.md`(F1~F6) · `MILESTONES.md`(언제) · `SAFETY-RULES.md`(안전)

## 1. 사용자 정의

| # | 사용자 | 상황 | 가장 원하는 것 |
|---|---|---|---|
| P1 | **조작자** | 조종권을 갖고 로봇을 움직인다 | 지금 로봇이 어떤 상태인지 확실히 알고 움직이기 |
| P2 | **관전자** | 로봇은 한 대, 사람은 여럿. 순서를 기다린다 | 남이 조작하는 걸 같은 화면으로 보기 |
| P3 | **안전 감시자** | 로봇 옆에 서 있다 | 어디까지 다가가도 되는지 눈으로 확인 |
| P4 | **발표자** | 시연하며 설명한다 | 로봇 없이도 화면으로 보여주기 · 지난 시연 재생 |
| P5 | **문제 해결자** | 안 될 때 원인을 찾는다 | 무엇이 왜 막혔는지 화면에서 알기 |

**P2가 이 프로젝트의 존재 이유다.** 지금은 로봇 앞에 앉은 한 사람만 쓸 수 있다.

## 6. 무엇부터 만드나

**표시 전용 화면 4개가 1순위다** — 상태판·안전 진단·오류 알림·도움말.
버튼이 0~2개고 라벨만 많다. **상태 스트림(SR_02) 하나만 붙으면 네 화면이 동시에 살아난다.**

조작 화면(조그·포인트)은 명령을 보내야 하므로 안전 판정(SR_12)과 확인 대화(SR_13)가 먼저 서야 한다.
순서를 바꾸면 안전장치 없는 조작 화면이 먼저 생긴다.

**포인트·시퀀스 화면은 마지막에 손댄다.** 버튼 74개짜리를 한 슬라이스에 넣으면 끝나지 않는다.
최소 세 슬라이스로 쪼갠다 — 목록 조회 / 저장·삭제 / 시퀀스 편집.

## 7. 범위 밖

- 역기구학 — 손끝 좌표를 직접 지정하는 이동. 저장된 관절값 재생으로 충분하다
- AR로 mm 단위 정렬 — 마커 오차가 ±5~15mm라 불가능하다
- 자율 작업 계획 — 사람이 가르친 것만 재생한다
- 프로그램 편집기 — v3의 Lua/블록 편집은 이번 범위 밖

## 8. 아직 정하지 않은 것

- **무대(배경)** — 시연 시나리오가 여기서 나온다. V1까지는 영향 없다
- 기록 저장소 — 파일 / SQLite / Supabase
- 조종권 이전 방식 — 선착순 / 대기열 / 관리자 지정
