# PRD — 무엇을 왜 만드는가

분류: **SSOT**. 범위가 헷갈릴 때 여기로 돌아온다.

## 문제

지금은 **로봇 앞에 앉은 한 사람만** 조작할 수 있다. 티칭한 자세는 그 사람 PC에만 남고,
저장된 지점이 실제 공간의 어디인지는 관절 각도 숫자 6개로만 보여서 아무도 모른다.
팀이 다섯인데 로봇은 한 대라 나머지 넷은 기다린다.

## 만들 것

**브라우저 하나로 팀 전체가 함께 쓰는 로봇 작업대.**

| # | 기능 | 완료 판정 |
|---|---|---|
| F1 | 웹에서 로봇 조작 | 팀원이 자기 노트북 브라우저에서 관절을 움직인다 |
| F2 | 화면 속 쌍둥이 | 실물이 움직이면 브라우저의 3D 로봇도 같이 움직인다 |
| F3 | 이동 지점 공유 | A가 저장한 지점을 B가 불러 재생한다 |
| F4 | 폰으로 겹쳐 보기 | 앱 설치 없이 QR로 열어 실물 위에 지점·경로가 보인다 |
| F5 | 조종권 | 지금 누가 조종 중인지 보이고, 나머지는 관전한다 |
| F6 | 기록 | 명령·상태가 남고 나중에 되돌려 본다 |

## 범위 밖 (이번에 안 한다)

- 역기구학 — 손끝 좌표를 직접 지정하는 이동. 저장된 관절 각도 재생으로 충분하다
- mm 단위 정밀 정렬을 AR로 하는 것 — 마커 오차가 ±5~15mm라 불가능
- 자율 작업 계획 — 사람이 가르친 것만 재생한다

## 미확정 — 팀 회의 대기

- **무대**: 작은 공장(부품 검사·분류)이 1순위 후보. 무인 카페·실험실·재활용이 대안
- **바퀴로봇 연계** 포함 여부
- **비전(카메라로 알아보고 집기)** 포함 여부 — 포함 시 일정 위험 큼

무대가 정해지면 F1~F6 위에 시연 시나리오 한 줄이 얹힌다.

## 성공 판정 (프로젝트 전체)

> 팀원 셋이 각자 기기에서 접속해, 한 명이 조작하고 두 명이 지켜보며,
> 폰으로 실물 위 경로를 확인한 뒤, 저장한 지점으로 한 사이클을 돌린다.

이게 되면 성공이다. 안 되면 기능이 아무리 많아도 실패다.
