# GOAL-amr-route-legible — AMR 경로를 **읽을 수 있게** 만든다

사다리 3 의 마무리. 앞: `assembly-line.md` · `dash-authoring.md` (evidence).

**기능은 다 됐는데 아무도 못 쓴다.** 경로를 그리고 끌고 사건에 붙이는 것이 전부 되는데,
주인님이 실제로 눌러 보고 넷을 못 했다 (2026-08-04):

```
· AMR 을 새로 놓을 수 없다          팔레트에 카드가 없다
· 어느 점이 몇 번인지 모른다         화면에 번호가 없다
· 어느 쪽이 출발인지 모른다          선만 있고 방향이 없다
· 언제 어디로 가는지 한눈에 안 보인다   마커를 하나씩 우클릭해야 안다
```

**넷 다 "만든 것을 보이게" 다.** 새 능력을 더하지 않는다 — 이미 있는 데이터를 읽히게 한다.

## 골 한 줄

```
빈 방에 터틀봇을 놓고, 경로를 그리고, 그 경로가 언제 도는지를
**우클릭 없이 화면만 보고** 알 수 있다.
```

## 1. Outcome

| | 완료 판정 |
|---|---|
| P1 팔레트 카드 | 빈 방에 AMR 을 놓을 수 있고 새로고침 뒤에도 남는다 |
| P2 점 번호 | 점 개수만큼 번호가 뜨고, 끌면 따라오고, 지우면 다시 매겨진다 |
| P3 방향 | 출발점이 다른 모양이고, 점 순서를 뒤집으면 화살표도 뒤집힌다 |
| P4 타임라인 띠 | AMR 사건이 있는 구간에만 띠가 뜨고 목적지 이름이 보인다 |

## 2. Verification surface

- `bash scripts/check/all.sh` — 게이트 전부
- `node scripts/check/dash-web-verify.mjs` — 실렌더. **phase 마다 검사를 더한다**
- **결함 주입** — phase 마다 되돌려 넣어 빨개지는 것까지 본다

## 3. Constraints (후퇴 금지)

- **평소에는 경로 선을 안 그린다** (주인님 결정 · `layout-view.js` §AMR).
  `[경로]` 를 켤 때만이다 — 번호·화살표도 같은 규칙을 탄다
- **좌표 변환을 새로 만들지 않는다** — `interaction.js` 의 `floorAtMm()` 하나 (하드 룰 5)
- **화면에 자세·좌표를 박지 않는다** — `motion.sh`·`scenario.sh` 가 지킨다
- **관제화면은 명령을 안 보낸다** — `timeline.sh` ⑨ (D36 · 하드 룰 4)

## 4. Boundaries

- **실기 주행은 범위 밖** — `TB-CONTRACT.md` 의 `/api/runs/{id}/path`(실측 궤적)는
  이 골에서 안 붙인다. 계획 경로와 실측 궤적은 자세의 `hand`/`taught` 와 같은 구도로
  나중에 갈린다
- **경로 자동 생성(Nav2 goal 변환) 안 한다** — 계약이 예약만 해 뒀다
- **충돌 회피 안 한다** — 교차는 보여주기만 한다

## 5. 미니멀 사다리 적용 기록

- P1 은 **새 코드가 아니라 카드 한 장**이다 — `place()` 가 `kind` 로 갈라지는 구조가 이미 있다
- P2·P3 는 `path-gizmo.js` 안에서 끝난다 — 화면(React)은 안 건드린다
- P4 는 타임라인 마크업에 한 줄 추가. `stateAt` 은 안 고친다 (사건이 이미 `amr`·`amrAt` 을 든다)

## 6. Blocked stop condition

- 게이트가 빨간 채로 다음 phase 로 안 간다
- 결함을 주입했는데 게이트가 안 잡으면 **그 검사는 통과할 수밖에 없는 검사**다 —
  이번 세션에 다섯 번 나왔다. 재는 것을 바꾼다

### 딸려 나온 수리 셋

**① 모르는 카드 종류가 NaN 지오메트리를 만들었다.** `place()` 가 마지막 분기로 흘러가
치수 없는 창을 만들었고 three 가 `Computed radius is NaN` 을 쏟았다 — 화면은 안 죽고
**보이지 않는 깨진 물건**만 남는다. P1 결함 주입 중에 드러났다.

**② 번호 라벨이 GPU 에 쌓였다.** 라벨은 `CanvasTexture` 라 `dispose()` 의 지오메트리
정리로는 안 없어진다. 배치안을 고칠 때마다 뷰가 새로 만들어지므로 **점을 한 번 끌 때마다
텍스처가 점 개수만큼 쌓였다** — 실측 10번 끌자 **10 → 50**. `createLayoutView.dispose()` 가
`pathGiz.dispose()` 를 부르게 고쳐 **10 → 10**.

**③ 검사 순서를 내가 깨뜨렸다.** 누수 검사를 ⌘Z 검사 앞에 끼워 드래그를 6번 더 하는 바람에
⌘Z 가 원래 값으로 못 돌아갔다. 뒤로 옮겼다.

### 통과할 수밖에 없던 검사 — 이번에도 하나

P4 의 첫 판정은 **구간 시작을 0 으로 고정해도 98/98 이 그대로 통과**했다. 두 AMR 다 사건이
하나뿐이라 `prev` 가 어차피 0 이었기 때문이다. **구간이 둘인 판**(사건 9·12 에 `amr2`)을
만들어 두 번째 다리가 앞 사건 시각(36초 · 73.47%)에서 시작하는지 보게 고쳤다.

이번 세션에서 같은 함정이 여섯 번째다 — 슬라이더가 자기 값을 자름 · FK 가 접촉만 잼 ·
문턱보다 격자가 먼저 막음 · 재는 시각이 틀림 · 슬라이더를 읽고 로봇을 안 봄 · 구간이 하나뿐.
**공통점은 "검사가 대상이 아니라 그 대상을 보여주는 것을 읽었다" 다.**
