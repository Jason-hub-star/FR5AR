# /발표 — 슬라이드 생성기에 먹일 단일 MD를 굽는다

**진행률 보고서가 아니다.** 팀원이 듣고 "아 저 기술을 저래서 골랐구나" 가 남아야 하고,
발표자 본인이 그걸로 **공부**가 돼야 한다. 그래서 축마다 **선택 · 이유 · 용어**가 셋 다 있어야 한다.

인자로 **축(도메인)** 과 **대상(`팀` | `외부`)** 을 받는다.
축이 없으면 최상위 작업 폴더에서 뽑고 **주인님에게 목록을 확인받는다.** 대상 기본값은 `팀`.
`외부` 는 강사·심사·타 팀 — 역할 경계와 설계 논증을 지운다 (§듣는 사람이 팀 밖이면).

---

## 1단계 — 수집 (여기서 추측하지 않는다)

**요약본을 근거로 삼지 않는다** (하드 룰 6). 아래를 직접 연다.

| 무엇을 채우나 | 어디서 |
|---|---|
| 프로젝트 한 줄 · 역할 경계 · 전체 그림 | `docs/ref/arch/ARCHITECTURE.md` |
| 확정 스택과 **버전** · 함정 | `docs/ref/arch/STACK.md` |
| 축마다 무엇을 하고 무엇을 안 하나 | 각 폴더 `AGENTS.md` |
| **실제 설치본**(문서와 어긋날 수 있다) | 각 워크스페이스 `package.json` |
| 축별 계약·수치 | `docs/ref/contract/*.md` |
| 지금 어디까지 · 실기 상태 | `docs/status/PROJECT-STATUS.md` |
| 폴더 실체 (문서에 있는데 비었을 수 있다) | `find <축> -maxdepth 3` |
| **슬라이드에 넣을 사진** | `docs/evidence/ALBUM.md` — 먼저 `node scripts/build/album.mjs` 로 굽는다 |

- **문서와 코드가 어긋나면 코드가 이긴다** — `package.json` 버전을 정본으로 쓰고 어긋난 건 따로 알린다
- **미착수 축은 보여줄 물건이 있을 때만 넣는다** — 사진이나 통념과 다른 실측 중 하나라도 있으면
  넣고 제목에 "미착수 · 경계만 확정" 이라고 적는다 (`Vision` — 카메라 실물과 시야 한계가 있다).
  둘 다 없으면 **뺀다** (`Database` — 슬라이드에 표 하나만 남고 그건 계획이지 결과가 아니다).
  미착수를 감추는 게 아니라, **결과가 없는 축은 발표에서 할 말이 없다**

## 2단계 — 슬라이드 문법 (고정)

```
# N. <축 이름>                     ← 대단원 = 슬라이드 그룹. 명사로 끝낸다
## 스택                            ← 표 (항목 | 선택 | 선정이유)
## 왜 이렇게 골랐나                 ← 불릿 0~2개. 표로 안 되는 것만. 없으면 절째로 뺀다
용어 — 한 줄 풀이                   ← 평문. 처음 나올 때만
```

- **대단원은 축 1개면 7~8개 · 여러 축이면 8~10개.** 표지 · (여러 축이면) 아키텍처 · 공통 스택 · 축별
- **처음 나오는 약어·영어 기술용어는 한 줄 풀이.**
  이게 이 산출물에서 가장 오래 살아남는 부분이다 — 발표자가 그대로 읽으면 설명이 된다.
  **한 줄로 끝낸다** — 두 줄 넘으면 뒷줄은 발표에서 안 읽힌다
- 표 칸을 억지로 채우지 않는다. **한 줄로 안 되면 비운다** — 빈 칸은 발표자가 입으로 말할 자리다
- **인용문 블록(`>`)·볼드(`**`)를 쓰지 않는다.** 슬라이드에서 강조는 자리가 하지 글꼴이 하지 않는다

### 문체 — 서술어를 끊는다 ← 두 번째로 많이 틀리는 자리

**`~다` 로 끝나는 문장을 슬라이드에 두지 않는다.** 슬라이드는 읽는 글이 아니라 발표자가
말을 얹을 뼈대다. 서술어까지 인쇄되면 발표자가 읽을 게 없어진다.

| 쓴다 | 안 쓴다 |
|---|---|
| 생산성 표시 | 생산성이 얼마나 달라지는지 눈으로 보게 만든다 |
| 안전 상한을 한 곳에서 강제 | 안전 상한을 한 곳에서 강제하기 위해서다 |
| 확정 | 이것으로 확정했다 |
| 명령이 아니라 제안 | 비전은 명령을 만들지 않는다. 제안을 만든다 |

- **표 칸·제목·불릿은 명사구로 끝낸다.** 어쩔 수 없으면 `~함` · `~임`
- 대단원 제목도 서술형 부제를 붙이지 않는다 — `FR5 대시보드` 지 `FR5 — 폰이 실물 위에 겹쳐 본다` 가 아니다

### 제약은 넣고, 경위는 뺀다 ← 가장 많이 틀리는 자리

둘 다 "왜 이렇게 만들었나" 인데 하나만 발표에 남는다.

| | 예 | |
|---|---|---|
| **제약 → 설계** | "폰에는 콘솔이 없다 → 그래서 화면 진단판을 만들었다" | **넣는다** |
| 경위 → 뒤집힘 | "마커만 된다고 알았다 → 아니었다 → WebXR 로 갔다" | **뺀다** |

발표는 **지금 무엇이 어떻게 되어 있나**를 설명하는 자리지, 우리가 어디서 틀렸는지를
복기하는 자리가 아니다. **결과만 적는다** — "마커와 WebXR 둘을 쓰고 역할이 이렇게 갈린다."

같은 이유로 **실측은 표만 남기고 "이게 통념을 뒤집었다" 는 프레이밍은 뺀다.**
숫자가 스스로 말한다.

### 실측은 축마다 넣지 않는다 ← 대상이 누구냐로 갈린다

**팀원 앞이면 축마다, 외부(강사·심사)면 전체에서 2~3개만.** 축마다 실측 표를 달면
슬라이드가 계기판이 되고, 듣는 사람은 어느 숫자가 중요한지 모른다.

살리는 기준은 **"그 숫자가 통념과 다를 때"** 하나다 — 인식 한계가 마커 크기가 아니라
명도차였다든가, 카메라가 마지막 36mm를 못 본다든가. 정상 범위 안의 수치(용량·주기·포트)는
발표에서 아무 일도 하지 않는다.

### 그림 — 대단원마다 1~2장

말로 설명한 화면은 **사진 한 장을 못 이긴다.** 축 대단원마다 `ALBUM.md` 에서 1~2장을 고른다.

```
<!-- 그림 docs/evidence/2026-08-06/fr5-cam-pip.png — 폰 카메라가 3D 위에 겹쳐 뜬 화면 -->
```

- **HTML 주석으로 적는다.** 슬라이드 도구는 무시하고 **발표자만 본다** — 파일경로가 슬라이드에
  인쇄되면 안 되고(§넣는 것/빼는 것), 그렇다고 경로가 없으면 발표자가 그 사진을 못 찾는다
- **캡션은 `ALBUM.md` 의 것을 그대로 쓴다.** 새로 지어내면 사진과 어긋난다.
  캡션이 `TODO` 인 사진은 **고르지 않는다** — 무슨 화면인지 확인되지 않은 것이다
- **표지·아키텍처 대단원에는 넣지 않는다.** 화면 사진은 축 대단원의 것이다
- 쓸 사진이 없으면 **비운다.** 다른 축 사진을 돌려 쓰지 않는다 —
  필요하면 `bash scripts/dev/shot.sh <슬러그> "<캡션>"` 로 지금 찍는다

### 넣는 것 / 빼는 것

| 넣는다 | 뺀다 |
|---|---|
| 구조 · 경계 · 데이터 흐름 | 진행률 · 로드맵 · 블로커 · "N/N 통과" |
| 스택 선택과 그 이유 (한 줄로 되는 것만) | 회고 · 교훈 · 결정 번호(D숫자) |
| 제약 → 설계 | 경위 · 뒤집힘 · 우리가 틀렸던 이야기 |
| 통념과 다른 실측 2~3개 (표로) | 실측 전수 · "이게 놀랍다" 는 해설 |
| 비교 표 (A vs B · 모드별) | 내부 심볼·파일경로·설정키 (`buildScene` · `?cv=` · `Shared/view3d/`) |
| 용어 풀이 | 만지면 깨지는 내부 함정 (그건 `AGENTS.md` 몫이다) |
| ⚠ 안전하다는 해명 ("이 구멍은 배포본에 없다") | ⚠ 아직 위험·미확인 (불안을 팔지 않는다) |
| 안 넣은 의존성 한 줄 | 안 넣은 것을 표로 부풀리기 |
| — | **역할 분담표 (우리 몫 / 팀원 몫)** |
| — | **내부 설계 논증** (데이터 경계·격리·교체 가능성) |

**"우리가 이걸 왜 안 골랐나" 를 변호하지 않는다.** 고른 것만 적으면 된다 —
없앤 선택지를 설명하는 순간 듣는 사람 머리에 그 선택지가 생긴다.

### 듣는 사람이 팀 밖이면 경계선을 지운다 ← 인자로 받는다

`/발표 대상=외부` 면 **누가 무엇을 했는지를 슬라이드에서 지운다.**

- 역할 분담표 · 다이어그램의 `← 우리` 화살표 · "우리는 받아서 보여준다" 류를 전부 뺀다
- 외부에는 **팀이 하나로 보여야 한다.** 안에서 나눈 몫은 질문이 나오면 입으로 답한다
- 같은 이유로 **내부 설계 논증도 뺀다** — 데이터 경계를 어떻게 격리했는지는 팀 안의 언어다

기본값은 `대상=팀`. 이때는 역할 경계와 설계 논증을 살린다 — 그게 팀 안에서는 본론이다.

## 3단계 — 쓰고 검사

**`scratchpad/` 에 쓴다. `docs/` 에 넣지 않는다.**
발표 산출물은 SSOT가 아니고, `docs/` 는 개별 450줄 · 총량 상한의 무게 게이트가 걸려 있다
(`scripts/check/docs-weight.sh`). 파일명은 `ppt-<주제>-<YYYY-MM-DD>.md`.

굽고 나서 스스로 센다.

- [ ] **축 1개면 120~150줄 · 여러 축이면 180~250줄.** 넘으면 잘릴 것을 쓴 것이다
- [ ] **`~다` 로 끝나는 줄이 본문에 없다** (표 칸·제목·불릿 전부 명사 종결)
- [ ] **볼드(`**`)와 인용문(`>`)이 본문에 없다**
- [ ] 용어 풀이가 처음 나온 자리에 **한 줄로** 있다 (두 번째부터는 없다)
- [ ] **축 대단원마다 그림 주석이 1~2개** 있고, 그 경로가 실제로 존재한다 (`ALBUM.md` 에서 골랐다)
- [ ] 실측 표가 **전체 2~3곳**에만 있다 (축마다가 아니라)
- [ ] 넣은 미착수 축이 미착수라고 적혀 있다
- [ ] 버전·수치가 **파일에서 읽은 값**이다 (기억이 아니라)
- [ ] 진행률·로드맵·교훈이 안 들어갔다
- [ ] **"처음엔 … 그런데 …" 로 시작하는 절이 하나도 없다** (경위 금지)
- [ ] 내부 심볼·파일경로·설정키가 본문에 없다
- [ ] ⚠ 가 **불안이 아니라 해명**이다
- [ ] `대상=외부` 면 역할 분담·`← 우리` 화살표·설계 논증이 없다

마지막에 **대단원 목록만** 보고한다. 본문을 다시 요약하지 않는다.

## 4단계 — pptx 로 굽는다 (요청받았을 때만)

```bash
python3 scripts/build/deck.py scratchpad/ppt-<주제>-<날짜>.md
```

같은 폴더에 `.pptx` 가 나온다. **텍스트가 편집 가능한 네이티브 pptx** 이고, 색은
`Shared/tokens/tokens.css` 밝은 테마에서 읽는다 (프로젝터라 어두운 테마를 쓰지 않는다).

### 슬라이드는 키워드, 문장은 대본으로

**슬라이드에 산문을 두지 않는다.** 읽을 글이 떠 있으면 듣는 사람이 발표자를 안 본다.

```markdown
## 한 줄

- 방산 탄두 조립 라인
- 로봇팔 · 자율주행로봇 **배치**
- → **생산성 표시**

::: notes
방산 탄두 조립 라인에서 로봇팔과 자율주행로봇을 어디에 놓고 어떻게 움직이느냐에 따라
생산성이 얼마나 달라지는지를 눈으로 보게 만드는 웹 작업대입니다.
:::
```

- `::: notes` 가 파워포인트 **발표자 노트**가 된다. 우리가 쓴 글자 그대로 들어간다
- 용어 풀이·설계 근거·경위는 **전부 노트로 내린다.** 슬라이드에는 이름만 남긴다
- **`**굵게**` 한 자리만 강조색이 붙고 나머지는 검정**이 된다 (`deck.py` 가 기계적으로 입힌다).
  슬라이드마다 색을 고르지 않는다 — 고르는 순간 그게 슬롭이다
- 표는 **항목 · 선택 두 칸까지.** "왜" 칸은 노트로 내린다

- **`<!-- 그림 … -->` 주석이 사진 슬라이드로 펴진다** — 캡션이 제목, 사진이 본문.
  경로는 슬라이드에 인쇄되지 않는다. 최종 크기·위치는 파워포인트에서 사람이 잡는다
- **영상은 어떤 md 도구도 pptx 에 못 넣는다** — 파워포인트에서 직접 삽입한다.
  스크립트는 사진이 아닌 경로를 만나면 건너뛰고 그 사실을 찍는다
- 그림 주석이 가리키는 파일이 없으면 **굽지 않고 멈춘다** (`build/` 규약)

### 코드블록 다이어그램은 **44칸**을 넘기지 않는다

구조 그림을 코드블록으로 그릴 때, pptx 는 md 뷰어보다 본문 폭이 훨씬 좁다.
넘치면 줄이 접혀 **선 연결이 어긋난 그림**이 된다 — md 에서는 멀쩡해 보이므로 눈치채기 어렵다.

- 한 줄 44칸 이하로 그린다. 안 되면 **세로로 쌓는다**
- 화살표 주석(`← 우리`)을 다이어그램 안에 넣지 않는다 — 그게 폭을 넘기는 주범이다

### 왜 pandoc 인가 (다시 고르지 않기 위해 남긴다)

| 후보 | 실체 | 판정 |
|---|---|---|
| pandoc `--reference-doc` | 파워포인트 레이아웃 placeholder 에 얹음. 텍스트 편집 가능. `::: notes` 를 **글자 그대로** 대본에 넣음 | **채택** |

슬라이드마다의 좌표는 파워포인트에 맡긴다.

### pptx 를 굽고 나서 반드시 눈으로 본다

pptx 는 **깨져도 조용하다.** 색이 무효면 기본색으로, 좌표가 없으면 귀퉁이로 넘어간다.
`deck.py` 가 XML 파싱과 placeholder 적용 개수를 빌드 시점에 세지만, 그래도 마지막은 렌더다.

```bash
soffice --headless --convert-to pdf --outdir /tmp <굽은>.pptx && pdftoppm -png -r 52 /tmp/<굽은>.pdf /tmp/s
```

몽타주 한 장으로 본다 (하드 룰 2). **글이 위쪽 귀퉁이에만 몰려 있으면 좌표가 안 붙은 것이다.**

## 하지 말 것

- **`docs/` 에 쓰기** — 무게 게이트를 밀고 SSOT 총량을 오염시킨다
- **진행률로 채우기** — 팀원이 듣고 싶은 건 "얼마나 했나"가 아니라 "무엇을 왜 그렇게"다
- **경위를 쓰기** — 위 §제약은 넣고 경위는 뺀다. 이게 매번 가장 많이 잘리는 자리다
- **버전 번호를 기억으로 적기** — `package.json` 을 연다
- **용어 풀이를 별도 섹션으로 몰기** — 처음 나온 자리에 붙어야 읽힌다
- **서술어를 인쇄하기** — 발표자가 말할 몫까지 슬라이드가 뺏는다 (위 §문체)
- **미착수 축을 전부 넣기** — 아래 기준으로 가른다
