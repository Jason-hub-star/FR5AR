# /슬라이스 — 수직 기능 1개 완결

한 슬라이스 = **기능 하나가 문서→코드→검증까지 관통.** 우리 단계(V0~V4)가 곧 슬라이스다.

## 절차

### 1. 문서 선행 (코드보다 먼저)
건드릴 것에 따라 아래를 **먼저** 고친다. `CLAUDE.md` 하드 룰 1.

| 바꾸는 것 | 먼저 고칠 문서 |
|---|---|
| 새 엔드포인트 · WebSocket 메시지 | `docs/ref/contract/API-CONTRACT.md` |
| 새 폴더 · 구조 | `docs/ref/arch/ARCHITECTURE.md` |
| 새 의존성 · 버전 | `docs/ref/arch/STACK.md` (`/스택가드` 참조) |
| 안전 조건 | `docs/ref/contract/SAFETY-RULES.md` |
| 기능 범위 | `docs/ref/product/FEATURE-SPEC.md` |

이 표는 **자주 쓰는 것만** 적었다. 정본은 `docs/INDEX.md`의 문서 지도다.
새 SSOT 문서가 생기면 INDEX에 등재하고, 이 표는 필요할 때만 늘린다.

### 2. 계획 상의 (승인 게이트)
한 문단으로 적고 **승인받고 코드 착수**한다.
- 범위 — 무엇까지 하고 무엇은 안 하는가
- **완료 판정** — 무엇이 눈에 보이면 완료인가 (Mock과 실물을 따로 적는다)
- 건드릴 파일 목록

### 3. 수직 구현
서버→통신→화면 한 바퀴. 미니멀 사다리를 지킨다 — 안 시킨 추상화·새 의존성 금지.
로봇에 명령을 보내는 코드면 `SAFETY-RULES.md`의 **fail-closed**를 지킨다.

### 4. 검증 (성역 — 깎지 않는다)
| 대상 | 확인 방법 |
|---|---|
| 3D·AR | 브라우저 실렌더 + 스크린샷. 콘솔이 아니라 **네트워크 요청**까지 본다 |
| 서버 | 실제 요청을 보내 응답 확인 |
| 자산 | `bash scripts/check/assets.sh` |
| 문서·하네스 | `bash scripts/check/all.sh` |

**증거 없이 완료 선언 금지.** `docs/evidence/YYYY-MM-DD-*.md`에 남기고,
**확인하지 않은 범위**까지 적는다.

### 5. 값이 바뀌었으면 전파
개수·기준값·버전·조건 수가 바뀌었으면 **`/정합`을 부른다.**
뿌리 SSOT → 참조하는 문서 → 스크립트 상수 순서다.
안 하면 다음 세션에 게이트가 거짓 실패한다.

### 6. 마감
**`/마감`을 부른다.** 게이트 → 완료 판정(`not-ready`/`ready-for-review`/`ready-to-share`)
→ 핸드오프 캡슐까지 닫힌다. 커밋은 별도 승인.

## 이 스킬이 부르는 것 (파이프라인)

```
/슬라이스
  1 문서 선행      ← 표로 매핑된 SSOT를 먼저 고친다
  2 값 등재        → /스택가드   (새 버전·SDK 필드명·엔드포인트가 있으면)
  3 승인 게이트    ← 사람. 범위·완료판정. 여기서만 멈춘다
  4 구현
  5 검증          → headless-cdp-verify (3D·AR) 또는 게이트
  6 전파          → /정합       (개수·기준값이 바뀌었으면)
  7 마감          → /마감
```

**자동으로 도는 것은 따로 있다.** 파일을 저장하면 훅이 변경 종류에 맞는 게이트를
이미 돌린다 (`scripts/README.md` §훅이 자동으로 부른다). 이 스킬이 그걸 또 부르지 않는다.

**사람이 멈추는 곳은 3번 하나다.** 나머지는 이어서 간다.

## 가드

- 한 슬라이스에 기능 2개 이상 넣지 않는다
- Mock 통과를 실물 통과로 적지 않는다
- 무대(배경)가 필요한 기능을 미확정 상태에서 시작하지 않는다 — **V1까지는 무대 무관**
