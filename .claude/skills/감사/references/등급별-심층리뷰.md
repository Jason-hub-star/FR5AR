# Tiered Review

한 모델이 전부 하지 않는다. **비용이 싼 모델은 넓게(광역 스캔·외부조사), 최고 가용 모델은 깊게(심층 리뷰), 메인 모델은 확실하게(원본 대조 검증)** 로 등급을 나눠 흐르게 한다. 목적은 "최고모델의 판단을 받되, 그 앞뒤를 싸게 채워 컨텍스트와 비용을 아끼고, 결과의 정확성은 원본 검증으로 못 박는 것".

`gap-find`(여러 **역할**의 렌즈로 결함 발굴)과 다르다 — 이건 **모델 등급**을 축으로 삼고, 결함뿐 아니라 **"지금 미리 설계해둘 것"** 까지 본다. `socratic-review`(질문 기반 설계 검증)보다 무겁고 산출이 구조화된다. 셋은 조합 가능하다.

## 핵심 원칙 — 모델 등급 라우팅

- **"최고모델"은 고정 이름이 아니다.** 그 시점 가용한 최상위 모델(예: 세션 메인이 상위급이면 메인 자신, 또는 다른 최상위 계열을 **다양성 렌즈**로 병렬). 특정 벤더/버전에 묶지 않는다.
- **메인이 이미 상위급이면 심층 리뷰를 메인이 직접 한다.** 서브에이전트는 모델 격상이 아니라 **병렬화·컨텍스트 절약** 목적일 때만. 메인이 하위급일 때만 상위 모델로 격상한다. (전역 에이전트 모델 규칙과 동일.)
- 다른 최상위 모델을 굳이 쓰는 정당한 이유는 하나 — **독립된 관점의 다양성**(같은 급 서로 다른 계열). "더 좋아지려고"가 아니라 "다르게 보려고".

## Use When

- 큰 설계/구현 착수 **전** 향후 취약점 + 미리 설계해둘 기능을 최고모델로 점검하고 싶을 때
- 문서/스펙이 방대해 한 컨텍스트에 다 못 넣을 때 (저가 모델로 나눠 스캔)
- 최신 SDK·외부 사실 확인이 필요할 때 (저가 모델 외부조사, 출처·버전 고정)
- **저가 모델이 만든 초안/레퍼런스/예제를 최고모델로 검수하며 확정할 때** (아래 변형)

## Steps

1. **광역 스캔(저가 모델, 섹션 병렬)** — 문서/코드를 도메인 섹션으로 나눠 동시 스캔. 분류를 재발명하지 말고 **"미래 리스크 씨앗"**(PENDING/LATER/TODO·thin-spot·되돌리기 힘든 결정)만 뽑게 한다. 파일 근거 강제.
2. **리뷰 대상 표(직접)** — 스캔 결과를 **섹션별 리뷰 대상 표**로 합친다. 저위험은 제외(검증 낭비 방지). 각 대상을 심층 리뷰 클러스터로 라우팅.
3. **심층 리뷰(최고모델, 클러스터 병렬)** — 각 클러스터가 **원본을 직접 열어** ①향후 취약점(트리거 조건·심각도·`파일:절` 근거) ②미리 설계할 seam(아래 3분류) ③외부조사 필요 질문을 낸다.
4. **외부조사(저가 모델, 병렬)** — 3에서 나온 구체 질문만 조사. **출처 URL·조회일·신뢰도** 강제, 불확실은 "미확인". 버전민감 항목은 버전 고정.
5. **충돌검증(메인 모델, 성역)** — `CONFLICT-RISK`·P0로 표시된 것은 **지목된 원본을 직접 열어** 대조. 서브에이전트의 오탐/오독/우선순위 오판을 여기서 걸러낸다. **절대 스킵 금지.**
6. **종합 + 반영(직접)** — 우선순위 표로 종합. 승인 시 프로젝트 관례대로 문서에 반영(watchboard/갭 등록·인덱스 등록·게이트 재실행·커밋).

> 6개를 매번 다 돌릴 필요는 없다. 규모에 맞춰 (예: 작은 건 1→3→5→6). 단 **5(충돌검증)는 언제나** 한다.

## Seam 3분류 (과설계 방지의 핵심)

미리 설계할 후보는 반드시 셋 중 하나로 판정한다:

- **NOW-seam** — 지금 넣으면 싸고 나중이면 마이그레이션/재설계가 비싼 확장 지점(스키마 컬럼·enum open·인터페이스 경계·버전 필드). "지금 할 최소 변경"+"나중이면 왜 비싼가" 1줄씩. **현 SSOT와 충돌 없음**을 확인.
- **DEFER-with-seam** — 지금 만들지 말 것(YAGNI). 나중을 위한 **이름 있는 seam만** 남긴다.
- **CONFLICT-RISK** — 지금 미리 설계하면 **현 SSOT 결정과 충돌**한다 → 어떤 결정(`파일:절`)과 부딪히는지 + "지금 만들지 말라" 근거. (5단계에서 원본으로 진위 검증.)

NOW를 남발하지 않는다 — 진짜 되돌리기 어려운 것만 올린다.

## 변형 — 저가 모델 초안을 최고모델로 검수 (레퍼런스/예제 작성)

저가 모델로 **버전 고정 레퍼런스/예제**를 병렬 작성시킨 뒤, 최고/메인 모델이 **코드 정확성을 반드시 검수**한다. 틀린 예제는 없느니만 못하다 — 실제로 존재하지 않는 API·비원자 로직·프로토콜 오차가 초안에 섞인다. 검수에서 잡은 결함은 인라인 수정하거나 문서 상단 "검수 노트"로 박고, 버전민감 항목엔 "설치버전 대조 필수"를 명시한다.

## 모델 등급

| 단계 | 등급 | 이유 |
|---|---|---|
| 광역 스캔·외부조사·초안 | 저가 | 병렬화·컨텍스트 절약. 사실 수집·초안은 저가로 충분 |
| 심층 리뷰 | 최고 가용 | 설계 판단·트레이드오프. 메인이 상위급이면 메인 직접 |
| 충돌검증·최종 종합·검수 | 메인(직접) | 원본 대조·정확성 책임. 위임 금지 |

## Verify

- [ ] 각 발견/판정에 `파일:절` 또는 출처 근거가 있음 (추측엔 "추정" 표시)
- [ ] 미리설계 후보가 전부 NOW/DEFER/CONFLICT 중 하나로 분류됨
- [ ] `CONFLICT-RISK`·P0는 원본 재대조 완료 (5단계 스킵 0건)
- [ ] 외부조사 항목에 출처·조회일·신뢰도, 버전민감은 버전 고정
- [ ] (초안 변형 시) 최고/메인 모델이 코드 정확성 검수 완료
- [ ] 반영했으면 프로젝트 게이트(lint/test/docs:check 등) 재실행 PASS
